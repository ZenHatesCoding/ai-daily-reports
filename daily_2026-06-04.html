Agent libOS: A Library-OS-Inspired Runtime for Long-Running, Capability-Controlled LLM Agents

LLM agent 正从一次性问答助手演化为长时运行的软件 actor：跨调用保持状态、fork 子任务、等待外部事件、申请人工授权、就地生成工具，副作用还要可恢复可审计。传统 agent 框架把这些能力散落在 prompt/tool/MCP 胶水里，进程一崩就丢上下文、长时任务没法接管、安全权限粒度粗到没法进生产。

⚙️ 方法：借鉴 Library-OS 思路，在宿主 OS 之上做一层 agent runtime substrate：把进程/地址空间/系统调用换成 capability-controlled 任务单元与受控副作用接口，让长时 agent 像传统进程一样可挂起、恢复、审计。优势是首次把 agent 当成可挂起恢复的'软件进程'管，状态、权限、副作用统一在 runtime 边界内可控可审。
⚖️ 取舍：为统一接管所有副作用，runtime 必须把所有工具调用/外部 IO 拦在 capability 网关后面，单步调用延迟上升、短任务 latency 反而被拖慢；定义良好的同步工具流可能反而比直接 prompt 慢，且 capability 模型越细，框架本身的开发与调试门槛越高。
📊 效果：提出完整的 libOS 风格 agent runtime 抽象与 capability 控制模型，把 fork/挂起/恢复/审计这类长时操作当成一等公民；可承载生成式工具与跨事件副作用（具体 SOTA 数字需结合论文内实验章节）。
🏢 团队：arXiv 2026-06-02 预印；Yingqi Zhang 单作，背景为华盛顿大学（University of Washington）等院校，独立研究者路线（具体机构以论文署名页为准）。

Language Models Need Sleep: Learning to Self-Modify and Consolidate Memories

过去十年 ML 从任务专一的浅层模型走向通用 LLM，但所有 LLM 都缺一件事：像人一样把临时上下文里的知识'睡一觉'就沉淀进长期参数。in-context 临时学到的时序知识一过窗口就丢，模型没法在长会话里真正持续学习、也没法把短期记忆迁移到长期行为，限制了部署成本和持续适配能力。

⚙️ 方法：仿照人类睡眠-记忆巩固机制，给 LLM 加一个 Self-Modify 通道：模型在'休眠'阶段用自己的输出回写自身参数，把上下文里的关键知识自我改写到长期权重。优势是不再只靠上下文窗口凑合，模型首次具备显式的自我参数改写能力，长会话记忆真正落进权重。
⚖️ 取舍：Self-Modify 让模型在权重上'自我手术'，副作用不可控：可能在不该改的通用能力上漂移、灾难性遗忘此前任务；触发频率和改写幅度越激进，回滚越难，长程一致性反而下降。
📊 效果：在长上下文/持续学习类任务上展示出对 in-context 时序知识的有效迁移（具体 benchmark 数字以论文实验章节为准），方向上首次把'睡眠巩固'做成可训练的 LLM 机制。
🏢 团队：Google Research 与 Stanford 合作；通讯 Vahab Mirrokni（Google Research 算法 VP），一作 Ali Behrouz（Stanford PhD，Mamba/Cobra 作者），Farnoosh Hashemi 共同作者。

Imaginative Perception Tokens Enhance Spatial Reasoning in Multimodal Language Models

VLM 在很多视觉任务上很强，但只要关键信息在画面外——遮挡、视角未给、路径要穿过盲区——空间推理就直接崩。人能凭'想象'脑补出没看到的视角、把多帧部分观察拼成完整空间，VLM 还停在'图里有什么答什么'，无法在遮挡/反事实视角下做可靠推理。

⚙️ 方法：提 IPT（Imaginative Perception Tokens）：在 VLM 中间层插入一组'想象性感知 token'，让模型把'假如站在那个角度会看见什么'显式外化成 token 序列，再喂给后续推理。优势是 VLM 首次拥有可读、可干预的'脑补中间表征'，把不可见视角从黑箱变成可控输入。
⚖️ 取舍：为生成可信的想象 token，模型必须先在训练分布涵盖的视角/遮挡模式上做大量监督；遇到训练时没见过的奇异视角或长链反事实推理时，想象出来的 token 会跑偏，越长链偏差越累积，敏感度高的几何任务上反而掉点。
📊 效果：在需要'想象不可见视角'的空间推理 benchmark（遮挡、反事实视角、路径追踪等）上相对基线 VLM 取得显著提升，方向上首次把'想象性感知'做成显式 token 中间表示（具体百分点以论文实验章节为准）。
🏢 团队：arXiv 2026-06-02 预印；一作 Mahtab Bigverdi，通讯 Ranjay Krishna 与 Linda Shapiro，均来自 University of Washington（Paul G. Allen School of Computer Science & Engineering），UW 视觉-语言实验室。

Synthesize and Reward -- Reinforcement Learning for Multi-Step Tool Use in Live Environments (PROVE)

把 LLM 训成能编排多步工具调用的 agent 卡在三处：搭一个真状态、真可执行的环境太贵；合成的训练 query 经常和服务端真实状态对不上，训出来的工具调用上线就失败；用 recall 类奖励又会催生出'为命中而堆调用'的啰嗦模式。开源社区一直在拼数据集、拼 MCP server，缺一套端到端框架把这三件事一起治。

⚙️ 方法：PROVE 框架三件套：(1) 20 个有状态 MCP 环境库做真执行；(2) 合成 query 紧贴服务端实时状态生成；(3) 用程序化 reward（Programmatic Rewards On Verified Environments）替代 recall 奖励。优势是首次让多步工具调用的 RL 训练在'真状态 + 真执行 + 程序化判分'的闭环里跑，端到端避开了合成-现实 gap。
⚖️ 取舍：为拿到'贴合真实状态'的训练信号，整个 pipeline 被绑在 20 个特定 MCP 环境的 schema 上；换协议/换工具类型就要重写环境与 reward；程序化判分只能量化可验证字段，对主观质量（回答好不好、对不对齐用户意图）这些'不可验'的维度无能为力。
📊 效果：在 20 个有状态 MCP 环境上做 RL 训练，多步工具调用相对 recall-reward 基线在执行成功率/调用步数压缩上同时更优（具体百分点以论文实验章节为准），方向上首次给出'真状态 + 程序化 reward'的完整训练回路。
🏢 团队：IBM Research AI；一作 Ibrahim Abdelaziz，通讯 Pavan Kapanipathi（IBM Research Senior Manager），共同作者 Asim Munawar、Kinjal Basu、Maxwell Crouse、Chulaka Gunasekara、Suneet Katrekar 均来自 IBM T. J. Watson Research Center。

Reasoning Structure of Large Language Models

业界评 Large Reasoning Model（LRM）几乎只盯两件事：最终答案对不对、生成 token 多少。问题是同一个 final accuracy、同一个 token 数背后，推理结构可能天差地别——是直链式一条路走到黑，还是分叉后再汇聚、有没有无效自循环？只看这俩指标，看不出模型'怎么想'，更没法定位失败模式。

⚙️ 方法：构造一套可扩展的 LRM 逻辑谜题基准，并把模型非结构化 trace 自动转成'claim + 依赖关系'的可验证推理图，再做图拓扑量化分析。优势是首次把'推理结构'从黑箱文本变成可度量、可比较的有向图对象，模型的好坏第一次能被'画出来'。
⚖️ 取舍：把 trace 转成推理图本身是一次强抽象：所有中间步骤被压成'claim + 依赖'，丢掉语用、措辞、隐含比喻等软信息；对逻辑性弱、靠语言风格/类比取胜的任务（数学证明、形式逻辑）友好，但评文学/对话式推理时结构性指标会失真。
📊 效果：在自建的逻辑谜题基准上，把多种主流 LRM 推理 trace 全部转成可量化推理图，揭示出 final-accuracy 之外显著的'结构差异'（具体图指标/对比 baseline 以论文实验章节为准）。
🏢 团队：ETH Zurich；通讯 Roger Wattenhofer（ETH Zurich 信息与计算机科学教授），一作 Frédéric Berdoz，共同作者 Luca A. Lanzendörfer、Fabian Farestam，arXiv 2026-06-02 预印。
