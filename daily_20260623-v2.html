Patch the Planet: OpenAI 推出 Daybreak 计划支持开源维护者

OpenAI 启动 Patch the Planet 计划, 与开源安全工具 Daybreak 联合, 通过资金、模型 API credits 和安全扫描工具帮助开源维护者识别并修复高危漏洞。首批合作包括 Linux Foundation、Python Software Foundation、Apache Software Foundation 等 20+ 主流基金会, 覆盖 PyTorch、Kubernetes、Linux kernel 等关键基础设施。OpenAI 承诺首年投入 1 亿美元等值资源, 包括 GPT 系列模型 API credits 和 Codex agent 自动化漏洞挖掘能力, 用于自动生成 patch PR 并协助 review。这是 OpenAI 首次将 Codex agent 用于非内部产品的对外公共安全基础设施, 也是首次向开源维护者开放 agent 自主提交流程。

💡 OpenAI 从模型 API 销售走向开源安全基础设施的战略延伸, 把 Codex agent 从闭源研发工具变成开源维护者的协作工具, 实质上是在与 Anthropic (Claude Code) + Google (Project Zero + OSS-Fuzz) 争夺 AI 时代的安全基础设施话语权。开源维护者基金这套玩法 (资金 + 模型 credits + 工具) 是 Anthropic 不会跟的赛道, 因为 Anthropic 一直把 safety 留在内部研究。Linux Foundation 等 20+ 基金会首批站台说明 OpenAI 在不到一年内完成了从营利公司到开源公共物品提供者的信任建设, 对 OSS 生态是真实利好, 但需要警惕 OpenAI 把 Codex agent 训练数据从开源项目 patch review 中汲取 (训练用 vs 安全用的边界)。

Codex-maxxing: OpenAI 让 Codex agent 能跑跨周长任务

OpenAI 发布 Codex agent 的长任务模式 (codex-maxxing), 允许 Codex 在云端持续运行跨天到跨周的复杂软件工程项目, 期间可自主重启、恢复上下文、跨 PR 推进任务。技术核心是把上下文窗口从单 session 8K-32K 扩到长任务记忆池 (persistent memory pool), agent 在任务中途被 pre-empt 后能无缝从上次检查点恢复, 配合 Codex 自带的任务规划-执行-验证循环 (plan-execute-verify) 自动重构失败的代码路径。OpenAI 内部 benchmark 显示, 跨周长任务的成功率从原 34% 提升到 67%, 单任务平均完成时间从 4.2 天降到 1.8 天。配套推出 Codex Tasks dashboard, 用户可监控 agent 的实时进度、cost 消耗、上下文摘要。

💡 Codex 从 chatbot IDE 补全升级到云端常驻工程师是 agent 工程化的关键一步 — Anthropic 的 Claude Code 仍是 session 模式 (用户要主动 keep alive), Cursor 仍是 IDE 嵌入式。OpenAI 把 agent 推到云端持久化是把 AI 员工从概念变成可计费 SKU (Codex Tasks dashboard 直接显示 cost), 商业模式上更接近 AWS Lambda (按 compute 时间计费) 而非 ChatGPT (按 message 计费)。跨周任务的持久记忆 + 任务规划循环是 agent 区别于长上下文 LLM 的关键能力 — Anthropic / Google 必须 6 个月内跟, 否则在企业软件工程市场会被甩开。67% 成功率听着不高, 但比人类初级工程师跨周独立完成任务的 60-75% 已经接近, 这就是为什么企业 CTO 在认真考虑把 Codex Tasks 当作虚拟 SDE 团队采购。

S-Agent: Spatial Tool-Use Elicits Reasoning for Spatial Intelligence

论文提出 S-Agent 框架, 把多模态大模型 (VLM) 从单帧图像理解改造为带空间工具调用能力的 agent, 在 MMSI-Bench 上 zero-shot 让 Gemini-3-Pro 提升 1.2%, 让 Qwen-VL-8B 提升 10.5%。核心机制是 3 层: (1) 层次化空间工具 (Hierarchical Spatial Tools) — 把空间推理拆成 grounding / 2D-to-3D lifting / aggregation 三个子工具, 每个子工具调用专业 CV 模型 (depth estimation / NeRF / pose estimation) 完成几何推理; (2) 双记忆系统 (Dual Memory) — Scene Memory 维护 3D 物体+空间事实, Agent Memory 维护工具调用 trace + 推理历史, 支持跨多视图多帧的 stateful reasoning; (3) 主动证据积累 (Active Evidence Accumulation) — agent 主动决定下一步需要什么证据 (query / condition / tool-use), 而不是单次 forward pass 输出所有结果。S-Agent 把当前 SOTA 空间 VLM 从 frame-centric recognition 推进到 scene-centric understanding, 支持视频级别的 spatio-temporal reasoning。

⚙️ 方法：S-Agent 的核心算法是 spatio-temporal evidence accumulation, 通过 VLM 作为 semantic planner 决策 evidence needs, 配合 hierarchy of spatial tools 调取几何专家 (depth / 3D / NeRF), 同时维护 Scene Memory + Agent Memory 双系统, 让推理从单次预测变成跨帧的状态追踪循环。配套 benchmark MMSI-Bench 验证 zero-shot + SFT 两种 setting 的提升幅度。
⚖️ 取舍：代价 1: 推理延迟高 — agent 模式比 VLM 单次 forward pass 慢 8-15 倍 (3-5 次工具调用), 在实时视频分析场景 (自动驾驶 / 机器人) 难以直接部署, 需配合 tool 蒸馏 (把 agent trace 蒸馏成单次 forward 模型) 才能落地。代价 2: 工具调用可靠性 — hierarchy tools 依赖 depth / NeRF 等子模型的精度, 在 transparent / reflective / textureless 物体 (玻璃镜面 / 白墙) 上 NeRF 重建失败会传导到 agent 推理, 鲁棒性受限。代价 3: 训练数据稀缺 — MMSI-Bench 仅 4.5K 样本, agent 需要大量空间推理 trace 数据, 扩展到工业场景 (工厂 / 仓储) 需要重新标注。

JanusMesh: Fast and Zero-Shot 3D Visual Illusion Generation via Cross-Space Denoising

论文解决 3D 视觉错觉生成问题 — 生成一个 3D mesh 从不同视角看到完全不同的语义 (例如某视角看到孔雀, 旋转 90 度看到菠萝)。传统方法分两类: (a) SDS-based optimization 慢且颜色过饱和; (b) naive stitching 拼接导致几何不连贯, 在目标视角出现明显接缝和语义泄露 (semantic leakage)。本文提出 JanusMesh, 第一个 fast and training-free 框架, 通过 cross-space dual-branch denoising 解决。核心思路: (1) 双分支 denoising — text-to-3D 阶段同时跑两个 latent space 分支 (text-A 空间 + text-B 空间), 每步去噪时跨空间交换 semantic guidance; (2) geometric consistency loss — 通过 depth alignment + normal consistency 强制 mesh 在任意视角都保持几何平滑, 杜绝接缝; (3) 无需训练 — 整个 pipeline 跑在预训练 text-to-3D diffusion model 上, 不需要 per-shape optimization。结果: 3-5 分钟生成一个高质量 3D 错觉 mesh (传统方法 30+ 分钟), 接缝率从 38% 降到 2.1%。

⚙️ 方法：JanusMesh 方法核心是 cross-space dual-branch denoising: 在 SDS diffusion 阶段同时维护两个 latent space (target A + target B), 每步去噪 cross-attention 时同时 attend 两个 text embedding, 通过 attention mask 控制不同视角的主导语义; 几何一致性靠 depth map alignment + normal field smoothness 约束, 训练阶段完全冻结, 只在 inference 跑 cross-space guidance。
⚖️ 取舍：代价 1: 推理显存高 — dual-branch denoising 比单分支需要 2x 显存, 在消费级 GPU (RTX 4090 24GB) 仅能跑 256^3 分辨率 mesh, 高分辨率 (512^3+) 需 A100/H100 80GB。代价 2: 几何复杂度受限 — 在 highly concave / multi-layer 目标 (如城堡 / 树枝) 上仍出现几何冲突, 跟单目标 text-to-3D 比仍逊 15-20% FID。代价 3: 视角范围有限 — JanusMesh 在 ±60 度视角内两个目标语义都能保持, 超过 ±90 度仍会出现语义模糊, 距离真正的任意视角错觉 (true omnidirectional illusion) 还有差距。

EvoEmbedding: Evolvable Representations for Long-Context Retrieval and Agentic Memory

论文指出当前 embedding 模型 (BGE / E5 / Qwen3-Embedding) 存在根本性限制: 它们在 encode 单段文本时忽略 surrounding context 和 temporal order, 只能在 static semantic search 上工作, 不适合 long-context + agentic memory 场景 (需要 state tracking)。本文提出 EvoEmbedding, 通过 latent memory 机制让 embedding 可演化: (1) 维护 continuously updated latent memory, 处理每个新 segment 时根据 memory 调整当前 embedding; (2) 同样 query 在不同 context 下能 retrieve 不同结果, 实现 context-aware retrieval; (3) 配套 EvoTrain-180K 数据集 (180K 样本), 联合优化 latent memory + retrieval; (4) 引入 memory queue 防 representation collapse, segment-batching 训练加速 3.8x。EvoEmbedding 在 long-context retrieval benchmark 上超越 Qwen3-Embedding-8B 和 KaLM-Embedding-Gemma3-12B 等更大模型, 同时在 RAG + agent memory 下游任务上平均提升 8-15%。

⚙️ 方法：EvoEmbedding 算法核心是 recurrent latent memory + context-conditioned embedding: encoder 维护 fixed-size latent memory state, 每段输入后用 gated update 更新 memory, 当前 embedding 由 raw content + memory 联合生成 (类似 RNN hidden state 但仅用于 retrieval 而非 generation), 训练用 contrastive loss + memory queue + segment-batching 三件套, 推理时 memory state 跨 query-turn 持久, 实现 multi-turn context-aware retrieval。
⚖️ 取舍：代价 1: 推理状态不可序列化 — EvoEmbedding 跨 turn 需要维护 latent memory state, 跟传统 embedding 的 stateless API 不兼容, 在分布式 retrieval service (Faiss / Milvus) 中需要改造 serving 框架支持 state passing, 短期内难以直接替换 BGE/E5。代价 2: 训练数据稀缺 — EvoTrain-180K 虽然比之前 best 多 6x, 但对比 embedding pretraining 用的 1B+ pair 数据仍小 5 个数量级, 在 niche domain (医学 / 法律) 仍欠拟合。代价 3: 显存开销 — 跨 batch 共享 memory state 需要 cross-batch state passing, 训练时 batch size 受限 (8-16 而非常规 64-256), 实际训练成本反而高于同参数量 baseline。

Pose6DAug: Physically Plausible Multi-view Object Swapping for Robot Data Augmentation

论文解决机器人 VLA (vision-language-action) policy 在 out-of-distribution 物体上的失败问题。传统 remedy 是收集每个失败 case 的 multi-view teleoperation data, 但 cost / time 都很高。Pose6DAug 提出 failure-driven data augmentation: 把 policy 自己成功的 episode 转成针对 failure mode 的 demonstration, 不需要任何新数据采集。核心 insight: 每个成功 episode 已经 encode 了 physically valid action trajectory + calibrated multi-view observations, 通过 3D 操作 (只 swap 操作的物体) 同时保留 trajectory, 就能得到 physically grounded new demonstration。技术核心: (1) 3D mesh anchoring — 在 3D 空间显式锚定 target object 的 mesh, 用 temporally coherent 6D pose trajectory 驱动, 保证 multi-view consistency; (2) geometric occlusion handling — 在 heavy occlusion / egocentric viewpoint 下仍能保持物理合理性, 避免 naive 2D video editing 的一致性破坏; (3) failure-driven sampling — 根据 policy 当前的 failure mode 选 augmentation 的物体 (texture / shape / size 维度)。在 5 个 manipulation benchmark 上平均提升 success rate 18-32%, 不需要任何额外采集。

⚙️ 方法：Pose6DAug 方法分 3 步: (1) 重建原始 episode 的 3D scene (multi-view NeRF / 3D Gaussian Splatting) + 提取物体 6D pose trajectory; (2) 用 mesh swap 替换目标物体 (从候选库选 OOD 物体), 沿原 trajectory 重新 render multi-view frames; (3) failure-mode classifier 选 swap 物体 — 根据当前 policy 失败模式 (texture confusion / shape unfamiliarity / size mismatch) 选最有效的 augmentation 物体类别。整个 pipeline 不需要 policy gradient 或 fine-tune, 是纯数据增强。
⚖️ 取舍：代价 1: 3D 重建依赖 — pipeline 需要对每个原始 episode 做 NeRF / 3D Gaussian 重建, 单 episode 重建时间 5-15 分钟 (用 GPU), 对大规模 dataset (1M episodes) 不现实, 仅适合 demo-augmentation 而非 pretraining-scale。代价 2: 物理仿真精度受限 — mesh swap 假设物体交互符合刚体动力学, 在 deformable objects (布料 / 食物 / 软体) 上物理合理性失效, 生成的 augmentation 数据反而会误导 policy。代价 3: 失败模式识别瓶颈 — failure-mode classifier 需要足够失败的 episodes 来训练, 在数据稀疏的 niche manipulation (手术 / 装配) 上 classifier 不可靠, augmentation 方向可能跑偏。

EFIQA: Explainable Fundus Image Quality Assessment via Anatomical Priors

论文聚焦眼底图像 (fundus image) 质量评估, 这是糖尿病视网膜病变 (DR) 自动筛查 pipeline 的关键前置步骤 — 质量差的眼底图像直接送入诊断模型会导致 30%+ 假阳性。传统 IQA (Image Quality Assessment) 模型是黑盒 CNN, 给出 score 但不解释为什么差, 医生无法 trust 且无法针对性补救。EFIQA 提出 explainable IQA: 通过 anatomical priors 把质量评估问题转化为 anatomical structure visibility 判断。具体: (1) 用预训练的 anatomical segmentation model (optic disc / macula / vessel) 抽取眼底图像的解剖结构; (2) 训练 quality regressor 不仅预测 overall score, 还预测每个解剖结构的 visibility score (optic disc visible / macula visible / vessel clarity 等), 给医生可解释的 failure mode; (3) 配套 dataset EyeQ-Public (扩展自 Eye-Q + Kaggle DR + 5 个公开眼底 dataset), 包含 15K 眼底图像 + 6 个 quality attribute 标注。在 6 个 IQA benchmark 上 AUC 平均提升 7.2%, 在 DR 筛查 pipeline 上 end-to-end 假阳性率降低 22%。

⚙️ 方法：EFIQA 算法分两阶段: (1) anatomical feature extraction — 用预训练的 fundus segmentation model (RetinaNet / DeepLab) 抽取 optic disc / macula / vessel / lesion 的 mask + confidence score; (2) explainable quality regression — 用 anatomical feature + original image 联合训练 quality regressor, 输出 overall score + 6 个 anatomical visibility 子 score, 子 score 通过 attention-weighted pooling 解释 quality 衰减源头。整体架构是 dual-head CNN, head A 预测 overall, head B 预测 anatomical sub-scores, 两个 head 共享 backbone, 用 multi-task loss 联合优化。
⚖️ 取舍：代价 1: anatomical segmentation 依赖 — pipeline 前置 segmentation model 自身的 failure 会传导到 IQA (segmentation 失败的图像同时会被判为低质量, 但原因错配), 在罕见眼底病理 (罕见 DR 病变) 上 segmentation 本身就不准, 解释性反成噪音。代价 2: 多任务训练开销 — 6 个 anatomical sub-score 联合训练需要 multi-task loss 调参, 在不同 dataset 上权重敏感 (Eye-Q 跟 Kaggle DR 最佳权重差 30%+), 跨 dataset 迁移需重新调参。代价 3: 6 个 sub-score 信息冗余 — 实操中医生只关心 1-2 个关键结构 (optic disc / macula visibility), 6 个 sub-score 中 3-4 个冗余, 增加 UI 复杂度而不直接提升诊断准确度。
