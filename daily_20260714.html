KronQ: LLM Quantization via Kronecker-Factored Hessian

想象你在工厂里要把一台重型机器压缩到一半体积, 还要保证它跑起来不抖——这就是 LLM 量化 (Quantization) 的活. KronQ 这篇做的就是: 不靠重新训练 (post-training quantization, PTQ), 直接把 4-bit / 8-bit 量化搞得更准. 痛点是现有 GPTQ 这种二阶 PTQ 方法只看'输入特征怎么分布', 忽略了'输出通道对量化误差的敏感度'——就像压缩机器时只看了零件重量, 没看齿轮咬合精度. KronQ 用 Kronecker 分解把 Hessian 矩阵拆成'输入 + 输出'两路乘积, 既能算得动 (二阶 Hessian 直接算不动), 又能完整刻画输出敏感度. 在 Llama-3 / Mistral / Qwen 系列上 4-bit 量化 perplexity 比 GPTQ 低 8-15%, 跟完整重训练 (OmniQuant) 差距从 5% 砍到 不到 1%.

📖 专业版问题讲解 (展开)
本文提出 KronQ, 一种基于 Kronecker 分解 Hessian 的二阶 post-training quantization (PTQ) 方法, 解决大语言模型 (LLM) 低比特量化中的精度退化问题. 现有二阶方法 (如 GPTQ) 仅基于输入激活统计构造量化目标, 隐含假设所有输出通道对量化误差同等敏感, 导致实际精度损失显著. 作者利用 Kronecker-factored Hessian 将完整二阶信息近似为'输入-输出' 两路乘积, 兼顾计算可行性与敏感性建模完整性. 在 Llama-3-70B / Mistral-7B / Qwen-72B 等模型上, 4-bit W4A4 量化设置下, KronQ 相比 GPTQ 在 WikiText-2 perplexity 上降低 8-15%, 与需要重训练的 OmniQuant 差距从 5% 缩减至不到 1%, 同时推理速度保持持平. 该方法无需任何反向传播或校准集再训练, 仅依赖前向统计, 部署成本接近 GPTQ 级别.
⚙️ 方法：核心方法: (1) Kronecker 分解 Hessian H 约等于 A 与 B 的张量积, 其中 A 刻画输入激活协方差, B 刻画输出通道敏感性; (2) 通过 K-FAC 风格近似把二阶矩阵乘法降为两次一阶矩阵乘法, 显存占用从 d 平方级降到 d 的 3/2 次方; (3) 量化目标函数从 min 范数 W x 升级为 min 范数 H 半幂 W x, 自然把输出敏感度纳入; (4) 集成到 GPTQ 的逐层 greedy 框架, 不需要重训练. 工程上完全复用 forward-only 推理流程, 一块 A100 即可量化 70B 模型 不到 30 分钟.
⚖️ 取舍：Kronecker 分解是对完整 Hessian 的有损近似, 当输入分布和输出敏感度的耦合非常强 (例如在高度专业化的 fine-tune 模型上) 时, 分解误差可能反向放大——论文在通用 base 模型上验证, 但对 domain-specific LoRA / 全参微调后的模型精度差距未充分评估. 另外二阶统计需要在前向过程中累积足够多样本, 小批量 / 流式场景下近似误差会显著上升, 工程上仍依赖 1024+ 样本的校准集. 相比 GPTQ 的部署便利性, KronQ 多了 Kronecker 分解步骤, 量化时间小幅增加 (10-20%).
📊 效果：核心数字: Llama-3-70B 4-bit W4A4 上 WikiText-2 perplexity 5.42 (GPTQ 6.18, OmniQuant 5.51, FP16 5.21); Mistral-7B 4-bit 上 perplexity 5.78 (GPTQ 6.45); Qwen-72B 4-bit MMLU 准确率保留 98.2% (GPTQ 95.4%). 量化时间不到 30min / 70B 单卡 A100, 跟 GPTQ 同量级. 部署后推理吞吐与 GPTQ 持平.

Long-Horizon-Terminal-Bench: Testing the Limits of Agents on Long-Horizon Terminal Tasks with Dense Reward-Based Grading

现在 Agent 评测大多 5 分钟就结束了, 跑完看个'成功/失败'二元分数——但真实业务里 Agent 经常要跑几小时甚至几天, 中间一步走偏就全盘崩. Long-Horizon-Terminal-Bench 这篇做了一个'小时级、多阶段、奖励密集'的 Agent 评测集, 评测 Agent 在长时间跨度内能不能稳. 关键创新是'Dense Reward-Based Grading'——把传统 0/1 终态评分改成对中间步骤 / 部分进展都给分. 结果: 现有最强 Agent (Sonnet 5 / GPT-5.6 / Claude Opus 5) 在这个 bench 上完成率不到 35%, 比短任务 (SWE-bench) 低 60%, 说明长时 Agent 的'中间过程治理'远未成熟.

📖 专业版问题讲解 (展开)
本文提出 Long-Horizon-Terminal-Bench, 一个小时级、多阶段、奖励密集的 AI Agent 长时任务评测基准, 弥补现有 terminal benchmark (如 SWE-bench / TerminalBench) 仅评估短时 (分钟级) 任务、且仅基于终态成功与否的二元评分的局限. 基准包含 200+ 个跨 8 类 (系统运维 / 数据管道 / CI/CD / 安全审计 / 批量 ETL / 长流程修复) 的真实终端任务, 平均完成时长 1.5-12 小时, 中位 3.5 小时. 核心创新是 Dense Reward-Based Grading (DRG): 对任务分解为 30-150 个 sub-goal, 每个 sub-goal 独立打分 (0/0.5/1) 加权汇总, 同时跟踪 token 消耗 / wall-clock 时间 / 中途失败-恢复次数. 评测 SOTA Agent (Claude Sonnet 5 / GPT-5.6 / Claude Opus 5 / DeepSeek-V3) 任务完成率 32% ± 4%, 比 SWE-bench 短任务低 58 个百分点; 中途失败后自主恢复成功率仅 24%; token 消耗是短任务的 11-23 倍.
⚙️ 方法：方法论: (1) 任务集设计采用 '真实工程师 6 个月工作日志回放', 每个任务包含完整 setup / 中途观察点 / 失败回滚场景; (2) DRG 评分采用 sub-goal decomposition + 知识追踪权重, 对'修复 + 解释 + 验证' 三段动作分别打分; (3) 评估维度扩展为: 完成率 (终态) + dense 分 (过程) + 中途恢复率 (韧性) + token 效率 (经济性) + 人类参考路径相似度 (对齐); (4) 引入 'time-budgeted evaluation', Agent 必须在限定 token / 时间预算内最大化 dense 分, 模拟真实生产环境的资源约束.
⚖️ 取舍：DRG 的 sub-goal 标注依赖领域专家, 8 个领域每个任务平均需要 3-5 小时人工标注, 这让 benchmark 难以快速扩展——200 个任务是 200+ 人工天投入, 加新领域成本线性增长. 另外 dense 分的权重设计有主观性, 不同团队对 '过程质量' 的定义可能差 20-30%, 这让跨 benchmark 比较存在 '权重不一致' 的归一化难题. 此外 hour-long 评测本身的复现成本极高 (单次 SOTA Agent 评测需要 200+ GPU 小时), 这阻碍了学界独立复现.
📊 效果：核心数字: SOTA Agent 任务完成率 32% ± 4% (Sonnet 5 35% 大于 GPT-5.6 31% 大于 Opus 5 29% 大于 DeepSeek-V3 27%); DRG dense 分 0.41 (满分 1.0), 比完成率高 9 个百分点; 中途失败后自主恢复成功率仅 24%; token 消耗中位数 1.2M / 任务 (短任务 80K), 最高单任务 18M tokens; wall-clock 时间中位数 2.8 小时; 与人类参考路径相似度 0.38, 说明 Agent 走的是'非人类路径'但常绕远.

PanoWorld: Real-World Panoramic Generation

全景图生成 (panoramic generation) 是世界模型 (world model) 的一块硬骨头: 你要让模型生成 360 度无缝环绕的视频, 但传统方法要么丢几何一致性 (旋转到背后场景突然跳变), 要么丢长时记忆 (走远就忘了起点什么样). PanoWorld 的核心思路是抓住全景图的'旋转等变性'——把相机旋转当成'隐式几何变换', 这样模型在训练时就能学到 '转 90 度 = 把图横移 + 上下卷' 的等价关系, 不需要额外标注. 配合新设计的 equirectangular attention 让模型在赤道和极地区域都用同一个 attention 窗口, 最终在 Room-to-Room / Replica / Habitat-Sim 三个仿真数据集上全景生成 FID 比 SOTA 低 22%, 长时一致性 (1 分钟以上) 比 SOTA 高 35%.

📖 专业版问题讲解 (展开)
本文提出 PanoWorld, 一种面向 360 度全景视频生成的 world model, 解决传统全景生成中的'几何不一致 (旋转到背后场景突变)'与'长时记忆丢失 (漫游后起点失真)'两大核心难题. 核心创新是利用 omnidirectional representation 的 rotation-equivariant 性质, 将相机旋转操作建模为隐式几何变换, 从而让模型在训练阶段就内化 '旋转 = 几何操作' 的等价性, 无需额外监督信号. 在 attention 层设计上引入 equirectangular positional encoding, 让赤道高密度区域与两极稀疏区域共享一致的 attention window, 避免传统 cubemap / ERP 投影在极区的采样爆炸问题. 在 Room-to-Room / Replica / Habitat-Sim 三个仿真数据集上, PanoWorld 相比 SOTA (e.g., Vista / GenWarp / 4D-BEV) 的 FID 降低 22%, 1 分钟以上长时一致性 LPIPS 改善 35%, 几何 warping error 降低 41%. 支持 30 秒 + 时长连贯全景视频生成, 推理速度 4.2 FPS (A100).
⚙️ 方法：核心方法: (1) Rotation-Equivariant Backbone: 把 3D 旋转群 SO(3) 的离散子群嵌入 attention, 训练时对每帧做随机水平旋转, 让模型学到 '旋转不变' 特征; (2) Equirectangular Attention: 极坐标 patch embedding + 球面相对位置编码, 让赤道与极区共享 attention 范围, 解决 cubemap 投影在极区采样稀疏的痛点; (3) Long-Range Memory Bank: 隐空间缓存最近 8 帧的 key-value, 通过球面坐标检索 (不是欧氏距离) 召回历史观测, 让走远后还能保持起点一致性; (4) 训练时同时监督 frame-level (像素) + scene-level (深度 + 法向量) + temporal (光流) 三路 loss, 让模型学到几何 + 时间 + 视觉的联合表征.
⚖️ 取舍：Rotation-equivariant backbone 训练时需要对每帧做随机水平旋转 augmentation, 训练时间相比 vanilla diffusion 增加 35%——单卡 A100 完整训练 7 天 vs SOTA 5 天. 另外 equirectangular attention 在极区的 patch 邻接是非欧的 (球面邻接), 现有 CUDA kernel 对非欧邻接优化不友好, 推理速度 4.2 FPS 相比 cubemap 投影的 12 FPS 有 3 倍差距, 落地到实时 VR / 游戏场景仍需工程优化. 此外 long-range memory bank 占用额外 3 GB 显存, 让 8GB 消费级显卡无法部署.
📊 效果：核心数字: Room-to-Room FID 18.4 (SOTA Vista 23.6, GenWarp 22.1), 降低 22%; Replica 长时一致性 LPIPS 0.18 (SOTA 0.28), 改善 35%; 几何 warping error 0.092 (SOTA 0.156), 降低 41%; 支持 30 秒 + 360 度连贯生成, 推理速度 4.2 FPS (A100 单卡), 显存峰值 22 GB. 消融实验显示 rotation-equivariant 单独贡献 FID 改善 11%, equirectangular attention 贡献 7%.

Video Generation Models are General-Purpose Vision Learners

NLP 领域靠 'next-token prediction' 把任务专属模型统一成 '通用 foundation model', 但 CV 一直没找到等价开关. 这篇论文提出: 大规模文生视频 (text-to-video, T2V) 模型就是 CV 领域的'next-token 等价物'——T2V 模型被迫学到'像素级 + 时间级 + 几何级 + 物理级'的联合表征, 这种表征天然可迁移到检测 / 分割 / 深度估计 / 光流 / 跟踪等下游任务. 作者用 DiT-XL 规模 T2V 模型做 frozen-feature extraction, 在 12 个 CV 任务上 fine-tune 一个线性 head 就能打到 SOTA 90% 以上, 部分任务 (如 video object segmentation) 首次超越 fully-supervised SOTA. 这是 CV 走向 'one foundation, many tasks' 的里程碑.

📖 专业版问题讲解 (展开)
本文论证大规模 text-to-video (T2V) 生成模型可作为计算机视觉领域的'通用 foundation model', 类比 NLP 领域 next-token prediction 推动 foundation model 统一化的角色. 核心论点是: T2V 模型在 '像素 + 时间 + 几何 + 物理' 联合分布上的预训练, 迫使其学到比图像分类 / 对比学习 / MAE 更通用的视觉表征, 这种表征天然可迁移到 dense prediction / 分割 / 检测 / 深度 / 光流 / 跟踪等下游任务. 作者使用 DiT-XL 规模 (675M 参数) T2V 模型作为 frozen feature extractor, 在 12 个 CV benchmark (COCO detection / ADE-20K segmentation / NYU depth / Sintel optical flow / DAVIS video segmentation / Kinetics action recognition 等) 上 fine-tune 线性 head 即可达到 SOTA 90%+ 水平, 其中 video object segmentation 首次超越 fully-supervised SOTA 3.2 mIoU, video depth estimation 接近 SOTA 误差 0.043. 消融实验显示 T2V 表征的通用性源于其'预测像素序列'而非'预测语义标签'的训练目标.
⚙️ 方法：方法论: (1) 使用 675M 参数 DiT-XL T2V 模型 (在 LAION-Chronicle 200M 视频上预训练) 作为 frozen encoder; (2) 从 T2V 模型的 intermediate DiT block (选 block 12、18、24) 抽取 spatial-temporal feature maps; (3) 对每个下游任务, 只 fine-tune 一个 task-specific 线性 head + 1-2 层轻量 adapter (参数量不到总模型 1%); (4) 训练数据只用目标任务的官方 train split, 不用任何额外数据; (5) 评测时把 frozen feature + linear head 端到端推理, 不需要 video 生成模型的解码器; (6) 与同期对比: 同样的 frozen 设置下, T2V 表征在 dense prediction 任务上比 DINOv2 / CLIP / SAM 的 frozen 表征高 8-15 个百分点.
⚖️ 取舍：T2V foundation model 推理成本极高 (675M 参数, 11 FPS / A100), 部署到边缘设备 (手机 / AR 眼镜) 不可行, 实时应用必须先用蒸馏 / 量化把模型压到 不到 100M 参数, 论文未提供完整蒸馏 pipeline. 另外 T2V 表征对'语义类别'的判别力弱于专门预训练的 CLIP / DINOv2, 在 zero-shot image classification 上落后 6-10 个百分点, 说明 T2V 适合 dense prediction 但不适合 high-level semantic 任务. 此外 frozen 设置让 fine-tune head 必须承担全部任务适配, 对复杂任务 (如 video captioning) 的适配深度不足, 跟 full fine-tuning 仍有 15-20% 差距.
📊 效果：核心数字: COCO detection frozen-T2V linear head mAP 58.4 (SOTA fully-supervised 62.1, 达到 94%); ADE-20K segmentation mIoU 47.2 (SOTA 51.8, 91%); NYU depth estimation RMSE 0.43 (SOTA 0.41, 接近); DAVIS video segmentation mIoU 86.3 (SOTA 83.1, 首次超越 +3.2); Sintel optical flow EPE 2.84 (SOTA 2.31, 81%); Kinetics-400 action recognition top-1 81.4 (SOTA 89.0, 92%). 12 个任务平均达到 SOTA 90%+ 水平, video class 任务最强, image class 任务稍弱. 推理速度: frozen T2V encoder 11 FPS (A100), fine-tune head 几乎免费.

📖 专业版问题讲解 (展开)
本文推出 Soofi S 30B-A3B, 一种主权、开源的 Mixture-of-Experts (MoE) hybrid Mamba-Transformer 基础模型, 专为德语和英语设计, 旨在满足欧盟对 '数字主权' (digital sovereignty) 的战略需求. 总参数量 30B 但每次推理只激活 3B (active parameters), 通过 Mamba 状态空间模型 (SSM) 与 Transformer attention 的混合架构, 在长上下文场景下实现 near-constant inference cache, 显著优于纯 Transformer 模型的 KV cache 线性增长问题. 模型在 1.5T token 欧洲语料 (含德国联邦法律 / 学术论文 / 媒体 / 政府公开数据) 上预训练, 100% 满足 GDPR 合规, 推理可完全本地化, 不依赖美国云服务. 在 German legal benchmark (JuraEval) / English MMLU / 长上下文 RULER (128K context) 上, 30B-A3B 性能接近 Qwen-72B 与 Llama-3-70B, 但推理速度比 70B dense 模型快 3.5 倍, 显存占用低 60%.
⚙️ 方法：核心方法: (1) Hybrid Mamba-Transformer: 70% Mamba SSM 层 + 30% 标准 attention 层交替堆叠, 让 SSM 处理长序列高效性 + attention 处理精确检索; (2) MoE 路由: 16 个 expert, top-2 激活, 每个 token 只激活 3B 参数, 平衡容量与效率; (3) 数据治理: 100% 欧洲数据源 + GDPR 合规审计 + 严格版权链验证, 训练数据来源 100% 可追溯; (4) 本地推理优化: 支持 GGUF 量化 (4-bit 不到 16GB 显存部署), Mamba state 可序列化到 NVMe, 让消费级 GPU 也能跑 30B 模型; (5) RLHF / DPO 用欧洲标注团队, 价值观对齐到欧盟 AI Act 框架.
⚖️ 取舍：Mamba SSM 在精确检索任务 (如 '找出第 87 段中'X' 词') 上比 attention 弱 5-8 个百分点——论文承认在 8K 以下短上下文, Mamba 的优势不明显, 主要优势在 64K+ 长上下文场景, 这限制了模型在短文本客服 / 对话场景的部署价值. 另外 100% 欧洲数据让模型在 '美国流行文化 / 流行梗 / 实时事件' 上的知识落后通用模型 6-12 个月, 对面向北美 / 亚太用户的产品是显著劣势. MoE 路由对工程部署要求高, top-2 gating 推理时偶发 'expert imbalance' (个别 expert 被过度激活), 需要运行时 rebalance.
