Qwen-Image-2.0-RL Technical Report

想象一下, 你让 AI 画一张「夕阳下的雪山 + 一只狐狸」, AI 画出来像但细节不对 (狐狸眼睛不像动物, 雪山光照奇怪) —— 普通训练只能让 AI 学会「像不像真的图片」, 但学不会「人眼觉得好不好看」+「跟文字描述对不对得上」。Qwen-Image-2.0-RL 走的是用人类反馈当老师 (RLHF) 的路子, 但跟 ChatGPT 那种语言模型上 RLHF 不一样, 它专门给「画图模型」设计了一套奖励系统 + 训练框架。

📖 专业版问题讲解 (展开)
Qwen-Image-2.0-RL 提出针对扩散模型的后训练 pipeline, 结合 RLHF (Reward Model from human feedback) 和 on-policy distillation (OPD)。Reward system 为 T2I 和 image editing 分别设计复合 reward (alignment / aesthetics / portrait fidelity for T2I; instruction-following + face identity for editing), 基于 fine-tuned VLM 用 chain-of-thought 做 pointwise scoring。训练侧用 GRPO 算法 + 混合 CFG 策略 + intra-group reward 过滤 + per-category reward 权重校准。最后用 on-policy distillation 把 T2I 跟 editing 两个专家合并到单一学生模型 (trajectory-level velocity matching)。
⚙️ 方法：核心是 reward system + RL 训练 framework + on-policy distillation 三件套: (1) Reward: 为 T2I 训练 alignment / aesthetics / portrait fidelity 三类 reward model; 为 editing 训练 instruction-following + face identity preservation reward, 全部基于 fine-tuned VLM + CoT pointwise scoring。(2) Training: GRPO 算法 + 混合 CFG 保留预训练知识 + intra-group reward range filtering 做 prompt curation + per-category reward weight calibration。(3) Distillation: on-policy distillation 用 trajectory-level velocity matching 把多个 task-specialized policy 合并到单学生模型。
⚖️ 取舍：代价 1: 多 reward model + per-category weight calibration 引入显著训练成本, 不适合小团队复现 —— 需要为每个 reward 维度独立 fine-tune VLM。代价 2: on-policy distillation 阶段需要多个 task-specialized teacher 同时采样, 显存 + 计算开销 ≈ 3x single-teacher distillation。代价 3: 评估依赖 Elo rating + Qwen-Image-Bench, 这些 benchmark 本身偏向 Qwen 优势场景, 跨 benchmark 泛化性 (GenEval / T2I-CompBench 等) 还需要更多验证。
📊 效果：Qwen-Image-2.0-RL 在 Qwen-Image-Bench 拿到 57.84 overall score (+2.61 over base); text-to-image arena Elo 1193 (+78); image edit arena Elo 1349 (+93)。在三个维度 (审美质量 / prompt adherence / editing accuracy) 都有 consistent gain, 验证了 RLHF + on-policy distillation 在 diffusion 后训练上的可扩展性。

PhysisForcing: Physics Reinforced World Simulator for Robotic Manipulation

想象一下, 你让 AI 学「抓杯子放桌上」, AI 看了一堆视频, 模拟器生成的视频里杯子「瞬移」、手指「穿模」、桌子「自己动」 —— 这些都是「物理不像真」的 bug。PhysisForcing 想让 AI 生成的视频在「物理规律」层面更像真, 这样机器人拿这个视频当训练数据, 学到的策略才不会在真实世界翻车。它专门盯「物理出问题的局部」(物体变形 + 多物体时空关系不对), 用两个 loss 一起纠错。

📖 专业版问题讲解 (展开)
PhysisForcing 针对 embodied world simulation 里的物理不一致问题, 提出 scalable training framework。核心观察: 物理不稳定主要由两个因素造成 —— (1) 运动物体自身变形; (2) 接触期间交互实体之间不合理的时空相关性。框架由两层 loss 组成: (a) pixel-level trajectory alignment loss, 用 reference point trajectories 监督 DiT features; (b) semantic-level relational alignment loss, 用 frozen video understanding encoder 抽取的 inter-region relations 对齐 DiT features。实验在 R-Bench / PAI-Bench / EZS-Bench 上验证, 改进 Wan2.2-I2V-A14B 和 Cosmos3-Nano base models。
⚙️ 方法：Two-level physics-informed loss: (1) Pixel-level: trajectory alignment loss 用 reference point trajectories 监督 DiT intermediate features, 强制模型学运动物体在时间维度上的几何一致性; (2) Semantic-level: relational alignment loss 用 frozen video understanding encoder 抽取的 inter-region 关系 (接触 / 推动 / 抓握) 对齐 DiT features, 强制模型学多物体交互语义。Both losses 加权联合优化, focus supervision 在 physics-informative 区域 (物体运动 + 接触时刻)。
⚖️ 取舍：代价 1: 两个 loss 加权联合训练需要 reference point trajectories annotation, 数据准备成本比 vanilla video generation 高。代价 2: frozen video understanding encoder 引入额外 inference 开销, training 阶段显存增加约 30-40%。代价 3: 评估只在 3 个 closed-loop benchmark (R-Bench / PAI-Bench / EZS-Bench) 上, 真实机器人部署 (manipulation success rate on hardware) 的 end-to-end gain 还需要更广泛验证。
📊 效果：在 R-Bench 上改进 Wan2.2-I2V-A14B 和 Cosmos3-Nano base models 22.3% 和 9.2%, 比 vanilla finetuning 进一步提升 7.1% 和 3.7%。Cosmos3-Nano 变体拿到 best overall score。作为 world model 在 WorldArena action-planner protocol 下 closed-loop success rate 从 16.0% 提升到 24.0%, downstream policy success 也显著提升。

GBC: Gradient-Based Connections for Optimizing Multi-Agent Systems

想象一下, 你让 5 个 AI 同事合作做一个项目 (一个查资料, 一个写代码, 一个检查 bug...), 出了错你怎么知道「到底是谁的那一步搞砸了」? 现在的多 Agent 系统只能给你「最终任务成功 / 失败」这个粗粒度反馈, 想精确定位 bug 来源很难。GBC 把多 Agent 系统当成一个有向图, 每一步算「梯度」(类似深度学习的反向传播), 找出「谁对最终错误贡献最大」, 针对性改 prompt。

📖 专业版问题讲解 (展开)
GBC (Gradient-Based Connections) 提出针对 LLM multi-agent systems (MAS) 的 fine-grained credit assignment 方法。把 MAS 建模成 directed computational graph, 引入 gradient-based connection weights 在 token-level 量化每个 agent 的 output 对 downstream agents 的影响。通过构建 attribution graph + 沿 task-specific loss 反向传播, 实现 error source 的精确定位 + targeted prompt optimization。配套实现 AgentChord, 利用 prefix-based gradient computation 提升 efficiency。在 MultiWOZ 和 τ-bench 上验证, GBC 改善 multi-agent 性能, attribution quality 跟 optimization effectiveness 正相关。
⚙️ 方法：Two-stage framework: (1) Attribution: 把 MAS 建模成 directed graph, 每个 edge 是 token-level gradient-based connection weight, 反向传播 task loss 得到 attribution graph, 精确定位 error source。(2) Optimization: 基于 attribution graph 做 targeted prompt optimization, 优先优化对错误贡献最大的 agent / step。Implementation: AgentChord 利用 prefix-based gradient computation, 复用 KV cache + prefix 共享, 大幅降低 attribution 的 compute cost。
⚖️ 取舍：代价 1: Gradient-based attribution 需要 task-specific loss 反向传播, 跟 supervised fine-tuning 流程深度耦合, 对 zero-shot agent pipeline 适用性有限。代价 2: Prefix-based 优化要求 agent 间 prompt 有 shared prefix, 对独立实现的 heterogeneous agents 不友好。代价 3: 实验只在 dialogue (MultiWOZ) + customer service (τ-bench) 两个 domain, coding agent / research agent 等其他 multi-agent 场景的泛化性未验证。
📊 效果：在 MultiWOZ (multi-domain dialogue) 和 τ-bench (customer service benchmark) 上, GBC 提升 multi-agent performance, 超过 strong single-agent + multi-agent baselines。Higher attribution quality (gradient weights 更准确) 关联 greater optimization effectiveness, 验证了 attribution → optimization 的因果链。AgentChord 比 naive gradient computation 快 5-10x, 接近 practical deployment 门槛。
🏢 团队：Xiaocheng Yang, Abdulrahman Alrabah, Dilek Hakkani-Tür, Gokhan Tur → University of Illinois Urbana-Champaign (UIUC, 伊利诺伊大学厄巴纳-香槟分校, 美国伊利诺伊州)

When Does Combining Language Models Help? A Co-Failure Ceiling on Routing, Voting, and Mixture-of-Agents Across 67 Frontier Models

想象一下, 你同时用 GPT-5.5 + Claude Opus 4.8 + Gemini 3 Pro + DeepSeek V4 + Qwen3.7 + Kimi K2.7 ... 总共 67 个顶级模型, 让他们投票 / 路由 / cascade 看答案是不是更准。作者发现: 这种「多模型 ensemble」准确率有个数学天花板 —— 等于「1 减去所有模型一起错的概率」(β)。市面上常见的「配对错误相关性」(ρ) 这个指标, 根本测不出 β, 所以大家高估了 ensemble 的增益。

📖 专业版问题讲解 (展开)
论文挑战 multi-model LLM systems (routing / voting / cascades / fusion / MoA) 领域的核心 diagnostic。理论证明: 任何「输出是某个成员模型答案」的 policy (router / vote / cascade), 准确率不可能超过 1 - β (β = all-wrong rate)。然而业界普遍报告的是 pairwise error correlation ρ, 但 ρ cannot identify β: 即便 marginals + pairwise correlations 相同, β 可以差很大。给出 Clopper-Pearson bound, 把一个 graded held-out query set 转化成「任何 policy 的最大增益都有 $0 certificate」的 bound, 在 router 训练之前就能算。跨 67 frontier models (GPT-5.5 / Claude Opus 4.8 / Gemini 3.1 Pro / Grok-4.3 / DeepSeek V4 / Qwen3.7-Max / Kimi K2.7) 21 个 provider 实测。
⚙️ 方法：Three components: (1) Theoretical: 证明 accuracy ceiling = 1 - β, 给出 Clopper-Pearson bound 把单 graded held-out query set 转化成对 β 的置信区间, 任何 ensemble policy 的最大增益都有可计算的 upper bound。(2) Empirical: 跨 67 个 frontier models (21 个 provider) 实测 β vs ρ, 验证 calibrated single-factor model 仍然 underprices all-wrong tail, 偏差随 pool size 扩大 (open-ended math 上 2.5x)。(3) Format sensitivity: 把 GPQA-Diamond 改成 free-response 而非 multiple-choice 时, β 从 0.073 升到 0.127, 把效果归因于 task format 而非 subject domain。
⚖️ 取舍：代价 1: 实验集中在 reasoning / coding 等可验证任务, creative writing / open-ended generation 等任务 β 定义本身模糊, 论文结论对那部分场景不直接适用。代价 2: 67 models pool 是 2026 上半年的快照, 新 model (GPT-5.6 / Claude Mythos 等) 出现后需要重新校准 β vs ρ 关系。代价 3: 论文主要验证 upper bound, 对如何 exploit 这个 bound 设计 better ensemble policy (具体 architecture / routing algorithm) 提供的 actionable guidance 较少。
📊 效果：67 frontier models 跨 21 provider 的 β 比 calibrated ρ 预测的高约 2.5 倍 (90% CI 1.7-3.4, k=17), 在 full 67-model Gaussian copula 下保持 (ρ=0.052 vs predicted 0.023)。在 execution-graded code task 上 β=0.079。论文给了一个 actionable 结论: 「diverse low-ρ ensemble 优于 high-ρ Self-MoA」 + 「task format (free-response vs MC) 比 subject domain 更影响 ensemble 上限」, 工程上 ensemble 大部分时候打不过 single best model 除非有 strong query-level routing signal。
🏢 团队：Josef Chen → KAIKAKU (新加坡 AI 创业公司, Josef Chen 是创始人)

Ko-WideSearch: A Korean Breadth-Search Benchmark for Exhaustively Enumerating Sets by Web Agents

想象一下, 你让 AI 「列出 2026 年 6 月韩国所有廉航, 每家写母公司 + 成立年份 + 主基地 + 当前机队规模」 —— 这不是「搜一个答案」, 是「找全一个集合 + 给每个成员填好几个字段」。Ko-WideSearch 是首个专门测 AI 「广度搜索」能力的韩文 benchmark, 228 张表 4,262 行 14,560 个 cell, Item-F1 高 (92.8) 但 Row-F1 只有 53.7, 说明 AI 找得到集合却填不全字段。

📖 专业版问题讲解 (展开)
Ko-WideSearch 是 Korean breadth-search benchmark, 自动化 synthesize-and-verify pipeline 构建。每个 task 命名一个 set-parent entity (TV season / dynasty / league / administrative region / election), 要求 enumerate 完整集合 + 给每项填 attribute table, 按 Item-F1 / Column-F1 / Row-F1 三层评分。228 tables 跨 190 entities + 16 categories, 三个难度 tier 由两个 structural knob 独立控制: table width (列数) 和 2-D composite key (复合键复杂度)。一个 normalization-aware comparator 在 gold construction 和 grading 之间共享, 防止稳定 date / count column 因为 formatting 被误 drop。
⚙️ 方法：Three contributions: (1) Ko-WideSearch 数据集: 228 韩语 breadth-search tables, 4,262 gold rows + 14,560 attribute cells, 跨 190 set-parent entities + 16 categories, 全部 web-sourced + decontaminated。(2) 自动化 synthesize-and-verify pipeline: build agent 自动生成候选 set + verify step 验证 completeness, 让韩语 breadth evaluation scalable 同时保证 gold trustworthy。(3) 评分设计: Item-F1 (找对集合成员) / Column-F1 (列定义正确) / Row-F1 (每行填全), 三层独立评分 + 一个 normalization-aware comparator 共享于 gold 构建 + 评分, 防止 date / count 因 formatting 被误 drop。
⚖️ 取舍：代价 1: Ko-WideSearch 专门针对韩语 + structured table, 对长文档 / 多跳 reasoning 评估仍然缺位 (跟 BrowseComp / K-BrowseComp 互补但不替代)。代价 2: 自动化 synthesize-and-verify pipeline 本身依赖 build agent 质量, gold set 仍有 ~5-10% 错误率, 影响 benchmark ceiling。代价 3: 评估只跨 20 个 agents, 未涵盖 specialized enterprise agents (RAG + tool use workflow), 这类 agent 在 production 场景更普遍。
📊 效果：跨 20 个 web agents (含 GPT-5.5 + Claude Opus 4.8 + Gemini 3 Pro + Qwen3.7-Max + 多个 specialized Korean agents) 实测, failure pattern 一致: agents 找得到 set (Item-F1 92.8) 但填不全 rows (Row-F1 53.7), accuracy 随 knob 收紧稳定下降, 更多 search / 更多 spend 都 close 不了 gap。Cell-level breakdown 显示 hard part 是「找到 right value」而非「format 正确」: open-ended free-text cells 失败最多, 标准答案 cells (date / name) 通常能答对。
🏢 团队：Minbyul Jeong → Upstage AI (韩国首尔, Solar / LLM 厂商)
