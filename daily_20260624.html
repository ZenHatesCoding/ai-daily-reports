EnterpriseClawBench: Benchmarking Agents from Real Workplace Sessions

论文提出 EnterpriseClawBench, 一个从真实企业工作流 (而非人工标注 demo) 构建的企业级 agent 评测基准。从私有工作会话档案出发, 通过 4 阶段流程构建 852 个可复现任务, 每个任务配 recovered fixtures (文件 + 工具状态), rewritten prompts (去敏感化后的企业 prompt), role classes (员工角色: 财务/法务/HR/PM/工程师), skill subclasses (技能分类: 文档生成/审批流/数据查询/客户沟通), hard rules (合规约束), 和 semantic rubrics (语义评分准则)。因为会话含企业机密内容, benchmark 数据不公开, 但论文贡献的是 construction protocol + evaluation rubric 这套方法论。在 EnterpriseClawBench 上, 最佳配置 (Codex + GPT-5.5) 仅达到 0.663, 比通用 agent 基准 (SWE-bench 65%+) 低很多, 说明企业真实场景是 agent 落地的真正瓶颈。

⚙️ 方法：方法核心是 4 阶段真实会话转 benchmark 流程: (1) workspace archive mining 从企业 agent 日志中按 role/skill 聚类, (2) session rewrite 把 PII + 商业机密脱敏并泛化, (3) fixture recovery 把每个 session 用到的文件/工具/中间产物恢复成可复现执行环境, (4) rubric design 由领域专家 + LLM 联合设计 semantic 评分细则。整个流程是可重用的, 论文开源 protocol 代码 (不含数据)。
⚖️ 取舍：代价 1: 闭源数据 — 因为会话含真实商业机密, benchmark 数据不公开, 第三方研究者无法复现具体任务, 只能复现协议, 对学术界的可比性有限。代价 2: 协议复杂度高 — 4 阶段流程需要企业级数据脱敏 + 领域专家标注, 单家中小企业难以独立构建类似 benchmark, 容易形成大厂 (Frontis/Scale) 的数据壁垒。代价 3: rubric 主观性 — semantic rubrics 由 LLM + 专家联合设计, 不同企业 (金融 vs 制造 vs 电商) 的合规细则差异极大, benchmark 通用性受限。
📊 效果：在 EnterpriseClawBench 上评估 6 个 SOTA agent 配置 (Claude Code + Claude 4.5 / Codex + GPT-5.5 / Devin v2 / AutoGen + GPT-5 / CrewAI + Claude / SWE-Agent + Claude), 最佳 Codex + GPT-5.5 达到 0.663 平均分, 最差 SWE-Agent 仅 0.31。角色维度: 法务任务最难 (平均 0.41), 财务任务最简单 (0.71)。技能维度: 文档生成 (0.78) 高于 客户沟通 (0.49) 与 审批流 (0.45)。失败案例分析: 72% 失败源于工具调用 schema 错误, 18% 源于长上下文遗忘, 10% 源于 hallucinate 业务规则。
🏢 团队：Zhang Kaiyan, Chen Wei, Liu Hao et al. → Horizon Research + Frontis.AI (前沿人工智能, 中国)

KaLM-Reranker-V1: Fast but Not Late Interaction for Compressed Document Reranking

论文提出 KaLM-Reranker-V1, 一个 fast-but-not-late-interaction (FBNL) 重排序模型, 解决现有 reranker 在 query 和 passage 联合编码时的算力浪费问题。传统 reranker 分两类: (a) cross-encoder 全联合编码, 精度高但每对 query-passage 都要重新 forward, 不适合大规模检索; (b) bi-encoder 预编码 passage, 快但精度低。late-interaction (ColBERT 类) 折中但仍需逐 passage 计算。本文 FBNL 思路: encoder 预编码 passage 用 Matryoshka embedding pooling (可变维度截断), decoder 模型 system instruction + user instruction + query intent, 通过 cross-attention 捕获 query context 与 passage 表示的关联。优势是 passage 侧只需预编码一次 (跟 bi-encoder 一样), 但 query 侧能利用 decoder 的强语义建模 (跟 cross-encoder 一样), 精度损失 < 3% 但推理速度提升 4-7 倍。

⚙️ 方法：方法核心是 encoder-decoder 分离架构 + Matryoshka pooling: (1) encoder 侧把 passage 预编码成多粒度向量 (128/256/512/768 维), 用 Matryoshka Representation Learning 让低维向量也能保留关键语义; (2) decoder 侧只对 query + instruction 做标准 transformer 解码, 通过 cross-attention 拿 passage 向量; (3) 训练阶段联合优化 query encoding + passage encoding, 推理阶段 passage 离线编码 + cache, query 在线编码 + cross-attend。
⚖️ 取舍：代价 1: Matryoshka pooling 牺牲精度 — 低维向量 (128 维) 比 768 维 nDCG 下降 4-5%, 需要根据场景权衡维度选择。代价 2: passage cache 占用 — 大规模企业级检索库 (亿级文档) 用 768 维 Matryoshka 全缓存需要 ~300GB 显存, 比 BM25 index 大很多, 部署成本是真实约束。代价 3: 训练数据依赖 — 模型表现依赖 query-passage 联合训练的标注数据, 跨领域 (医疗/法律/金融) 迁移时需要重新微调, 通用性受训练数据覆盖范围限制。
📊 效果：在 BEIR 13 个子基准 + MIRACL 中文检索基准上, KaLM-Reranker-V1-1.5B 达到 nDCG@10 平均 56.7 (vs ColBERT-v2 54.2, vs BGE-reranker-v2-m3 55.8), 接近 cross-encoder 7B 模型 (58.1) 精度但只占 1/5 显存。推理速度: 768 维 Matryoshka pooling 让长文档 (10K token) 检索速度 4.7 倍快于 ColBERT-v2, 跟 BM25 + 简单 bi-encoder 速度持平。中英双语 benchmark 表现一致 (MIRACL-zh nDCG@10 68.3 vs 65.4)。

Causal Discovery in the Era of Agents: Data First, Agents Assist

论文对当前 LLM 与因果发现 (causal discovery) 结合的方法做系统性反思, 主张 agents 应该 assist the workflow 而非 supply causal conclusions。当前 LLM 介入因果发现的三种模式 (推断 pairwise direction / 提出 graph structure / 注入 LM 输出作 prior) 都混淆了 data-supported evidence 和 textual associations, 把 prompt artifacts + hallucinated mechanisms 当作因果证据。本文提出 causal-learn+ 平台, 把 agents 定位为: 检查数据、检索上下文、解释方法假设、澄清 graph 输出, 但不提供 edges / orientations / priors / constraints / causal conclusions。核心原则: 因果声明必须 grounding in data + explicit assumptions + formal algorithms + diagnostics + user decisions。配套 Big Five personality 数据 case study 验证 agent-assisted 流水线在不把 LM unreliability 转化为 causal evidence 的前提下加速因果发现。

⚙️ 方法：方法核心是 causal-learn+ 平台架构 + causal-grounding 约束: (1) 平台整合 causal-learn 生态 (PC algorithm / GES / FCI / NoTEARS 等算法库), agents 作为 orchestrator 协调数据预处理 / 方法推荐 / 专家知识注入 / 形式化发现 / 结果解释; (2) causal-grounding constraint 强制要求任何 agent 输出都可追溯到具体数据点 + 假设 + 算法, 不允许 free-form 因果声明; (3) diagnostics 模块自动检测违反 assumption 的情况 (高维小样本 / latent confounder / selection bias), 给出 human review 触发条件。
⚖️ 取舍：代价 1: 速度比纯 LLM 慢 — 因果发现需要数据预处理 + 假设验证 + 多种算法比较, agent 辅助模式比 end-to-end LLM 慢 3-5 倍, 不适合需要即时因果判断的场景 (临床实时决策)。代价 2: 依赖领域专家 — diagnostics 模块的 assumption violation 检测需要统计 + 领域双重知识, 普通用户难以独立判断 review trigger, 实际部署需要 training 的 causal scientist 在场。代价 3: 不解决根本争议 — 论文把 agents 定位为助手而非因果推理主体, 但当前学界对 LLM 是否能产生新 causal hypothesis 仍有分歧, 论文回避了这一立场。
📊 效果：在 8 个标准因果发现 benchmark (Sachs / SynTReN / Alarm / Hepar2 等) 上, causal-learn+ (with GPT-5 agent) 比纯 LLM-based causal discovery 方法 (LLM-Causal / DirectLLM) F1 提升 14-22%, 比传统算法 (PC / GES) 在样本量 < 500 时 F1 提升 8-12%, 但在样本量 > 5000 时与传统算法持平。Big Five personality case study 上, agent 加速数据预处理 5 倍, 但 causal conclusions 100% 保留数据驱动, 无 hallucinated mechanism。Human review rate 23% (LLM-only baseline 4%), 说明更严格的不确定性沟通。

Unlimited OCR: One-shot Long-horizon Parsing with Human-like Working Memory

论文针对 end-to-end OCR 模型 (DeepSeek OCR 为代表) 在长文本复制任务中的效率衰减问题提出 Unlimited OCR 模型。核心观察: 现有 OCR 模型用 LLM 作为 decoder, 输出序列越长 KV cache 累积越多, 内存消耗线性增长, 生成速度指数级下降 — 而人类在做长文本抄写时无此效率衰减。本文提出 Working Memory (WM) 机制: 把 DeepSeek OCR baseline 的所有 attention 层替换为 propose WM-Attention, 让 decoder 模拟人类工作记忆的 limited capacity + selective refresh 行为。具体: (1) WM-Attention 在每步生成时只 attend 局部 window + 关键 anchor token, 不 attend 全部历史; (2) Memory Refresh Policy 决定何时把局部 window 内容写入 long-term memory (压缩到固定容量); (3) 在 100K+ token 长文档复制任务上, 内存占用恒定 (vs baseline 线性增长), 速度恒定 (vs baseline 5x 衰减)。权重在 GitHub 开源 (github.com/baidu/Unlimited-OCR)。

⚙️ 方法：方法核心是 Working Memory Attention (WM-Attention) + Memory Refresh Policy: (1) WM-Attention 修改 decoder 的 attention mask, 强制每步只 attend 局部 sliding window (默认 1024 token) + sparse global anchor tokens (按 attention score top-k); (2) Memory Refresh Policy 每 512 步触发一次, 用 cross-attention 把局部 window 压缩到固定容量 (默认 4096 token) 的 long-term memory bank; (3) 训练阶段用课程学习 (curriculum learning), 从 1K token 长度逐步扩到 100K token, 让模型学会在长序列中保持稳定的 attention 模式。
⚖️ 取舍：代价 1: 短文本无优势 — 在 < 2K token 短文档 OCR 上 Unlimited OCR 与 DeepSeek OCR baseline 持平, Working Memory 机制未带来提升, 短文本场景用 baseline 更简洁。代价 2: 局部 window 大小是超参 — 默认 1024 token window 在 dense layout (表格 / 多栏) 文档上可能截断关键 layout 信息, 需要根据文档类型调参, 通用性受限。代价 3: 训练成本高 — 课程学习从 1K 扩到 100K token, 训练 compute 比 baseline 高 ~3 倍, 中小团队难以复现, 形成大厂 (百度) 的训练数据 + compute 双重壁垒。
📊 效果：在 5 个长文档 OCR benchmark (CCLongOCR / DocVLM-Long / LongDocBench / Arxiv-100K / Custom-Book) 上, Unlimited OCR (7B 参数) 在 100K token 文档复制任务上 F1 达到 96.8%, 跟人类抄写准确率 (97.2%) 持平, 比 DeepSeek OCR baseline (72.3% F1, 100K token) 高 24.5 个百分点。速度: 100K token 文档 7 秒完成 (vs baseline 47 秒且 OOM), 内存峰值 18GB (vs baseline 89GB)。短文本 (1K token) 上跟 baseline 持平, 无明显精度损失。

Vera: A Layered Diffusion Model for Content-Preserving Video Editing

论文解决视频编辑中 content preservation 的核心挑战: 现有视频 diffusion 模型在编辑时重新生成所有像素, 经常改变应保持不变的元素 (角色外观 / 背景场景)。本文提出 Vera, 一个分层扩散框架, 核心是把生成过程分为 edit layer (编辑层) + alpha matte (合成蒙版) + source video (源视频) 三层, 通过 Mixture-of-Transformers (MoT) 架构让编辑层与源视频通过 joint self-attention 协同。具体: (1) edit layer DiT 生成编辑内容 (新增物体 / 修改风格 / 替换角色), (2) alpha matte DiT 决定 edit layer 在每一帧每一像素的透明度, (3) MoT 让两个 DiT 通过 joint self-attention 保持空间一致性。结果: 在 DAVIS / YouTube-VOS / 自建电影片段基准上, content preservation F1 达到 92.4% (vs baseline 71.2%), 编辑质量 (FID-Edit) 提升 14.3 个百分点, 同时支持 1080p / 30fps 长视频 (60+ 秒) 编辑。

⚙️ 方法：方法核心是 Layered Diffusion + Mixture-of-Transformers (MoT): (1) Layered Diffusion 把传统 video diffusion 的单层输出拆为 edit layer + alpha matte, 合成时按 alpha 融合源视频与编辑层; (2) MoT 架构 — 把 text-to-video DiT 扩展为多 DiT (每个 layer 一个 DiT), 通过 joint self-attention 让不同 layer 的 token 在 attention 中互相 attend, 保持空间 + 时间一致性; (3) 训练数据用合成电影片段 + 真实 DAVIS, 配合 frame-by-frame alpha supervision。
⚖️ 取舍：代价 1: 推理成本高 — 双 DiT + joint self-attention 让推理显存是单 DiT baseline 的 2.1 倍, 长视频 (60+ 秒) 编辑需要至少 A100 80GB, 消费级 GPU (4090 24GB) 难以部署。代价 2: 训练数据依赖 — alpha matte 监督需要逐帧 alpha 标注, 自建数据集成本高, 跨领域 (动画 / 广告 / 短视频) 迁移需要重新标注 alpha。代价 3: 仍非完美 — 在大幅度运动 (fast camera pan / 角色快速移动) 场景下 content preservation F1 降到 84.1%, 编辑层与源视频的对齐仍有 motion blur 边界模糊问题, 适合中等运动场景而非极限运动。
📊 效果：在 DAVIS-2017 (40 视频) + YouTube-VOS-2024 (50 视频) + 自建 Netflix 内部电影片段 (20 段, 60-120 秒) 三个 benchmark 上, Vera-7B 达到 content preservation F1 92.4% (vs ProPainter 71.2% / vs TokenFlow 78.5%), 编辑质量 FID-Edit 23.7 (vs baseline 38.0), 用户研究 (n=80) 偏好度 82%。1080p / 30fps / 60 秒视频编辑耗时 4.2 分钟 (单 A100), 比 Runway Gen-3 / Pika 2.0 编辑时长短 40%。支持 6 种编辑类型: 物体增删 / 风格迁移 / 角色替换 / 季节变化 / 视角平移 / 动态效果添加。
