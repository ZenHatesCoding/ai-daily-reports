Remember When It Matters: Proactive Memory Agent for Long-Horizon Agents

想象一下: 你让 AI 跑一个长任务(比如一天内处理 50 个客户工单), 但到第 30 个时, 模型已经忘了'这是个 B2B SaaS 公司, 客户需要 24h 内回复'——上下文被淹没了, AI 跑偏了. 这篇论文把这个问题叫 'behavioral state decay' (行为状态衰减), 解决方案是给 Agent 配一个'记忆 Agent'——它跟 action agent 并行跑, 主动维护一个结构化 memory bank, 在需要时把'关键状态'塞回上下文.

📖 专业版问题讲解 (展开)
We study memory as an active intervention mechanism for long-horizon agents. We introduce the concept of behavioral state decay, where decision-relevant state is scattered across an expanding trajectory and pushed beyond context. A separate memory agent runs alongside an unmodified action agent, updating a structured memory bank from observation-action traces and selectively re-injecting critical state. We release MemoryAgentBench with 7 long-horizon tasks across ALFWorld / WebShop / tau-bench / VirtualHome. Memory agent improves success by 24-43% relative and reduces redundant actions by 35% on average, with the largest gains on tasks where trajectory length exceeds context window by 3x or more.
⚙️ 方法：双 Agent 架构: 一个'记忆 Agent'跟'行动 Agent'并行跑; 记忆 Agent 从观察-动作轨迹持续更新结构化 memory bank(分层: 任务要求 / 环境事实 / 失败诊断 / 开放子目标), 在每个决策点用主动注入机制选择性地把关键 state 塞回 action agent 的上下文窗口; 不修改 action agent 自身.
⚖️ 取舍：memory agent 本质是在 context window 之外建了第二层 working memory, 这种'外挂记忆'会有'写时遗忘'——记忆 agent 写下去的内容未必是 action agent 真正需要的; 论文没给出'记忆 Agent 的失败模式', 只测了'有它 vs 没它', 实际部署时 memory agent 本身也是 LLM, 会有自己的幻觉; 此外, 35% 的冗余动作减少在延迟敏感场景(web 实时客服)可能反而增加延迟(双 Agent 串行决策).
📊 效果：MemoryAgentBench 上 7 个长任务, memory agent 相对 baseline 提升 24-43% 成功率; 平均减少 35% 冗余动作; 在轨迹长度超过 context window 3x+ 的任务上提升最显著; 不修改 action agent 即可获得提升, 通用性高.

DrugGen 2: A disease-aware language model for enhancing drug discovery

想象一下: 现在 AI 制药工具能根据蛋白质结构生成新分子, 但它常常忽略'这个蛋白质在病人身上实际是哪个病'——同一个靶点在癌症和阿尔茨海默症里作用完全不同. 这篇 DrugGen 2 是第一个把'疾病本体 (disease ontology) + 靶点蛋白序列'同时作为条件的生成模型, 用 GPT-2 在已批准药物 + 疾病 + 靶点三元组数据上 fine-tune, 让 AI 制药从'靶点中心'转向'疾病中心'.

📖 专业版问题讲解 (展开)
DrugGen-2 is a disease-aware generative language model for small-molecule drug design, conditioned on both disease ontology and target protein sequences. We fine-tuned a pre-trained GPT-2 on a curated dataset of approved drugs linked to their diseases and targets via a two-step supervised-then-RLHF strategy. On drug-likeness (QED), synthesizability (SA), and binding affinity (pIC50) benchmarks, DrugGen-2 outperforms MolGPT and ChemGPT by 18-32% across multiple therapeutic areas, with particularly strong gains in oncology and CNS where disease context most influences target behavior.
⚙️ 方法：在 pre-trained GPT-2 上 fine-tune, 用两步策略: (1) supervised fine-tuning on 已批准药物 + 疾病本体 + 靶点蛋白序列的三元组数据集; (2) RLHF with reward = QED (类药性) + SA (可合成性) + pIC50 (结合亲和力) 加权; 条件输入把 disease ontology embedding 跟 target protein sequence embedding 拼接后送入 decoder.
⚖️ 取舍：DrugGen-2 的'disease-aware'本质是给 GPT-2 加了 disease ontology embedding 作为额外条件, 这种'条件化扩展'在罕见病 / 跨疾病机制重叠(例如某些自身免疫病)上的泛化能力没测; RLHF reward 三件套 (QED+SA+pIC50) 是经典指标, 但忽略了毒性 + 代谢稳定性 + 实际临床转化率这些药企真正关心的指标; 此外, GPT-2 backbone 对长 SMILES 串 (复杂分子) 的 tokenization 效率低, 长链生成质量衰减.
📊 效果：在 QED / SA / pIC50 三个标准 benchmark 上比 MolGPT / ChemGPT 提升 18-32%; 在肿瘤 + CNS 两个治疗领域提升最显著(这两个领域疾病上下文对靶点行为影响最大); 已开源 (PyTorch).
🏢 团队：['Ali Motahharynia', 'Mohammadreza Ghaffarzadeh-Esfahani', 'Mahsa Sheikholeslami', 'Navid Mazrouei', 'Matin Irajpour', 'Yousof Gheisari']

Linear Attention Architectures: Mechanisms, Trade-offs, and Cross-Layer Routing

想象一下: 你想让 LLM 处理超长上下文(几十万 token), 但传统 softmax attention 的计算量是 O(n²), 上下文一长就崩. 现在有一类'线性 attention'(DeltaNet / Gated DeltaNet / Kimi Delta Attention / Gated DeltaNet-2)号称能跑 O(n), 但它们各自有什么不同, 哪个更适合哪个场景, 业界一直没有统一对照. 这篇论文是第一个把 4 种主流线性 attention 用统一'循环记忆'符号写出来, 在 350M 参数规模上做公平对比, 还提出 'cross-layer routing' 让不同层用不同 attention 机制.

📖 专业版问题讲解 (展开)
We present a comparative study of softmax attention and four recent recurrent linear-attention architectures: DeltaNet, Gated DeltaNet, Kimi Delta Attention, and Gated DeltaNet-2. We express these mechanisms in a common recurrent-memory notation, making explicit how they differ in expressivity, memory decay, erase and write control, training throughput, and implementation complexity. Our 350M-parameter controlled comparison shows that no single linear-attention variant dominates, motivating cross-layer routing that dynamically selects mechanisms per layer. We achieve 7-12% loss reduction on long-context retrieval and code completion vs best single-mechanism baselines.
⚙️ 方法：统一'循环记忆'符号: 把所有 4 种线性 attention 表达为 (memory state, decay, erase, write, read) 5 元组的特定实例; 350M 参数对照实验 (同样数据 / 同样训练步数 / 同样硬件) 在 retrieval / 代码补全 / 长文摘要 3 类任务上比较; cross-layer routing 用轻量路由器让不同层动态选 attention 机制.
⚖️ 取舍：论文的核心贡献是'对比 + 统一符号', 但 cross-layer routing 引入了新超参 (路由器学习率 + 路由选择温度), 实际部署需要重新调优; 350M 参数规模偏小, 真实生产模型 (7B+) 的 trade-off 曲线是否一致未知; '循环记忆'视角虽然优雅, 但没有讨论'记忆衰减率'的可学习性, 留给未来工作.
📊 效果：350M 参数对照实验: 没有单一线性 attention 变体在所有任务上最优; cross-layer routing 在长上下文 retrieval 和代码补全上比最佳单一机制 baseline 减少 7-12% loss; 训练吞吐比 softmax 高 1.8-3.2x.
🏢 团队：['Tommaso Cerruti', 'Tim Rieder', 'George Rowlands', 'Lingfeng Jin', 'Imanol Schlag']

Jet-Long: Efficient Long-Context Extension with Dynamic Bifocal RoPE

想象一下: 你有个 8K 上下文训出来的开源模型, 现在要直接部署到 RAG / 仓库级编码 / Agent 这种 80K+ 上下文场景. 传统做法是先做一个'长上下文 fine-tune', 但成本极高. 现有零样本扩展方法(不 fine-tune)只能选一个固定 rescaling 因子, 太激进短上下文精度丢, 太保守长上下文搞不定. Jet-Long 提出 'Dynamic Bifocal RoPE', 让模型根据上下文长度自动切换'近距离细节'和'远距离位置'两套编码, 不用 fine-tune 就能在 8K→80K 上保持精度.

📖 专业版问题讲解 (展开)
Jet-Long is a tuning-free zero-shot method for long-context extension based on Dynamic Bifocal RoPE. Instead of a single fixed rescaling factor, it uses two complementary frequency regimes: a near-focus regime preserving short-context fidelity, and a far-focus regime supporting long-context positional generalization. A length-aware switch dynamically selects the regime based on input length. Across LLaMA-3 / Qwen2.5 / Mistral families at 8K→128K extension, Jet-Long achieves 95-98% of the perplexity of full long-context fine-tuning with zero additional training, outperforming YaRN and LongRoPE by 1.5-3.2 perplexity points on retrieval and code tasks.
⚙️ 方法：Dynamic Bifocal RoPE 在 rotary position embedding 中引入两套频率 regime: near-focus (保留原始 RoPE 频率, 维持短上下文精度) + far-focus (外推的更长周期频率, 支撑长上下文泛化); length-aware switch 根据当前输入长度动态选 regime; 全程 zero-shot, 不需要 fine-tune.
⚖️ 取舍：Dynamic Bifocal RoPE 的两套频率 regime 本质是手动设计, length-aware switch 的切换阈值是超参, 不同模型家族(LLaMA-3 / Qwen2.5 / Mistral)的最佳阈值不同, 实际部署要逐模型调; 'near-focus' regime 在 32K-64K 区间跟 far-focus 切换有边界抖动; 论文没测 Agent / RAG 真实业务场景, 只测了 perplexity 和 retrieval, 业务级精度可能仍有 gap.
📊 效果：8K→128K 零样本扩展上达到 full fine-tune 的 95-98% perplexity; 在 retrieval 和 code 任务上比 YaRN / LongRoPE 优 1.5-3.2 ppl; 不需要任何额外训练; 已开源 (PyTorch).
🏢 团队：['Haozhan Tang', 'Zerui Wang', 'Yuxian Gu', 'Song Han', 'Han Cai']

OpenCoF: Learning to Reason Through Video Generation

想象一下: 现在 LLM 推理靠 'Chain of Thought (CoT)'——一步一步把思考写出来. 但有些推理任务更适合'用画面表达'——比如物理预测(小球从斜面滑下会撞到哪)、轨迹推理(给一张地图, 推演一段旅程). 这篇 OpenCoF 提出 'Chain of Frame (CoF)'——让模型通过生成'时间相连的视频帧'来做推理. 配套 17K 数据集 OpenCoF-17K + 专用推理视频生成模型 + 多任务 benchmark.

📖 专业版问题讲解 (展开)
OpenCoF is a framework for Chain-of-Frame (CoF) reasoning, where reasoning unfolds through temporally connected video frames rather than text tokens. We release OpenCoF-17K, a 17K-sample reasoning video dataset, and OpenCoF-Gen, a reasoning video generation model trained with CoF-aware objective. We establish CoF-Bench covering physics prediction, spatial reasoning, and trajectory forecasting. OpenCoF-Gen outperforms general video generators by 18% on physics prediction and 23% on spatial reasoning, while being competitive on standard video quality (FVD).
⚙️ 方法：三件套: (1) OpenCoF-17K 数据集 (17K 视频 + 推理标签, 覆盖物理 / 空间 / 轨迹); (2) OpenCoF-Gen 模型 (在 Sora 类架构上加 CoF-aware 训练目标, 让模型学会'生成过程就是推理过程'); (3) CoF-Bench 评测集 + 评测协议 (物理预测 / 空间推理 / 轨迹预测 3 类).
⚖️ 取舍：Chain-of-Frame 推理的代价是'视频生成本身的高成本'——每做一次推理都要生成多帧视频, 推理延迟比 CoT 高一个数量级; OpenCoF-17K 数据集 17K 规模对视频模型而言偏小, 模型泛化到未见过的物理现象 / 空间场景的能力未充分验证; '生成过程 = 推理过程' 的可解释性优势在 CoT 已经能做的纯逻辑任务上不显著.
📊 效果：在物理预测上比通用视频生成模型优 18%, 在空间推理上优 23%; 标准视频质量 (FVD) 与 SOTA 持平; 17K 样本数据集 + CoF-Bench 是该方向第一个系统资源.
🏢 团队：['Xinyan Chen', 'Ziyu Guo', 'Renrui Zhang', 'Dongzhi Jiang', 'Hongsheng Li']
