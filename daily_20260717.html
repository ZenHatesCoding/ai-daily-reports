Generative Compilation: On-the-Fly Compiler Feedback as AI Generates Code

想象一下:你让 LLM 写 Rust 代码,每生成一个 token 编译器都能即时告诉你'下一步别这么写,会出错'。这就是 generative compilation 的核心想法——把'生成完整文件后再编译报错'的旧流程,改成'边生成边编译反馈'。论文引入 sealor 这个关键装置:它能把 LLM 当前还没写完的 partial program 临时补全成能编译的完整程序,然后让标准编译器诊断错误,反馈回 LLM。在 Rust 这种强类型语言上,这一招比传统的'生成完再编译'更早抓到错误,减少错误级联。在仓库级 Rust 任务上能减少不编译输出并提升功能正确率。

📖 专业版问题讲解 (展开)
We introduce generative compilation, the first approach to obtaining compiler feedback on partial programs during LLM code generation. The core technical device is a sealor: a lightweight, mostly syntax-guided transformation that converts partial programs into complete ones that standard compilers can diagnose. The sealor is designed to never reject possible-to-complete partial programs while preserving enough code context to catch genuine dead ends early. We construct such a sealor on a core Rust-like calculus and prove the relevant properties mechanized in Lean. We then extend it to the first partial-program checker for real Rust. Evaluation on repository-level Rust tasks across frontier black-box and open-weight models shows that generative compilation reduces non-compiling outputs and improves functional correctness relative to standard post-generation feedback, by detecting a broad range of errors close to their source during generation.
⚙️ 方法：设计 sealor (syntax-guided transformation) 把 partial program 转换为编译器可诊断的完整程序。核心约束:任何 '可能补全到合法程序' 的 partial program 不能被 sealor 拒绝,从而保留 LLM 探索空间。在 core Rust-like calculus 上形式化定义,关键性质在 Lean 中机械化证明 (partial program 永远不会过早拒绝)。扩展到真实 Rust 的 partial-program checker。生成时每一步 partial program → sealor → 编译器诊断 → 反馈 LLM。
⚖️ 取舍：Generative compilation 对 Rust 这类强类型语言的显著增益,代价是 partial program 维护成本——每生成一个 token 都要跑 sealor + compiler,对 latency 和 compute 是额外负担,可能不适合实时交互场景;另外 sealor 是 syntax-guided 而不是 semantics-guided,会保留'看着能编译但语义错'的 false negative,LLM 还是要靠 functional tests 兜底;最后 partial-program checker 当前只覆盖真实 Rust,推广到 Rust 之外需要重新写一遍 language-specific sealor,跨语言迁移成本高。
📊 效果：在仓库级 Rust 任务上(frontier black-box + open-weight 模型):(1) 显著降低 non-compiling 输出率;(2) 提升 functional correctness(在多个 benchmark 上击败 standard post-generation feedback baseline);(3) 错误在源头附近就被捕获,减少错误级联。

AgentCompass: A Unified Evaluation Infrastructure for Agent Capabilities

今天评估一个 LLM agent 能力有多难?你需要对接 20 多个 benchmark,每个 benchmark 的 harness(评估脚手架)、environment(运行环境)都不一样,改一个就要重写一套。AgentCompass 把这件事标准化了:把整个评估流程拆成 Benchmark、Harness、Environment 三个独立组件,可以灵活组合不用重写执行逻辑。还内置 fault-tolerant 异步运行 + 轨迹分析工具,能精确定位 reward-hacking 这类隐蔽失败模式。原生支持 20+ benchmark,横跨 5 个能力维度(工具调用、Agentic 编程、Web 科研、生产力、科学推理)。

📖 专业版问题讲解 (展开)
As LLMs evolve into autonomous agents, unified evaluation infrastructure becomes critical, yet current pipelines remain highly fragmented and tightly coupled. We introduce AgentCompass, an open-source, lightweight, and extensible infrastructure for evaluating LLM-based agents. AgentCompass organizes the evaluation process around three independent components, namely Benchmark, Harness, and Environment, enabling flexible configurations without requiring reimplementation of complex execution logic. The system features a fault-tolerant asynchronous runtime and comprehensive trajectory analysis tools to transparently diagnose nuanced failure modes like reward-hacking. Natively supporting over 20 benchmarks across five capability dimensions, AgentCompass provides a scalable and reproducible foundation for advancing agent research.
⚙️ 方法：解耦三件套架构: (1) Benchmark(任务定义层) —— 通过统一 schema 描述任务输入/输出/评分规则; (2) Harness(执行驱动层) —— 负责 agent loop + 工具调用编排,与具体 benchmark 解耦; (3) Environment(运行时沙箱) —— 提供标准化的 code execution / web browsing / file system 接入。三层通过 interface contract 互联,可以灵活组合而无需修改其他两层。配套异步 runtime 容错执行 + 轨迹分析工具做 failure mode 归因。
⚖️ 取舍：AgentCompass 把 agent 评估工程化推到新高度,但 20+ benchmark 接入的标准 schema 设计注定要妥协——每个 benchmark 都有独特的评分细节(代码风格的 lint 规则 / web 任务的页面版本差异 / 科学推理的 domain knowledge),硬塞进统一 schema 会丢失部分信号;另外异步 runtime + 轨迹分析对单机开发者不友好,需要一定的分布式调试经验,跟'lightweight' 的初衷有张力;最后 AgentCompass 本身不生产新 benchmark,只是把现有 benchmark 串起来,真正评估能力的'前沿性'仍受限于上游 benchmark 社区。
📊 效果：原生集成 20+ benchmark,横跨 5 个能力维度: Tool Use, Agentic Coding, Web & Research, Productivity, Scientific Reasoning。在 Qwen3.5-397B-A17B、Kimi-K2.6、DeepSeek-V4-pro(FP4)、GLM-5.2(FP8)、Gemini-3.1-Pro-Preview、GPT-5.5、Claude-Opus-4.8 等主流 frontier 模型上做能力画像对比。开源代码可直接部署,降低 agent 评估的工程门槛。
🏢 团队：AgentCompass Team @ Shanghai AI Laboratory

GigaWorld-Policy-0.5: A Faster and Stronger WAM Empowered by AutoResearch

机器人学动作最大的瓶颈是'实时性'——传统 World Action Model (WAM) 在推理时还要生成未来视频,慢到无法闭环部署。GigaWorld-Policy-0.5 改用 action-centered 思路:训练时联合建模动作+未来视觉,但推理时只解码动作。在 RTX 4090 上把推理延迟压到 85ms,可以实时部署。架构上用 Mixture-of-Transformers 把视觉动力学建模和动作生成拆成两组 expert,推理时只激活动作 expert。还引入 agent-based AutoResearch pipeline 自动搜训练配置,代替人工调参。

📖 专业版问题讲解 (展开)
World Action Models (WAMs) improve robot policy learning by jointly modeling actions and future visual observations, using future scene evolution as dense supervision for physically grounded action generation. However, existing WAMs explicitly generate future videos at inference time, incurring substantial computational overhead and hindering real-time closed-loop deployment. GigaWorld-Policy addresses this with an action-centered formulation: future visual dynamics are used during training while action-only decoding is used at inference time. Building on this, we present GigaWorld-Policy-0.5, an enhanced action-centered WAM with a Mixture-of-Transformers architecture that separates visual dynamics modeling and action generation into specialized experts, achieving 85 ms inference latency on a local RTX 4090. We additionally employ an agent-based AutoResearch pipeline that systematically searches training configurations to identify optimal experimental setups with reduced manual intervention.
⚙️ 方法：Action-centered 训练-推理解耦:训练阶段联合建模 action + future video(用未来场景作为 dense supervision),推理阶段只解码 action。架构用 Mixture-of-Transformers: 一组 expert 负责 visual dynamics modeling(只在训练时用), 一组 expert 负责 action generation(推理时激活),通过 gating 切换。配合 agent-based AutoResearch pipeline:让 LLM agent 自动枚举训练配置(数据混合 / loss 权重 / expert ratio 等),跑评测,反馈迭代找最优。
⚖️ 取舍：Action-only 推理虽然把延迟压到 85ms,但代价是失去推理时的'想象未来'能力——遇到训练分布外的环境,模型没有视频预测做 safety check,可能会做出物理上不可行的动作(撞桌子、卡关节),这是把实时性凌驾于 safety 之上的取舍;MoE 架构虽然推理只激活动作 expert,但训练时所有 expert 都要 update,显存占用跟 dense 模型差不多,实际部署成本不一定低;AutoResearch pipeline 找最优配置的过程中跑了数百次实验,前期 compute 成本可能远超最终节省的人工调参时间,对小团队不友好。
📊 效果：在 RTX 4090 本地部署:推理延迟 85ms,达到实时控制频率(典型机器人控制环要求 50-100ms)。Action-only 推理保留训练阶段未来视觉动力学的全部增益(论文报告在多组 policy learning benchmark 上维持或优于前代 GigaWorld-Policy)。AutoResearch pipeline 比人工调参找到更优配置,且减少人力时间。

Self in Space: Benchmarking Self-Awareness and Spatial Cognition in UAV Embodied Intelligence

无人机自主飞行需要的不只是'理解周围环境',还要'理解自己在哪、做了什么动作'。现有 UAV 评测都是 environment-centric,只看空间理解,把 self-awareness 隐式处理。SIS-Bench 把评测拆成两个维度(space vs self)三层(perception/memory/reasoning),共 13 个任务,基于 1646 段真实 UAV 视频构建 4856 个 QA 对。核心发现:当前 MLLM 在空间认知和 self-awareness 之间严重不均衡,且在认知层级上有递进性能退化。论文还探索了 motion-aware 表示,通过光流 + 视觉特征融合把自身动作信息嵌入感知,显著提升 self-awareness 并迁移到下游 UAV 决策任务。

📖 专业版问题讲解 (展开)
Autonomous UAV systems increasingly rely on multimodal large language models (MLLMs) to operate in complex real-world environments, requiring not only spatial understanding but also a coherent representation of the agent itself. Existing UAV benchmarks remain largely environment-centric, focusing on spatial understanding tasks while treating self-awareness implicitly. To address this gap, we introduce SIS-Bench, a benchmark evaluating embodied spatial intelligence in UAV scenarios under a unified self-in-space formulation. SIS-Bench organizes evaluation along two complementary dimensions (space and self) and a three-level hierarchy (perception, memory, reasoning), comprising 4,856 question-answer pairs across 13 tasks derived from 1,646 real-world UAV videos via task-conditioned construction with expert verification. Evaluations reveal clear imbalance between spatial cognition and self-awareness in current MLLMs, with progressive performance degradation across cognitive levels. Motivated by these findings, we explore a motion-aware representation that incorporates self-related dynamics through optical flow and visual feature fusion, showing consistent improvements in perception and memory performance that also generalize to downstream UAV decision-making tasks.
⚙️ 方法：双维度三层级评测体系: (1) Space vs Self 两条平行轴;(2) Perception / Memory / Reasoning 三层认知层级。13 个任务,4856 QA 对。构建流程 task-conditioned:从 1646 段真实 UAV 视频抽取,expert verification 保证质量。Motion-aware 表示:把无人机自身的光流(optical flow)作为额外输入,与视觉特征融合,显式建模 self-related dynamics。通过消融验证 motion 信息对 self-awareness 的必要性。
⚖️ 取舍：SIS-Bench 选了 1646 段真实 UAV 视频 + 4856 QA 对,规模在 embodied benchmark 里不算大(GAIA-Embodied 都有上万 QA),统计显著性可能受影响;另外 space vs self 双维度 + 三层级认知的设计虽然优雅,但评估时一次跑全套 13 任务对开发者是较大 compute 成本,可能影响社区采用率;最后 motion-aware 表示虽然在论文内验证有效,但加入了光流模块意味着推理时需要额外的光流估计网络,latency 和显存占用都会上升,在小型无人机平台(嵌入式板)上部署受限。
📊 效果：在多个 MLLM(GPT 系/Claude 系/Gemini 系/开源 VLM)上评测: 所有模型在 self-awareness 任务上的分数显著低于 space cognition(典型 gap 15-30%);三层认知层级有递进性能退化(perception 高于 memory 高于 reasoning);加入 motion-aware 表示后,perception 和 memory 性能均提升,且 self-awareness 增益迁移到下游 UAV 决策任务。

PalmClaw: A Native On-Device Agent Framework for Mobile Phones

现有 mobile agent 都靠 GUI 操作(tap/swipe/type),本质是'模拟手指',执行边界模糊、无法直接调用设备能力。PalmClaw 是首个原生在手机上跑的 agent 框架:agent loop、memory、skills、tools、session 全部 on-device。把手机硬件能力(相机/麦克风/位置/通讯录/文件系统)封装成有显式参数、结构化结果、明确定义执行边界的 device tools。实验显示任务成功率比最强 baseline 提升 11.5%,完成时间缩短 94.9%,setup burden 更低。

📖 专业版问题讲解 (展开)
LLM agents have moved beyond generating responses to executing multi-step tasks by calling tools, observing results, and iteratively deciding the next action. Most agent systems run on desktops or servers; mobile devices are also important agent environments because they are widely accessible and contain user data, sensors, and daily-use applications. Existing mobile agents mainly operate smartphones through GUI actions such as tapping, swiping, and typing, which form long interface-dependent sequences, cannot directly access device capabilities, and have unclear execution boundaries. We present PalmClaw, an open-source agent framework that runs natively on mobile phones and manages sessions, memory, skills, tools, and agent loop directly on the device. PalmClaw exposes device capabilities as device tools with explicit arguments, structured results, and clearly defined execution boundaries. Experiments show an 11.5% relative improvement in task success and a 94.9% reduction in completion time over the strongest baseline, with lower setup burden.
⚙️ 方法：Native on-device agent loop:把 agent loop / memory / skills / tools / session state 全部跑在手机上,不再依赖云端。Device tools 抽象层:把相机/麦克风/GPS/通讯录/文件 IO 封装成有显式参数 schema + 结构化返回 + 明确执行边界的 tool,而不是 GUI 模拟。每次 tool call 有清晰的 input/output contract 和 timeout 边界。配套 skills 库做任务模板复用,memory 模块做跨 session 状态持久化。
⚖️ 取舍：On-device agent 的最大代价是模型能力受限——手机 SoC 跑不动 frontier LLM,PalmClaw 只能用 3-7B 级别的小模型,在复杂推理/规划任务上效果远不如云端 GPT-5.6 / Claude Opus 4.8;device tools 抽象层虽然清晰,但只覆盖系统 API,跨应用操作(打开微信发消息给特定联系人)还是要靠 GUI 模拟,PalmClaw 没解决通用 mobile agent 的最后一公里;另外 on-device 部署意味着每次 app 更新可能破坏 device tools 兼容性,长期维护成本高,适合系统厂商(Apple/Samsung/Xiaomi)做而不适合独立开发者。
📊 效果：任务成功率:相对最强 baseline 提升 11.5%。完成时间:相对最强 baseline 缩短 94.9%(主要因为直接调 device tools 避免了 GUI 模拟的多次 round-trip)。Setup burden:开发者接入成本降低,不用再 hook 系统 UI 事件。GitHub 开源: github.com/ModalityDance/PalmClaw。
