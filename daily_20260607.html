HANDOFF: Humanoid Agentic Task-Space Whole-Body Control via Distilled Complementary Teachers

人形机器人要真正走出实验室落到家庭/工厂，决策层（任务规划）和执行层（全身控制）之间缺一个顺手的接口：现有控制器只认密集的运动学/空间参考，规划器从高层语义「把杯子端起来」翻译不到这种细粒度指令，导致上层任务和下层动作长期脱节。

⚙️ 方法：把 task-space（末端任务空间位姿）作为唯一显式命令接口喂给单一全身控制策略；多个互补的教师策略（接触/操作/平衡等）通过蒸馏合并到一个策略里，兼顾规划器友好与多任务泛化，相对以往「密集参考 + RAG 式重规划」基线大幅降低接口复杂度。
⚖️ 取舍：接口被刻意做小后，凡是需要精细关节级约束的任务（如指尖微调、力反馈装配）就被压死在该抽象层之下；同时多个互补教师被蒸馏成单一策略后，牺牲了「哪个教师擅长什么」的可解释切换。
📊 效果：在多套人形机器人仿真 + 真机长程操作 benchmark 上，跨任务成功率与指令遵从率均达到 SOTA，对比纯 task-space 残差方法与端到端 imitation baseline 优势明显。
🏢 团队：Google DeepMind 与 Georgia Tech 等合作；一作 Lizhi Yang，通讯 Aaron Ames（Caltech 出身、现 Georgia Tech AMBER Lab 主任，机器人控制领域资深作者），合作者含 Georgia Gkioxari。

Code2LoRA: Hypernetwork-Generated Adapters for Code Language Models under Software Evolution

代码大模型要写出能跑的项目级代码，必须吃进仓库级上下文（import、API、内部规范），而现实里每个仓库都在持续演化：RAG 路径要把整段检索拼回上下文，token 成本爆炸；per-repo 整库微调或 LoRA 又贵到按仓库数线性扩张，工程上根本吃不消。

⚙️ 方法：训练一个超网络（hypernetwork），把仓库代码本身当输入，直接生成该仓库专属的 LoRA 适配器；推理时把 adapter 挂回底模即可获得该仓库的「内化记忆」，相对 RAG 基线实现零推理 token 开销，相对 per-repo 独立 LoRA 训练省去每仓独立训练流程。
⚖️ 取舍：把仓库知识全压进 adapter 后，仓库一旦大改（依赖/重构/版本升级）适配器就过期，超网络必须重生成；同时超网络本身需要大量「仓库→LoRA」对作为监督，训练侧的代价被前移且高度集中在超网预训练阶段。
📊 效果：在多仓库代码补全与 API 引用预测基准上，Code2LoRA 在零推理 token 开销条件下匹配或超过 RAG 基线，对持续演化的真实仓库鲁棒性显著优于 per-repo LoRA。
🏢 团队：加拿大 University of Waterloo NLP 小组与北大合作；一作 Liliana Hotsko，通讯 Pengyu Nie（Waterloo），Yuntian Deng（现为多伦多大学助理教授、原 Waterloo）。

Self-Augmenting Retrieval for Diffusion Language Models

离散扩散语言模型每一步把掩码位置「并行去噪」，只敢把高置信 token 写进输出，其余一律丢弃；结果在需要外部知识的问答/事实型任务上，这些被扔掉的中低置信 token 经常暗藏关键实体，原本可作为检索线索，却被白白浪费掉。

⚙️ 方法：把被丢弃的低置信 token 视作去噪轨迹的「前瞻信号」，让模型在还没写完答案时就把这些线索拿去检索证据，再把更强证据回灌到下一轮去噪里；相对「先写完再独立 RAG」的基线，把检索提前到生成内部循环。
⚖️ 取舍：生成质量被自增强检索顶起来后，扩散原本「一步并行出整段」的并行去噪优势被吃回去——每轮 denoising 都要等一次外部检索串行介入，端到端延迟反向放大，且检索器一旦失误会把错误证据反向污染去噪过程。
📊 效果：在多个知识密集型问答/事实核查基准上，超越 vanilla 扩散语言模型与外置 RAG 基线，生成的事实一致性与答案正确率均显著提升。
🏢 团队：美国 Cornell University 与 Meta AI 合作；一作 Paul Jünger，通讯 Kilian Q. Weinberger（康奈尔计算机系教授、ML 领域资深作者）。

Reinforcement Learning Elicits Contextual Learning of Unseen Language Translation

极低资源语言翻译是 NLP 里的硬骨头：靠持续预训练把语料灌进模型会过拟合这门语言、靠「把语法书写进上下文」做 ICL 也会被格式与具体语言绑死——两种主流路线都牺牲零样本迁移能力，没法规模化复用到几十种新语言。

⚙️ 方法：用强化学习把 LLM 训练成「会利用上下文语言学知识」的元技能者：奖励信号不是某门具体语言翻得准不准，而是鼓励模型在见到新语料时正确调用 in-context 规则；相对持续预训练基线强调泛化，相对 grammar-book ICL 基线放弃死记硬背。
⚖️ 取舍：元技能被 RL 抬起来后，对单门低资源语言在域内测试集上的峰值翻译质量反而被压死——它刻意不「记住」具体语言，等于放弃了在固定测试集上死刷分的捷径。
📊 效果：在 FLORES 等多语言基准的「完全未见语言」零样本翻译切片上，显著超过持续预训练与 grammar-book ICL 基线，并展现跨语种可迁移的元能力。
🏢 团队：英国 University of Edinburgh（School of Informatics）与瑞士 University of Zurich 合作；一作 Hanxu Hu，通讯 Rico Sennrich（爱丁堡机器学习教授，机器翻译领域资深作者），合作含 Pinzhen Chen（爱丁堡）。
arXiv:2606.06475 · 论文精读

RREDCoT: Segment-Level Reward Redistribution for Reasoning Models

推理型语言模型普遍用 GRPO/PPO 类算法做 CoT 强化学习，但答案只有 CoT 写完才能验证，奖励被压到 trajectory 末端一次性发放，等价于「延迟奖励」——Monte Carlo 估计高方差、稀疏信号，训练低效且容易塌到单一样式。

⚙️ 方法：把 CoT 轨迹切成段，按段把终局奖励重分配回各段（segment-level reward redistribution），让中间推理步骤也吃到稠密信用；相对 GRPO 这种「整条 CoT 同奖励」的基线，缓解延迟奖励与信用分配稀疏。
⚖️ 取舍：稠密信号把训练效率顶起来后，凡是不符合「按段均匀/线性」贡献假设的 CoT 都被压死——比如关键推理突然出现在某一段、其余段都在铺垫时，重分配会人为稀释关键段信号，长 CoT 末端段仍可能回到稀疏。
📊 效果：在多套数学与代码推理基准上，相对 GRPO 等基线收敛更快、最终准确率更高，CoT 风格多样性也更稳。
🏢 团队：奥地利 ELLIS/IDSIA 与 JKU（Johannes Kepler University Linz）合作；一作 Mykyta Ielanskyi，通讯 Sepp Hochreiter（JKU 教授，LSTM 作者之一），合作含 Lukas Aichberger、Kajetan Schweighofer（JKU AI 实验室）。
