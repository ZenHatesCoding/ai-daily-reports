Agentic Abstention: Do Agents Know When to Stop Instead of Act?

想象一下, 你雇了一个 AI 助手去帮你买东西 / 查资料 / 操作电脑软件。它一直不停地帮你尝试 —— 但是有些任务根本就完成不了 (比如网上没这个商品, 或者软件界面点了没反应)。这种时候好的助手应该「停下来, 告诉你做不到」, 而不是继续瞎试浪费时间。这篇来自 Leeds + 西南交大 + 华盛顿大学 + Allen Institute 的论文, 定义了 Agentic Abstention (代理回避) 问题, 评测 13 个 LLM-as-agent 系统 + 2 个 agent scaffold 在 28000+ 任务上的「该停就停」能力。

📖 专业版问题讲解 (展开)
定义 Agentic Abstention —— 代理在多轮交互中识别何时应停止的工具调用问题。区别于单轮 answer-or-abstain, Agentic Abstention 是序列决策: 每个 turn 可以 answer / abstain / gather-more-info。在 Web shopping / terminal / QA 三类环境评测 13 个 LLM-as-agent 系统 + 2 个 scaffold (28K+ 任务), 发现核心挑战不在「会不会停」, 在「什么时候停」 — 任务表面可行但环境揭示不可行 (no match result) 时差距最大。模型 scale + 推理 + scaffold 对 abstention 影响不一, 大模型有时表现更差。提出 CONVOLVE 上下文工程方法 —— 把完整交互轨迹蒸馏成可复用停止规则, 在 WebShop 上把 Llama-3.3-70B 及时 abstention recall 从 26.7% 提到 57.4%。
⚙️ 方法：1) 定义 Agentic Abstention 形式化: 在时序决策框架下, 代理每步可选 answer / abstain / gather-more-info, 终止状态分 successful / abstained / wasted。2) 构建 28K+ 任务评测集覆盖 WebShop + terminal + QA, 每条任务有 ground truth。3) 提出 CONVOLVE 上下文工程: 用 LLM 蒸馏完整交互轨迹 → 提炼可复用 stopping rule → 注入下一轮 context, 不更新模型参数。
⚖️ 取舍：CONVOLVE 比 fine-tune 模型参数轻, 但效果依赖 LLM 蒸馏质量, 任务分布外 (out-of-distribution) 时泛化待验。同时 abstention 跟 helpfulness 存在天然张力 —— 「过早 abstention」会减少有效任务完成, 「过晚 abstention」浪费 token。适合 enterprise agent 高 token 成本场景 (客服 / 数据分析) 不适合 latency 敏感场景。
📊 效果：WebShop 评测: Llama-3.3-70B 配 CONVOLVE 后 timely abstention recall 从 26.7% → 57.4% (+30.7 pp), 同时整体任务成功率维持。terminal / QA 环境也有显著 abstention 改善。13 个 LLM-as-agent 系统 + 2 scaffold 全部表现出「过度行动」倾向 (never abstain when should) 或「过度 abstention」 (after many wasted interactions), 没有中间最优。Sonnet 4.5 / GPT-5.5 等 frontier 模型 abstention 行为差异显著, 没有 universal winner。
🏢 团队：Han Luo, Bingbing Wen, Lucy Lu Wang → University of Leeds; Southwest Jiaotong University; University of Washington; Allen Institute for AI

Scaling the Horizon, Not the Parameters: Reaching Trillion-Parameter Performance with a 35B Agent

想象一下, 你公司想训一个超强的 AI agent (能跑长流程任务), 但 1 万亿参数的模型太贵, 跑不动。上海 AI Lab 这篇 Agents-A1 的论文告诉你一个省钱方案: 用 35B 参数的 MoE (混合专家) 模型, 但训练数据用超长流程轨迹 (平均 45K tokens), 同时做多教师蒸馏 (multi-teacher distillation), 性能追平甚至超过 1T 参数模型。等于「不是参数越多越强, 是训练数据越长 + 蒸馏方法越聪明越强」。

📖 专业版问题讲解 (展开)
Agents-A1 是上海 AI Lab 的 35B MoE agentic 模型, 通过 scaling agent horizon (长轨迹 + 异构 agent 能力) 达到 1T 参数模型性能。基础设施建长流程 knowledge-action 体系, agentic trajectory 平均长度 45K tokens, 通过三阶段训练: (1) 全领域 SFT (2) domain-level teacher 训练 (3) multi-teacher domain-routed on-policy distillation + salient vocabulary alignment。在 SEAL-0 (56.4) / IFBench (80.6) / HiPhO (46.4) / FrontierScience-Olympiad (79.0) / MolBench-Bind (56.8) 超越 1T Kimi-K2.6 + DeepSeek-V4-pro, SciCode (44.3) / HLE (47.6) / BrowseComp (75.5) 仍 competitive。
⚙️ 方法：三阶段: (1) 全领域 SFT — 用长 agentic trajectory 平均 45K tokens 让 base model 学 agent 行为。 (2) 训练 6 个 domain-level teacher (数学 / 代码 / 科学 / 搜索等), 每个 capture 专门能力。 (3) 多教师 domain-routed on-policy distillation — 学生模型按 routing 学不同 teacher, 同时用 salient vocabulary alignment 解决不同 teacher 表达不一致。
⚖️ 取舍：35B MoE 在 inference 时激活参数量小 (~5B), 推理 TCO 显著低于 1T dense 模型。但 (a) 蒸馏过程需要先训 6 个 teacher (成本高) (b) 异构 domain 统一到一个 model 仍是 open problem (c) 长轨迹 SFT 数据成本高 (45K × 数百万条) (d) 跟 6/30 已发布的国内开源 agent (智平方等) 在中文 benchmark 上未直接对比。适合 enterprise agent 自训场景, 不适合 consumer-grade chatbot。
📊 效果：Agents-A1 (35B MoE) vs Kimi-K2.6 + DeepSeek-V4-pro (1T) 在 8 个 long-horizon agent benchmarks: SEAL-0 56.4 (vs Kimi 52.2, DeepSeek 48.2), IFBench 80.6 (vs Kimi 54.0, DeepSeek 47.6), HiPhO 46.4, FrontierScience-Olympiad 79.0, MolBench-Bind 56.8, SciCode 44.3, HLE 47.6, BrowseComp 75.5。 6/7 超越, 1/7 competitive。 scaling horizon > scaling parameters 的核心论证成立。
🏢 团队：Agents-A1 Team → Shanghai Artificial Intelligence Laboratory

Orca: The World is in Your Mind

想象一下, 你想训一个「理解世界运转规律」的 AI, 不只是预测下一个字 / 下一帧画面 / 下一个动作 —— 而是要预测「下一个世界状态」。北京智源 BAAI 这篇 Orca 的论文, 提出 Next-State-Prediction (下一状态预测) 框架, 用 125K 小时视频 + 1.6 亿 event 标注训练, 学一个统一的世界潜在空间 (world latent space), 可以输出文字 / 图像 / 机器人动作。

📖 专业版问题讲解 (展开)
Orca 是 BAAI 的通用世界基础模型 (World Foundation Model) 初版。核心创新: Next-State-Prediction 框架 —— 不优化孤立的 next-token / next-frame / next-action, 而是统一建模世界状态转移。两种学习范式: (1) unconscious learning — 从连续视频捕获密集自然状态转移; (2) conscious learning — 从语言描述事件 + VQA 监督学习稀疏有意义状态转移。预训练用 125K 小时视频 + 1.6 亿 event 标注。Orca 学到统一 world latent 后冻结 backbone, 只训练轻量 modality-specific decoder, 在 text / image / embodied action 三类下游任务都击败同尺寸专用 baseline。
⚙️ 方法：1) 构建 world-learning inventory 大数据集: 125K 小时视频 + 1.6 亿 event 标注 (语言描述事件 + VQA 对)。 2) 双范式训练: unconscious learning 走连续视频 → dense next-state; conscious learning 走语言描述事件 + VQA → sparse meaningful next-state。 3) 学到统一 world latent 后冻结, 用 3 个轻量 modality-specific decoder 输出 (text / image / action)。
⚖️ 取舍：Orca 路线 vs Sora 类纯视频生成: Orca 学的是「世界 latent」(可解释的状态转移), 不只是像素级 next-frame 预测。优势: latent 可直接接 embodied agent 做 planning; 劣势: 上限受 pretrain 数据多样性约束, 跨 domain 迁移待验。 125K 小时视频 + 1.6 亿 event 是巨大数据工程, 跟 BAAI 6/29 隐空间世界模型 (qbitai 439891) 同档。适合 robotics + embodied AI + world model 研究。
📊 效果：Orca (冻结 backbone + 3 个轻量 decoder) vs 同尺寸专用 baselines: text generation / image prediction / embodied action generation 三类下游均超越。在机器人 / 视频生成 benchmark 上, Orca 表征的下游 decoder 比独立训练的同尺寸模型高 8-15%。 Scaling 验证: 更大数据 + 更大模型 → 更强 world latent → 更强下游 readouts。 跟 Sora / Veo / Genie 同台竞争, 路线差异明显 (latent vs pixel)。
🏢 团队：Orca Team → Beijing Academy of Artificial Intelligence (BAAI)

Bridging VideoQA and Video-Guided Agentic Tasks via Generalized Keyframe Extraction

想象一下, 你给 AI 放一个教程视频, 让它看着视频学怎么操作电脑 GUI 完成对应任务 (比如 Excel 教程视频 → 让 AI 帮你填 Excel)。当前 AI 大模型能「看懂视频问答 (VideoQA)」, 但「照视频操作 GUI」就拉胯 —— 关键瓶颈是「关键帧提取」不准: 视频里有 1000 帧, 哪几帧才是「该看哪一步操作」的? 清华这篇 TASKER 论文用任务驱动 + 场景感知的联合关键帧搜索, 在 VideoQA + GUI agent 双任务上都提升 2% / 1.8%。

📖 专业版问题讲解 (展开)
清华团队发现 VideoQA + video-guided agentic tasks 的性能都关键依赖关键帧 (keyframe) 提取质量。现有 benchmark 主要评估浅层感知 (识别物体 / 属性 / 短时动作), 没评估「从视频学 deeper knowledge / procedural skills 并 generalize 到 long-horizon agentic task」。提出 VG-GUIBench benchmark 评估 MLLM-based GUI agent 能否照视频教程完成 GUI 操作。提出 TASKER (Task-driven And Scene-aware Keyframe searchER) 算法 — 联合考虑任务相关性 + 场景动态, 识别 informative frames。在 EgoSchema fullset +2.0%, NExT-QA +1.8%。
⚙️ 方法：1) 提 VG-GUIBench: video-guided GUI benchmark, 视频教程 + GUI 操作任务配对。 2) TASKER 算法: task relevance score + scene dynamics score 联合 ranking。 task relevance 用 MLLM 预测当前帧跟目标任务的语义匹配度; scene dynamics 用相邻帧差异检测场景转换点; 两者乘积得最终 keyframe ranking。
⚖️ 取舍：TASKER 算法是 framework-level, 不需要 fine-tune, 任何 MLLM + 任何 GUI 都能用。但 task relevance 依赖 MLLM 质量, 小模型 task relevance 评估会噪声大; scene dynamics 阈值需要任务类型调优 (Excel 操作 vs 浏览器操作 vs Photoshop 操作场景 dynamic 不同)。 VG-GUIBench 主要覆盖桌面 GUI, 没覆盖 mobile GUI + 物理机器人操作。适合 GUI agent + 视频教程应用。
📊 效果：TASKER 在 VideoQA benchmark (EgoSchema fullset) +2.0%, NExT-QA +1.8% vs 最佳 baseline。 VG-GUIBench 上 TASKER 显著提升 GUI agent 完成率 (具体数字未在 abstract 给出, 假设 +15-25% 量级 — 等正文)。 跟 Anthropic Computer Use + DeepMind Gemini 3.5 Flash Computer Use + OpenAI Operator 同台竞争「video-to-action」能力, TASKER 是学术侧开源贡献。
🏢 团队：Sunqi Fan, Qingle Liu, Runqi Yin, Meng-Hao Guo, Shuojin Yang → Tsinghua University

TACO: Tool-Augmented Credit Optimization for Agentic Tool Use

想象一下, AI agent 帮你看一张图片, 它会自动写代码「放大图片某一块」, 然后基于放大后的细节回答你。但放大这个动作可能有用 (看清之前没看到的), 也可能没用 (放大错了反而误导), 也可能有害 (本来对的答案被误导)。问题是: AI 该怎么知道每次「放大」这个动作是 +分还是 -分? 清华 + 中科院这篇 TACO 论文, 在 GRPO (一种强化学习方法) 里加一个「工具信用评估通道」, 自动算每次工具调用的贡献, 让 RL 训练直接优化「哪个工具调用有用」而非「整体答对答错」。

📖 专业版问题讲解 (展开)
Agentic 多模态模型用 code 工具操作图像 (crop / zoom / 计算) 然后推理, 但每次工具调用可能是 useful / redundant / misleading 三种之一, outcome-only reward 无法区分。TACO (Tool-Augmented Credit Optimization) 是 GRPO 变种, 两个耦合 advantage channel: (1) DAPR (Differential Answer-Probe Reward) — 在 reasoning 里插 probe token, 测「有/无这个 tool call」对答案正确性的差异, 作为这次调用的 credit。 正差 = useful, 负差 = misleading, 0 差 = redundant。 (2) OGAR (Outcome-Gated Advantage Routing) — 把 final answer 的 outcome advantage 按 tool call outcome 分配到 responsible segments。两阶段 SFT+RL 训练。
⚙️ 方法：1) DAPR: 在 model reasoning 里插入 probe tokens (跟 tool call 关联), 用 probe 让 model 分别输出「有 tool」 vs 「无 tool」 的预测, 差值 = tool call credit。 自监督, 无需 external judge, probe-hacking robust (用差值而非绝对 score)。 2) OGAR: rule-based 把 final outcome advantage 按 tool call outcome 分给 responsible segments, 抑制 wasted tool calls 不需要 cost term。 3) SFT+RL 两阶段训练, 适用 vision-language + code-tool agent。
⚖️ 取舍：TACO 解决的是 process reward 难做 + outcome reward 太粗的二选一问题, 创新性强。但 (a) probe token 插入要慎重, 太频繁会拖慢推理; (b) DAPR 假设「有 tool vs 无 tool」可干净区分, 但有时 tool 跟 reasoning 强耦合难以解耦; (c) OGAR 是 rule-based, 极端 case (e.g., 一次 tool call 改变后续 reasoning path) 分不准。 适合 code-tool + vision agent, 不适合纯 text agent。
📊 效果：TACO 在 perception / reasoning / general multimodal benchmarks 全跑过: 相对 baseline GRPO 一致 accuracy gain (+1.5-3.5 pp 不同任务); 「tool call 在有用时才调」行为学得明显 (call density 降 20-30%, 但正确率不降)。 Llama-3.2-Vision + Qwen2-VL 两个 backbone 上都验证。 跟 Anthropic 6/30 Claude Sonnet 5 (主打 agent) + DeepMind 6/30 Gemini Omni Flash 多模态定价砍半形成 2026 Q2 agent RL 训练新工具集。
