WorldDirector: 用 LLM 当「3D 导演」让视频生成跨镜头保持物体一致

想象你拍一部连续剧, 几十个镜头里同一个角色不能「换脸」, 同辆车不能突然变颜色。AI 生成视频最容易「失忆」 — 一旦镜头移开再回来, 物体就变了。WorldDirector 的思路是让一个 LLM 先当「3D 导演」, 把每个镜头里 3D 物体怎么动、相机怎么转先规划好, 再让视频模型照着规划合成画面。这样镜头出去再回来, 物体还是同一辆红色的车、还是同一个穿红衣的女人。

📖 专业版问题讲解 (展开)
WorldDirector 由 HKUST + Ant Group + Zhejiang University + CUHK 联合提出, 解决 video world model 中「跨镜头动态物体记忆丢失」的根本问题。现有的 video world model 把物理动态和像素渲染混在一起, 又依赖连续视觉观察维持运动, 一旦物体移出视野再回来就「换脸」。WorldDirector 显式解耦 3D semantic motion orchestration 与 latent video synthesis: 用 LLM 先 orchestrate 3D trajectories + camera movements 生成 control signal, 再用这个 control signal 指导 video diffusion 生成。
⚙️ 方法：Two-stage framework: (1) LLM-based 3D Trajectory Orchestrator 接收文本 prompt + reference frames, 输出每个动态物体的 3D trajectory 和 camera path; (2) Trajectory-conditioned Video Diffusion 把 3D trajectory 作为 control signal 生成视频, 保持物体 appearance 在跨镜头一致性
⚖️ 取舍：优势: 第一个 explicit 解耦 3D motion + pixel render 的 world model 架构, 把 LLM 重新定位为 planner 而非 generator; 限制: 需要 3D trajectory ground truth 作为训练信号, 真实视频里获取成本高; LLM planner 增加 inference latency, 不适合实时视频应用; 多物体协调 (interaction) 还没完全解, 物体间碰撞物理还没在所有场景验证
📊 效果：在长时序 world simulation + 自由视角探索 benchmark 上, 维持 dynamic object memory 跨镜头稳定性; 同时支持复杂多物体运动、镜头遮挡后重现; 实验在 HKUST + Ant Group 内部 GPU 集群完成
🏢 团队：Wang, Hanlin, Ouyang, Hao, Wang, Qiuyu, Wang, Wen, Bai, Qingyan, Cheng, Ka Leong, Yu, Yue, Li, Yixuan, Meng, Yihao, Liu, Zichen, Zeng, Yanhong, Shen, Yujun, Chen, Qifeng → HKUST (Hong Kong University of Science and Technology, 香港科技大学) + Ant Group (蚂蚁集团) + Zhejiang University (浙江大学) + CUHK (Chinese University of Hong Kong, 香港中文大学)

Program-as-Weights: 用「程序当权重」把模糊任务编译成可执行神经网络

想象你让 AI 「写一个函数, 把重要的日志行挑出来」, 这个规则没法用代码精确写出来, 因为「重要」很模糊。现在大家直接调 GPT 大模型 API 来干这事, 但每次都付钱 + 不保证每次相同 + 一旦 GPT 升级行为就变。本文说: 试一次, 让大模型把这个模糊函数「编译」成一个本地能跑的小神经网络「权重文件」, 后续每次调用都读这个小文件, 又快又便宜还稳定。

📖 专业版问题讲解 (展开)
Program-as-Weights (PAW) 由 University of Waterloo + Cornell + Harvard 联合提出, 提出 fuzzy-function programming 新范式: 把「自然语言描述的模糊函数」编译成本地可执行的 compact 神经网络 artifact (parameter-efficient adapter), 通过在 FuzzyBench (10M 样本基准) 训练一个 4B 编译器实现。0.6B Qwen3 interpreter 执行 PAW 输出可直接调用, 匹配 32B Qwen3 直接 prompt 的性能, 但推理内存只用 1/50, 在 MacBook M3 跑 30 tokens/s。
⚙️ 方法：Three-step pipeline: (1) natural language function spec → (2) Neural compiler (PAW, 4B) 把 spec + 训练数据编译成 compact adapter weights → (3) Frozen interpreter (0.6B Qwen3) loaded with adapter, locally executes function offline. FuzzyBench 10M-example dataset 提供训练语料
⚖️ 取舍：优势: 第一次把 LLM 从 per-input solver 重新定位为 tool-builder, 一次编译多次复用; 限制: PAW 编译需要 4B model + fine-tune, 编译成本只有「一次」但首次 setup 仍需 GPU; FuzzyBench benchmark 任务覆盖有限 (主要是文本 pattern matching), 视觉/多模态模糊函数还没验证; interpreter 必须冻结, 升级 interpreter 行为可能变
📊 效果：Performance 匹配 32B Qwen3 direct prompting (在 FuzzyBench 基准), 但 inference memory 只用 1/50; 在 MacBook M3 上跑到 30 tokens/s (CPU 也能本地推理); parameter-efficient adapter reuse across multiple function definitions
🏢 团队：Zhang, Wentao, Hotsko, Liliana, Kim, Woojeong, Nie, Pengyu, Shieber, Stuart, Deng, Yuntian → University of Waterloo (滑铁卢大学) + Cornell University (康奈尔大学) + Harvard University (哈佛大学)

OrbitQuant: 不用重新训练就让 diffusion transformer 把比特压到 4-bit

想象 Sora 这种视频生成模型本来跑一次要 80GB 显存, 你只有 16GB 显卡, 玩不起。本文给了一个「不用重新训练」的瘦身方法 OrbitQuant — 把模型权重压到 4-bit 但不让画质掉。具体做法是「基于 orbit」地旋转权重让它们的分布更适合量化, 对 image 和 video diffusion 都行, 还不用 calibration data。

📖 专业版问题讲解 (展开)
OrbitQuant 由 Cantina Labs + USC + UIUC 联合提出, 解决 diffusion transformer (DiT) post-training quantization 难题: 现有 PTQ 方法在低 bit (4-bit) 下质量掉太多, 需要 calibration data 又耗时。OrbitQuant 提出 Orbit, 一种 rotation-based data-free quantization scheme, 对 weight 在 orbit 子空间上做 rotation + 量化, 同时支持 image (Stable Diffusion 3) 和 video (CogVideoX / Wan) diffusion transformer。
⚙️ 方法：Orbit-based rotation + quant: (1) 对 weight matrix 在 orbit 子空间做 rotation, 重新对齐 weight distribution 适配 quantization grid; (2) data-free optimization, 不需要 calibration dataset; (3) joint image + video DiT compatibility, 通过 weight-only rotation 保持 attention pattern
⚖️ 取舍：优势: data-free quantization, 不需要校准数据集, 直接适配 production diffusion models; 限制: activation 仍 4-bit 极限, 进一步压缩 (2-bit) 质量掉; orbit rotation 增加推理时 complexity 一点点, 但内存省 4×; 对 model architecture 变化 (新 attention) 适配需要重新设计 orbit basis
📊 效果：W4A4 quantization (weight 4-bit, activation 4-bit) 下, 图像 FID / 视频 FVD 都接近 full precision baseline; 同时支持 image (SD3) 和 video (CogVideoX) DiT; 无 calibration data, quantization 几分钟完成
🏢 团队：Lee, Donghyun, Chavan, Jitesh, Nguyen, Duy, Huang, Sam, Jiang, Liming, Panda, Priyadarshini, Mertens, Timo, Shukla, Saurabh → Cantina Labs + University of Southern California (南加州大学) + University of Illinois Urbana-Champaign (UIUC)

EvoPolicyGym: 测 AI agent 是否真能「多次尝试让代码变好」

想象让 AI 帮你修一段代码, 它改了一版, 你给反馈「这里不对」, 它再改一版, 再改一版。最终版本好不好, 不是关键 — 关键是它有没有真的「改得越来越对」, 而不是「瞎试」。以前的评测只看最后一次跑分, EvoPolicyGym 第一次专门看「AI 是否真的从反馈中学到了东西」, 而不是堆 retries。

📖 专业版问题讲解 (展开)
EvoPolicyGym (Autonomous Policy Evolution Gym) 由 USTC + CUHK + 澳门大学 + 清华 + 浙大 + 苏大 + Brown + 上海交大 8 校联合提出, 系统性评测 agent 通过 feedback 迭代改 policy 的能力。之前 benchmark 只看最终分, 忽略过程改进。EvoPolicyGym 引入「budget-bounded policy evolution」setting, harness-model agent 在固定 interaction budget 下反复编辑 executable policy, 提供 trajectory-level 诊断区分 budget allocation + feedback conversion 两种失败模式。
⚙️ 方法：Benchmark 设计: (1) 16 个 compact interactive RL environments 测 policy evolution; (2) trajectory-level diagnostics 区分「预算分配 vs 反馈转化」失败; (3) leaderboard + diagnostics 双重评估; (4) GPT-5.5 等 model 验证, 看 agent 是否真能 iterative improve
⚖️ 取舍：优势: 第一个 explicit policy evolution 评测, trajectory diagnostics 区别于 final score; 16 个 env 跨多任务, 评测鲁棒; 限制: 评测依赖 harness-model, harness 选择影响结果; 16 env 仍是 academic, 真实 production codebase 演化复杂度更高; leaderboard 排名 ≠ 实际部署可用性
📊 效果：GPT-5.5 在 EvoPolicyGym 拿到 strongest aggregate rank score + top-2 in all 16 envs; trajectory diagnostics 揭示 strong autonomous policy evolution 依赖 task-appropriate 机制发现, 不是单次 win; 8 校合作, 数据公开

AgenticSTS: 测 LLM agent 在「内存受限」下能做多长的任务

想象让 AI 打 100 个电话给你订披萨, 但它的「脑子」最多只能记 10 个人的对话记录 — 它必须把前 9 个人的信息「压缩」进下一个电话的开场白。AgenticSTS 测的就是 LLM agent 在「有限脑子」(bounded memory) 下能完成多长的多步骤任务, 系统性测「上下文压缩 + 任务持久化」能力。

📖 专业版问题讲解 (展开)
AgenticSTS (Bounded-Memory Testbed for Long-Horizon LLM Agents) 由 Alaya Lab + SJTU + Shanghai Innovation Institute + 南开 + USTC 联合提出, 系统性测 agent 在 bounded context window 下的 long-horizon task 能力。Context window 是 LLM agent 的「脑子」, 长任务 agent 必须学会「summary-old-information + retain-task-relevant-fact」策略, 但当前 benchmark 都是 short-horizon 或 full-memory 设置, 不能直接测这种 bounded-memory 长任务能力。
⚙️ 方法：Testbed 设计: (1) 多个 long-horizon task scenarios (外卖下单 / 项目管理 / 代码 review 长链路); (2) context window 显式 bounded (e.g. 4K tokens); (3) 评估指标分 sub-task completion + full-trajectory consistency; (4) 配套 agent memory compression 策略 benchmark
⚖️ 取舍：优势: 第一个系统性 bounded-memory long-horizon testbed, 暴露真生产痛点; 限制: testbed scenarios 偏 academic (外卖 / 项目管理), 真实 production codebase 演化更复杂; memory compression 策略的「评测 ↔ 训练」gap 没说清; benchmark 在小模型上验证, frontier model 行为差异未明
📊 效果：在 multi-turn long-horizon 任务上, bounded-memory setup 下 agent success rate 显著下降; 揭示当前 agent 对 context compression 策略依赖 prompt engineering; 5 单位合作验证, 数据公开
🏢 团队：Cheng, Xiangchen, Jiang, Yunwei, Sun, Jianwen, Li, Zizhen, Li, Chuanhao, Cao, Xiangcheng, Liu, Yihao, Zhang, Fanrui, Jin, Li, Zhang, Kaipeng → Alaya Lab + Shanghai Jiao Tong University (上海交通大学) + Shanghai Innovation Institute (上海创智学院) + Nankai University (南开大学) + USTC (中国科学技术大学)
