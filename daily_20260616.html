Towards Direct Latent-Space Synthesis for Parallel Branches in LLM-Agent Workflows

大模型正在被当成 agent 的执行引擎,但所有分支结果最终还是被塞回一条单向的文本流:多路探索、各自检索、并行试解,最后都靠'字符串拼接+再 prefill'交给模型合并。结构化并行探索被迫拍扁成串行文本,先并行后串行的红利几乎全被这一步抹平。

⚙️ 方法：提出 Direct Latent-Space Synthesis:让 LLM 在隐空间里直接读入各分支已经生成好的 latent 状态,跳过把分支再渲染回 token、再 prefill 的回路。跷跷板翘起的是'并行结构信息被原样保留'这一头——模型看到的是分支的中间表征,而不是被人类文本格式压扁后的代理,合并阶段终于不再替序列化买单。
⚖️ 取舍：为了吃下隐空间 latent,整个方案被绑死在某一个具体 LLM backbone 的隐层几何上:换基模、换词表、换分词器,这套 latent 合成接口就作废,跨模型的可移植性被自家 backbone 的特异性压死。
📊 效果：在多分支 agent 工作流上,DLS 用同一 LLM 即可把端到端合成阶段的延迟和 token 开销打掉相当比例,且合并质量相对文本拼接基线更稳;具体数字与所测 backbone 在论文主表里给出。
🏢 团队：第一作者 Shikun Liu（联合发起人之一）；作者群体覆盖上海/北京/香港多所机构（包含 Mufei Li、Dongqi Fu、Pan Li 等），通讯待原文确认。

Neither Parallel Nor Sequential: How DiffusionGemma Actually Commits Tokens

开源离散扩散语言模型一直被宣传成'并行、非自回归'的下一代解码器,但工业界真正在用的 checkpoint 在每一轮 unmask 时到底先落哪些位置、什么时候落、以多高置信度落,几乎没人去量;用户以为拿到了并行推理,实际拿到的是另一台 AR 机器,这种'宣传-行为'错位是当下扩散语言模型推广最危险的暗坑。

⚙️ 方法：提出一套轻量探针方法:hook 进 DiffusionGemma 26B 的 sampler accept 步,记录每个画布位置何时 commit、以何置信度 commit;用 686 条 prompt、6 种 regime 的探针 suite 做压力测试。翘起的是'显式测得'这一头——首次系统给出扩散语言模型真实的 commit 时序,撕开'纯并行'的市场话术。
⚖️ 取舍：为了把 commit 行为测得细,整套 hook、accept 记录和 regime 探针都是为 DiffusionGemma 26B 的 sampler 内部结构定制的:换别的扩散语言模型就要重写 hook 位置与 accept 协议,可复用的诊断框架被模型内部黑盒压死。
📊 效果：在 6-regime、686 prompt 的探针下,DiffusionGemma 26B 的解码被证实既非纯并行也非 block-AR,而是处于中间地带;论文同时给出 confidence 时序、位置分布与若干 regime 下的边界,直接驳斥其并行声明。
🏢 团队：作者：Ali Asaria、Tony Salomone、Deep Gandhi（独立/小团队研究，机构信息以论文首页为准）。
arXiv:2606.14703 · 论文精读

Gaze Heads: How VLMs Look at What They Describe

视觉-语言模型描述图像时,究竟在看图里的哪一块、什么时候看,内部机制长期是黑盒;研究者只能看到最终文字,看不到'说这一句时眼睛落在画面哪一格'。这种内部不可观测性,让 VLM 的可解释性、可控编辑和故障归因都缺少一个最朴素的物理锚点。

⚙️ 方法：在 VLM 的语言 backbone 注意力头里定位出'注视头 (gaze heads)':用连环画这种'叙事顺序按空间排开'的图像做受控 testbed,只需少量 forward pass 的相关度打分就能挑出那批头。翘起的是'极低开销+物理直觉'这一头——几遍前向就能圈出'描述某处时正盯某处'的注意力头,把不可见的对齐变成可指认的部件。
⚖️ 取舍：为拿到'头部-图像区域'这种一对一的可读对应,整套定位严重依赖叙事顺序与图像空间排布一致的控制场景(如 comic strips):换成自然照片、视频或抽象图,空间-语义的对齐不再同构,方法的直观性就被场景特异性压死。
📊 效果：在多种 VLM 上稳定找到一小撮 gaze heads,它们在描述某区域时注意力确实追踪到该图像块;论文给出 head 数量、跨模型复现率与若干可视化证据,展示这批头可被用来做局部编辑与失败归因。
🏢 团队：Northeastern University（美国东北大学）。一作 Rohit Gandikota，通讯作者 David Bau。

CORA: Analyzing and bridging thinking-answer gap in Multimodal RLVR via Consistency-Oriented Reasoning Alignment

把可验证奖励的 RLVR 搬到多模态后,大家都在抢两件事:让推理 trace 覆盖到图,别让模型在图上幻觉;但一个被低估的暗病是'想的过程'和'最终答案'语义对不上——模型嘴上推理得头头是道,落笔给的答案却和推理里那句结论相反,这种 thinking-answer 错位在多模态 RLVR 里比纯文本更普遍、更难抓。

⚙️ 方法：提出 CORA:在多模态 RLVR 里显式建模'推理-答案一致性'作为额外优化目标,用 consistency-oriented reasoning alignment 把这条一致性直接抬到与可验证 reward 同级的训练信号里。翘起的是'一致性'这一头——把'说的和给的必须自洽'从隐式偏好变成显式奖励,专门打击 thinking-answer 错位。
⚖️ 取舍：为精确度量并对齐 thinking-answer 一致性,框架需要稳定的 thought/answer 切分与多模态 reward 拆解:reward 信号被一致性判别器的设计空间绑死,一旦判别器和 backbone 的输出分布耦合,跨任务的可校准性就被自家一致性判别器压死。
📊 效果：在多种多模态推理基准上,CORA 相对现有 RLVR 基线在一致性指标上取得显著提升,同时保持或提高准确率;论文给出 thinking-answer gap 的量化分析与若干边界 case。
🏢 团队：机构以原文为准（作者：Jiayue Cao、Zhicong Lu、Xuehan Sun、Wei Jia、Hongling Zheng、Changyuan Tian、Zichuan Lin、Wenqian Lv）。
arXiv:2606.14694 · 论文精读

AdaSR: Adaptive Streaming Reasoning with Hierarchical Relative Policy Optimization

大推理模型默认是'读完再想':一次性拿到完整输入,在静态上下文里推完再答。但真实场景(音视频流、直播、传感器)信息是连续涌进来的,模型必须边读边想、边想边改、边改边答;现有 streaming reasoning 又多靠在固定轨迹上做监督模仿,适应性差,遇到分布外就崩。

⚙️ 方法：提出 AdaSR + Hierarchical Relative Policy Optimization:把'读'和'想'分成层级策略,用相对策略优化(HRPO)在层级粒度上做在线适配,让模型学会在流还没读完时动态决定何时更新推理、何时落子输出。翘起的是'自适应'这一头——把'想'从一次性静态计算改成随流速动态调节的阀门,让模型在部分观测下也能边读边改边答。
⚖️ 取舍：为做到层级粒度的相对策略优化,训练信号被锁在'读-想'分层结构与相对优势估计的设计选择上:这套层级抽象一旦换任务类型(比如从视频流换成交互式对话)就得重做层级划分与 reward shaping,通用性被自定义层级压死。
📊 效果：在多种 streaming reasoning 基准上,AdaSR 用 HRPO 相对静态'读完再想'和纯模仿式 streaming 基线取得稳定优势,在流速扰动与早答准确率上均给出提升;具体数字以论文主表为准。
🏢 团队：作者：Junlong Tong、Wenqi Xu、Yingqi Fan、Anhao Zhao、Xuan Lu、Yang Tan、Xiaoyu Shen（机构以论文首页为准）。

trycua/cua

cua（Computer-Use Agents）是一套面向「电脑操控型 AI Agent」的开源基础设施。它提供跨 macOS、Linux、Windows 三大平台的虚拟桌面沙箱、Python/TypeScript SDK 以及标准化评测基准，让开发者可以训练、部署并评测能让 Agent 像真人一样点击屏幕、操作软件、跨应用完成任务的模型。技术上，cua 通过 Lume 等虚拟化层提供可快照、可复现的高保真操作系统环境，并集成计算机视觉、屏幕解析（grounding）与 GUI 操作链路。适用场景包括自动化办公、RPA 替代、软件测试 Agent、以及作为 OpenAI Operator、Anthropic Computer Use 等系统的开源复现底座，被研究者与产品团队广泛用于构建可上桌面的智能助手。

vllm-project/vllm

vLLM 是目前最主流的开源大模型推理与 serving 引擎，专注于把 GPU 显存用满、把吞吐拉满。它的核心创新是 PagedAttention——借鉴操作系统虚拟内存的分页机制来管理 KV cache，使显存碎片大幅减少、batch 并发能力提升数倍。在此基础上，vLLM 提供了与 OpenAI 兼容的 HTTP 服务、流式输出、Continuous batching、Speculative decoding、Tensor/Pipeline/Expert 并行、张量量化（GPTQ/AWQ/FP8/INT4）以及多模态模型支持，号称是 HuggingFace 模型「开箱即用」的最高性能部署方案。广泛被企业用于生产环境替代昂贵闭源推理服务，支撑聊天机器人、代码助手、搜索增强生成（RAG）以及大规模在线推理平台，单卡 H100 即可服务数十路并发请求。

⭐ 82,969 · Python
开源 · GitHub

axolotl-ai-cloud/axolotl

Axolotl 是社区最受欢迎的大模型微调（fine-tuning）框架之一，以 YAML 配置驱动、覆盖从单卡到多节点全栈训练流程。它原生支持 HuggingFace transformers、trl、PEFT/LoRA/QLoRA/DoRA 等高效参数微调方法，并集成 FSDP、DeepSpeed、Flash Attention 2/3、liger-kernel 等加速组件，能在 7B–70B+ 模型上做预训练、SFT、DPO/ORPO/IPO/KTO 等对齐训练，以及多模态模型微调。亮点是「一份 yaml 跑天下」：用户只需声明模型、数据集、超参和并行策略，无需改代码即可在 H100/A100/4090/Apple Silicon 上启动训练。适合需要定制化行业大模型、垂直领域助手、研究团队复现论文以及中小公司低成本做私有化模型对齐的开发者，是 Ollama、Unsloth 之外训练侧的事实标准之一。

⭐ 12,053 · Python

microsoft/TRELLIS

TRELLIS 是微软研究院发布的 3D 生成模型，对应 CVPR 2025 Spotlight 论文《Structured 3D Latents for Scalable and Versatile 3D Generation》。它用统一的「结构化 3D 潜空间」同时支持文生 3D、图生 3D，并能输出 mesh、辐射场（Radiance Field）、3D Gaussian 等多种表征，质量与可控性显著优于此前的逐方案路线。技术上核心是 OVL（Organic Versatile Lattices）稀疏结构潜表示，加上 rectified flow transformer 与 DPO 对齐训练，使生成既快又精细。适用场景包括游戏资产生成、AR/VR 物体建模、产品设计快速打样、影视概念资产、研究人员探索 3D 基础模型——一句话：输入一句话或一张图，输出一只可旋转、可渲染、可 3D 打印的实体。

huggingface/lerobot

LeRobot 是 Hugging Face 推出的开源机器人学习框架，把视觉-动作模仿学习（imitation learning）与强化学习真正「平民化」。它内置 ALOHA、SO-100/101 等开源低成本机械臂硬件参考设计与 3D 打印文件，配套数据集格式、可视化工具与训练管线（ACT、Diffusion Policy、VQ-BeT、TDMPC 等 SOTA 策略），让研究者甚至爱好者花几百美元就能复现「教机器人叠衣服、拿积木」等任务。技术上，LeRobot 基于 PyTorch + HuggingFace Hub，用户可在 Hub 上像分享模型一样分享数据集、checkpoint 与机器人演示片段。适用人群包括机器人研究者、AI for Robotics 教育者、具身智能初创团队以及希望低成本搭原型的人，是当前具身智能（embodied AI）社区事实上的入门首选库。

MODSetter/SurfSense

SurfSense 是一款开源、注重隐私的团队级「第二大脑」与知识助手，被视作 Google NotebookLM 的开源替代品，但更强调本地化与无数据上限。它能把你的网页浏览记录、Notion/Obsidian 笔记、PDF、Slack/Discord、GitHub Issues、Linear、YouTube 字幕、学术论文等数十种来源统一接入索引，再借助大模型（支持任意 OpenAI 兼容 API、Ollama 本地模型）做语义检索、跨源问答、播客式语音对话生成。技术上基于向量检索 + RAG + 多 Agent 协作，所有数据默认存本地、可自托管、无 token 计费。适合研究人员整理文献、产品经理聚合调研素材、咨询团队沉淀客户资料，以及任何希望「把散落的网络笔记变成一个可对话的私有知识库」的个人或小团队。
