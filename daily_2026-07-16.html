Xiaomi-Robotics-U0: Unified Embodied Synthesis with World Foundation Model

想象一下,你想让家里的机器人学会'帮我从冰箱拿可乐',传统方法是拍 1000 段视频教它。现在小米团队说:我们直接训练一个'世界基础模型',输入文字指令,它就能在虚拟环境里合成机器人执行任务的**完整 4D 场景**(3D 空间 + 时间),包括机器人怎么动、物体怎么变、视角怎么切,不需要任何真实视频。Xiaomi-Robotics-U0 把具身数据合成的成本从'百万级真实演示'降到'零样本文字生成',这是具身 AI 在数据层第一次跑赢真实采集。

📖 专业版问题讲解 (展开)
本文提出 Xiaomi-Robotics-U0,一种统一具身合成框架,基于自回归-扩散混合架构(world foundation model)对机器人感知-动作-场景演化进行联合建模。核心贡献包括:(1) 多视角几何一致性约束,在 4D 隐空间同时编码深度、法线、语义;(2) 任务条件化的长视野 rollout(平均 60s),支持复杂指令链;(3) 与真实机器人控制栈(VLA、Diffusion Policy)的零样本迁移。在 8 个具身基准(MetaWorld、RLBench、ManiSkill2 等)上,U0 合成数据训练的下游策略在成功率上达到真实数据训练的 92.4%,而数据采集成本降至 1/400。
⚙️ 方法：采用三阶段训练:第一阶段在大规模视频-动作对(800K 段)上预训练 4D 世界模型,使用时空因果 attention;第二阶段注入机器人 embodiment 约束(本体感知 token、运动学链),通过 LoRA 适配不同形态;第三阶段对任务指令做 instruction tuning。推理时,世界模型在隐空间预测未来 N 帧的 4D 表示,再通过神经渲染器解码为多视角 RGB-D,直接喂给下游策略网络进行模仿学习。整套 pipeline 端到端可微。
⚖️ 取舍：U0 训练算力开销巨大——单次预训练需要 256 块 H100 跑 14 天,中小实验室难以复现;合成数据在'长尾任务'(如罕见物体+复杂背景)上仍落后真实数据 15-20pp;世界模型的物理一致性在接触动力学(软物体形变、流体)上仍有显著 artifact。
📊 效果：在 8 个具身基准上,用 U0 合成数据训练的策略平均成功率 78.6%,真实数据训练 85.1%,差距仅 6.5pp;数据采集成本从 400h/人/任务降到 1h/人/任务,降幅 400 倍。特定任务如'抽屉开关-物体抓取-放置'三步复合指令,合成数据训练策略首次跑赢真实数据(+2.3pp)。长视野任务(60s+)保持时序一致性优于现有 SOTA(Sim4CV+ManiSkill2)13pp。

Weak-to-Strong Generalization via Direct On-Policy Distillation

传统观念是'强模型教弱模型',但 OpenAI 早期实验发现反过来也行——让 GPT-2 当'老师',GPT-4 当'学生',学生能学会比老师更强的能力。清华大学 + 多家机构 7/14 论文把这个现象推到极致:**直接策略蒸馏**(Direct On-Policy Distillation),老师不用离线打分,而是实时在线给出动作示范,学生在线学习。关键创新是用 RL with verifiable rewards(RVLR)替代人工偏好,蒸馏效率和稳定性都大幅提升。

📖 专业版问题讲解 (展开)
本文研究 weak-to-strong generalization 的理论极限与工程实现。提出 Direct On-Policy Distillation(DOPD)框架:小型 teacher model 在 verifiable reward 环境(数学、代码)中实时生成 rollouts,大型 student model 通过 importance sampling 直接拟合 teacher 的 on-policy 分布,绕过传统 reward modeling 步骤。理论上证明 DOPD 在线性化假设下与监督蒸馏等价,但样本效率提升 O(log N)。实验覆盖 7B→70B、13B→120B、70B→400B 三档规模,在 MATH、HumanEval、CodeContests 上 DOPD 训练的学生模型平均比 teacher 强 8.3pp,比 SFT 蒸馏强 4.7pp。
⚙️ 方法：核心是把 RLVR(reinforcement learning with verifiable rewards)的两阶段(rollout 生成 + reward 计算)合并为单阶段 on-policy 蒸馏。teacher model 在每个 batch 内实时采样 K 条 trajectory,student model 用 cross-entropy + KL 散度约束同步拟合 teacher 的完整输出分布,而不是只拟合最高 reward 的答案。引入 trust region 防止 student 偏离 teacher 过远,同时保留 verifiable reward 作为辅助信号。整体框架兼容 PPO/GRPO/DPO 多种 RL 算法。
⚖️ 取舍：DOPD 仅在有 verifiable reward 的任务上有效(数学/代码/逻辑),开放式生成(对话/创作)无法直接套用;teacher 必须足够强(性能大于等于 student 的 30%),否则会拖垮 student;on-policy 蒸馏对显存要求高(teacher + student 同时 forward),7B→70B 蒸馏需 8xH100。
📊 效果：在 MATH 基准上,7B→70B DOPD 蒸馏后 student 达到 78.4%(teacher 70B 是 71.2%),超过 SFT 蒸馏 baseline 4.7pp。在 HumanEval 上 13B→120B 蒸馏后 pass@1 达到 92.1%(teacher 13B 是 85.6%)。3 档规模(7B→70B、13B→120B、70B→400B)平均 student 超过 teacher 8.3pp。重要的是:DOPD 训练时间比 SFT 蒸馏+RL 两阶段节省 35%。

SynthDocBench: Controlled Benchmark for Long-Context Visual Document Understanding

你想测 VLM(视觉语言模型)能不能'读完 200 页合同找其中某条款',但现有 benchmark 都不够——要么文档太短,要么问题太明显。ServiceNow 团队 7/15 发布 SynthDocBench:用合成方法生成**长达 1000 页的视觉文档**,长度、布局、模态、查询类型四个维度独立可控,覆盖 27 类真实业务文档(合同/财报/医疗/法律)。这是目前唯一能让 VLM 在'长上下文+视觉理解'上现原形的测试集。

📖 专业版问题讲解 (展开)
本文提出 SynthDocBench,一个用于长上下文视觉文档理解的可控评估基准。核心创新在于:(1) 解耦的因子化设计——文档长度(1-1000 页)、布局复杂度(纯文本/表格/多列/混合)、模态(文本/图/公式/签名)、查询类型(定位/提取/推理/跨页关联)四个维度可独立调控;(2) 程序化合成保证 ground-truth 精确性,避免人工标注误差;(3) 评估 17 个主流 VLM(GPT-5.6、Claude Sonnet 5、Gemini 2.5、InternVL3、Qwen3-VL 等)在 12 个任务上的表现。关键发现:现有 VLM 在 100 页以下表现尚可,但超过 200 页后性能断崖式下跌,Qwen3-VL-235B 在 500+ 页跨页推理任务上仅 31% 准确率,远低于人类 89%。
⚙️ 方法：合成 pipeline 分四层:文档层用 LaTeX/HTML 模板程序化生成多页文档,支持任意长度和布局;内容层用 LLM 生成语义连贯的合成文本(图例/合同条款等),并注入跨页引用;查询层用模板+LLM 生成四类问题及精确 ground-truth(span/box/答案),保证自动评测;评估层用 GPT-4o 作为 judge 对开放式回答打分,辅以规则匹配。整个 benchmark 完全可复现,生成 1000 页文档约需 3 分钟。
⚖️ 取舍：SynthDocBench 是合成数据,虽然 ground-truth 精确,但可能与真实文档(签字/印章/手写)分布有差异;评测用 GPT-4o 作为 judge 可能引入模型偏置;1000 页文档生成对存储和评测算力要求高,中小实验室难以完整复现全档位结果。
📊 效果：在 12 个任务 × 17 个 VLM × 5 个文档长度档位的评测中,关键结果:(a) 200 页是 VLM 性能断崖——Claude Sonnet 5 从 50 页的 84% 跌到 200 页的 52%;(b) 跨页推理最弱,Qwen3-VL-235B 仅 31%;(c) 简单定位/提取任务表现尚可(70%+),但需要跨页关联时几乎所有模型崩溃;(d) 人类基线 89%,最佳 VLM 仅 67%。证明当前 VLM 在企业级长文档处理上仍有巨大差距。

Read It Back: Pretrained MLLMs Are Zero-Shot Reward Models for Text-to-Image Generation

AI 画图怎么知道画得好不好?传统方法是训练一个专门的'评分模型',成本高又要人工标注。HKU + 字节跳动 + PKU 团队 7/13 提出 SpectraReward:**直接拿现成的多模态大模型当评委**——让 MLLM 看图,看能不能把生成图'读回去'还原成原始 prompt,还原度就是奖励分。无需训练、无需偏好数据、MLLM 越大奖励越准。更绝的是 Self-SpectraReward:让模型自己当自己的评分员。

📖 专业版问题讲解 (展开)
本文提出 SpectraReward,一种 training-free 的 reward function,将预训练 MLLM 直接用作图像生成 RL 的奖励模型。核心思想:SpectraReward 通过单次 image-conditioned teacher-forced 前向计算,衡量 MLLM 从生成图像恢复原始 prompt 的对数似然——能'读回去'意味着生成图与 prompt 对齐。作者进一步提出 Self-SpectraReward,适用于统一多模态模型(UMM),让策略自身的理解分支充当生成分支的奖励模型,形成无需外部 reward 的自改进闭环。实验覆盖 2 个扩散模型 × 3 种 RL 算法 × 9 种 reward MLLM(4B-235B)× 5 个 OOD T2I 基准。关键发现:SpectraReward 显著优于现有 MLLM 派生奖励训练方法;更大的 reward MLLM 不一定更好,reward-policy alignment 是关键因素。
⚙️ 方法：SpectraReward 实现极简:对 prompt p 和生成图 x,在 MLLM 上做一次 image-conditioned teacher-forced forward,计算条件对数似然 log P(p|x) 作为奖励分。无需 fine-tuning,无需偏好数据,直接调用现成 MLLM 即可。Self-SpectraReward 是 SpectraReward 在 UMM 上的特例——UMM 的理解分支和生成分支共享 backbone,让理解分支评估生成分支,形成 self-play 闭环。训练时用 PPO/GRPO/DPO 任一 RL 算法,奖励信号就是 SpectraReward 输出。
⚖️ 取舍：SpectraReward 依赖 MLLM 的图像理解能力,对完全抽象/反常识 prompt 评估不准;teacher-forced forward 计算成本不低(每个 reward 评估需一次完整 MLLM forward),在 235B 模型上单次 RL step 评估数千张图成本可观;Self-SpectraReward 仅对统一多模态模型有效,纯扩散模型(如 SDXL)无法直接使用。
📊 效果：在 9 个 MLLM backbone × 5 个 OOD benchmark 上,SpectraReward 平均提升 GenEval 4.7pp、TIIFBench Long 6.2pp,优于所有 MLLM 派生奖励训练方法(如 ImageReward、HPSv2)。Self-SpectraReward 在 BAGEL 7B 上达到 GenEval 89.5%,超过用 Qwen3-VL 235B 外部奖励的 86.8%。关键发现:reward MLLM 越大不一定越好——Qwen3-VL 30B-A3B(88.3)反超 Qwen3-VL 235B(86.8),说明 reward-policy alignment 才是关键。

Search Beyond What Can Be Taught: Evolving the Knowledge Boundary in Agentic Visual Generation

AI 画图有个老毛病:训练数据里没有的东西它会瞎编(比如让你画'昨天的奥运冠军'它就胡诌)。传统方法是用检索增强(RAG)给模型外挂知识库。7/15 论文提出**进化知识边界**——让 AI agent 自己决定什么时候该搜、搜什么、怎么把搜来的知识融进画面,而不是被动检索。简单说:让 AI 学会'我不懂就搜,搜完再画',而不是'假装懂乱画'。

📖 专业版问题讲解 (展开)
本文提出 EvoSearch(Evolutionary Knowledge-Boundary Search),一种面向 agentic visual generation 的知识增强框架。核心思想:将视觉生成任务分解为 knowledge boundary detection + targeted search + integrated synthesis 三步,由一个多模态 agent 自主决策。关键技术包括:(1) 基于不确定性估计的知识边界检测器,识别模型'知识盲区';(2) 进化搜索策略——通过多轮 query 演化(refine/expand/prune)逼近真实信息需求;(3) 跨模态证据融合——将搜索结果(文本/图/知识图谱)结构化映射到生成 prompt。在 8 个 long-tail 任务(罕见人物/事件/品牌/科学现象)上,EvoSearch 在事实准确性上比纯生成 baseline 提升 47%,比单轮 RAG 提升 19%,且用户主观评分提升 31%。
⚙️ 方法：EvoSearch 框架由三个协同组件构成:(1) Knowledge Boundary Detector:在生成前用 MLLM 评估 prompt 涉及的概念是否在训练分布内,输出不确定性分数;(2) Evolutionary Search Agent:当不确定性超过阈值,触发多轮检索,每轮基于上轮结果生成新的 query(refine/expand/prune 三个策略并行),用搜索结果相似度作为 fitness signal 迭代优化;(3) Cross-modal Synthesis:把检索到的文本/图/知识图谱信息通过 cross-attention 注入扩散模型的 UNet,在生成过程中实时引用证据。整个 pipeline 在 12-15 秒内完成一张图。
⚖️ 取舍：EvoSearch 推理成本高(平均 12-15s/图,baseline 仅 3s),主要来自多轮检索和跨模态融合;搜索质量受限于上游搜索引擎,中文/小语种任务效果下降;agent 决策链路较长(平均 4-6 轮),对延迟敏感场景(实时聊天)不友好;知识边界检测器对'伪盲区'(模型其实会但评估说不会)有 8% 误判率。
📊 效果：在 8 个 long-tail 任务(包含 200+ 真实用户查询)上,EvoSearch 在事实准确性上比纯 SDXL baseline 提升 47.2pp(从 38% 到 85%),比单轮 RAG(66%)提升 19pp。用户主观评分(真实性/美观/相关性)平均提升 31pp。进化搜索相比单轮检索的 query 质量提升 2.3 倍(retrieval recall)。特别在'昨日新闻事件'这类强时效任务上,EvoSearch 几乎完美(92%),baseline 仅 12%。
