MrFlow: Multi-Resolution Flow Matching for Training-Free Diffusion Acceleration via Staged Sampling

想象你让 AI 生成一张海报, 它原本要 80 秒, 现在用 MrFlow 只要 8 秒 — 而且不需要重新训练。它先快速出一张模糊版的「整体结构」(低分辨率), 然后用一个轻量级的 GAN 模型把模糊图放大成清晰图, 再稍微加点噪让细节重新生成, 最后再修一遍细节。这样四步流水线既能跑得快, 又不让画糊掉。

📖 专业版问题讲解 (展开)
MrFlow 由 Beihang University (北航) + NTU + CAS ICT + ETH Zürich 联合提出, 是 pretrained flow-matching model 的 training-free acceleration 策略。利用 low-resolution sampling 的 quadratic token reduction + reduced step requirement, 通过 staged low-to-high-resolution pipeline 实现训练免费的 diffusion 加速。在 FLUX.1-dev 和 Qwen-Image 上 end-to-end 实现 10× 加速, OneIG 质量指标跟加速前仅差 1%, 显著超越其他 training-free 加速策略, 可与 timestep distillation 方案正交叠加达到 25× 加速度。
⚙️ 方法：Staged low-to-high-resolution pipeline: (1) 在 low resolution 快速生成 main structure; (2) 用 light pretrained GAN-based model 在 pixel space 做 super-resolution; (3) inject low-strength noise 启用 high-frequency resampling; (4) refine 细节在 high resolution。全程不需要 training, 利用 quadratic token reduction 和 reduced step requirement
⚖️ 取舍：优势: 训练免费 — 不需要 fine-tune, 几分钟部署; 利用 pretrained GAN super-resolution 模块不增加训练负担; 正交叠加蒸馏方法能翻倍加速; 限制: 多阶段 pipeline 增加 integration complexity; low-to-high 超分依赖现成 GAN 模型 (FLUX.1-dev / Qwen-Image), 新模型可能需要新 GAN; 多次 inference steps 让 pipeline latency 仍有下限
📊 效果：在 FLUX.1-dev 和 Qwen-Image 上 end-to-end 实现 10× 加速, OneIG 质量指标跟加速前仅差 1%; 跟 timestep distillation 正交叠加能再翻倍到 25×; 跟 ToMA (1.01×) / DB-Taylor (4.13×) / SPEED (8.61×) / RALU (8.79×) / Pi-Flow (19.6×) 比, 25.1× 是当前 training-free SOTA
🏢 团队：Zheng, Xingyu, Liu, Xianglong, Ding, Yifu, Feng, Weilun, Lin, Junqing, Guo, Jinyang, Qin, Haotong → Beihang University (北京航空航天大学) + Nanyang Technological University (南洋理工大学, 新加坡) + Institute of Computing Technology, Chinese Academy of Sciences (中科院计算所) + ETH Zürich (苏黎世联邦理工学院)

AgenticDataBench: A Comprehensive Benchmark for Data Agents

想象你雇了一个 AI 数据分析师, 怎么知道它到底是真懂还是瞎编? 现在的测试都太简单 — 只看它会不会写 SQL 改数字。但真实数据工作有 15 个行业、几十种「处理缺失值、画趋势图、找异常点」这类操作, 中间还要懂业务才行。本文搞了一个新基准, 把这些真实行业任务都收进来, 让 AI 数据分析师考一遍。

📖 专业版问题讲解 (展开)
AgenticDataBench 由 Tsinghua University (清华大学) + Ant Digital Technologies (蚂蚁集团) 联合提出, 是首个针对 LLM-based data agents 的跨领域细粒度基准。Benchmark 从 15 个垂直行业 (含 5 个 B2B fintech 真实用例) 收集真实数据集与任务, 引入 data science skills (recurring data-centric operational patterns, 如 'Handling Missing Data') 作为评估单元, 用 Stack Overflow 大规模 task solution 做 hierarchical clustering 抽取代表性 skills, 同时对没有真实数据的领域用 LLM-based task generation 系统化合成任务。
⚙️ 方法：三阶段评测: (1) 跨 15 行业收集真实任务 (含 5 个 fintech B2B 用例); (2) 用 LLM 从 Stack Overflow 大规模 task solution 做 skill-aligned hierarchical clustering 抽取 skills; (3) 没有真实数据的领域用 LLM-based task generation 系统合成; 同时 open-source testbed 提供细粒度 skill-level 评测
⚖️ 取舍：优势: 第一个跨 15 行业 + 含真实 fintech B2B 的 data agent benchmark; skill-aligned 评估粒度比 outcome-only 强很多; 限制: 真实任务从头部 5 个 B2B 收, 可能有 selection bias; LLM-based task generation 合成的任务可能跟真实任务复杂度有 gap; benchmark 偏数据领域, 对 multi-modal (image/audio) 数据任务还没覆盖
📊 效果：包含 15 个垂直行业的真实数据任务 (含 5 个 fintech B2B 用例); skill-level granularity 评估单位, 不只评最终答案是否对, 还看 AI 中间调用了哪些 skills; 提供开源 testbed 和 fine-grained skill-level insights, 让评测能区分「运气对」和「流程对」

SkillCoach: Self-Evolving Rubrics for Evaluating and Enhancing Agentic Skill-Use

想象公司让 AI agent 处理大量 SOP (标准操作流程) — 哪个工单走哪条流程、哪个步骤漏一步都对不上号, 现在用「最后做对没」一个分数根本不够。本文搞了一个「自我进化的评分表」 — 让 AI 从真实操作轨迹里反推出「完整的检查项」, 再用这些检查项当评分标准, 把「流程对不对」和「答对答错」分开评估。

📖 专业版问题讲解 (展开)
SkillCoach 由 HKUST(GZ) (香港科技大学广州) + JD.COM (京东) 联合提出, 解决 agent 工业场景里「skills (SOP/domain rule/tool workflow) 大到一定规模就 reliable use 困难」的核心痛点。提出 self-evolving rubric framework: 从真实 rollout 抽取 skill-grounded process rubrics, 沿四个维度 (skill selection / skill following / skill composition / skill-grounded reflection) 评估轨迹, 把外部 verifier 当 outcome-only signal 单独保留, 让 process quality 跟 accidental success 区分开。Evolved rubrics 同时作为 process supervision 选高质量训练 trajectory。
⚙️ 方法：Self-evolving rubric framework: (1) 从真实 rollout 推导 skill-grounded process rubrics; (2) 沿 4 个维度 (selection / following / composition / reflection) 评估轨迹; (3) 保留外部 verifier 当 outcome-only signal, 让 process quality 跟 accidental success 分开; (4) evolved rubrics 当 process supervision, 过滤出高质量训练 trajectory 进一步提升 agent 行为
⚖️ 取舍：优势: 第一个显式区分 process quality 和 outcome success 的 agentic skill 评测框架; 实验显示 rubric-based supervision 比 result-only 强不少; 限制: 4 个维度可能不够细分 enterprise 复杂流程 (缺合规/审计维度); rubric auto-evolution 仍需要 ground truth rollout 起点, 获取成本高; 主要针对 JD.com 内部 SOP 验证, 跨 enterprise 泛化待验证
📊 效果：在企业场景 (含 SOP-heavy 工作流) 上: evolved rubrics 显著提升 evaluation quality; 暴露 final-accuracy 看不住的 hidden failures (选了 distractor skill、缺关键步骤、workflow 顺序错、忘 final checks); evolved rubric supervision 比 outcome-only filtering 更强地提升 agentic skill-use
🏢 团队：Zhu, Jiayin, Mao, Kelong, Guo, Yudong, He, Dengbo, Xu, Sulong, Gu, Simiu, Yue, Yutao → HKUST(GZ) — Hong Kong University of Science and Technology (Guangzhou), 香港科技大学 (广州) + JD.COM (京东) + Institute of Deep Perception Technology, JITRI (江苏省产业技术研究院深度感知技术研究所)

AutoMem: Automated Learning of Memory as a Cognitive Skill

想象你让 AI 在《NetHack》这种地下城里玩几千步, 中间要记「这把钥匙在第几层第几格」、「这个 NPC 是不是骗子」、「上次踩的陷阱叫什么」 — 但 AI 不像人一样懂得「该记什么、什么时候回头看」。本文让 AI 的「记忆」本身变成一种可训练技能 — 通过一个 LLM 反复改进「记忆的笔记怎么写」和「用记忆的方式怎么变聪明」两个轴, 让它玩得比 Claude Opus 4.5 还好, 而模型本身没动。

📖 专业版问题讲解 (展开)
AutoMem 由 Stanford University 提出, 借鉴认知科学的 metamemory (元记忆) 概念, 把 agent 的 memory management 重新定位为 trainable skill: 把 file-system operations 提升为 first-class memory actions, 跟 task actions 同级, 让 model 决定怎么管理自己的记忆。两个 loop: (1) strong LLM 反复修订 memory structure (prompts / file schemas / action vocab); (2) 从大量 episode 中找到 model 自己好的 memory decisions 当训练信号, 直接提升 memory proficiency。在三个 procedurally generated long-horizon games (Crafter / MiniHack / NetHack) 上验证, 32B open-weight model 仅优化 memory 就可跟 Claude Opus 4.5 / Gemini 3.1 Pro Thinking 对标。
⚙️ 方法：Two-loop framework: Loop 1 — strong LLM 审查完整 agent trajectory, 反复修订 memory structure (prompts / file schemas / action vocab), 优化如何跟 memory files 交互; Loop 2 — 从众多 episode 识别 model 自己好的 memory decisions 当训练信号, 直接训练 model memory proficiency; file-system operations 提升为 first-class memory actions 跟 task actions 平级
⚖️ 取舍：优势: 第一个把 agent memory 重新定位为 trainable skill 的工作, 借鉴认知科学 metamemory 概念; 不改 base model weights 就能追平 frontier 闭源系统; 限制: 仅在 procedurally generated 3 个 long-horizon games 验证, 开放环境 (真实 web / multi-app) 还没测; Loop 1 强 LLM (e.g. Claude Opus) 反复审查 trajectory 成本高; memory structure 搜索空间大, 优化耗时
📊 效果：在 Crafter / MiniHack / NetHack 三个 long-horizon games 上: 仅优化 memory (不改 model 的 task-action 行为), 32B Qwen2.5 base agent 性能提升 2-4×; 32B open-weight model 在 memory skill 优化后达到 Claude Opus 4.5 / Gemini 3.1 Pro Thinking frontier 系统水平; 证明 memory management 是可独立学习的 leverage 高的目标
🏢 团队：Wu, Shengguang, Zhu, Hao, Zhang, Yuhui, Wang, Xiaohan, Yeung-Levy, Serena → Stanford University (斯坦福大学)

The State-Prediction Separation Hypothesis

Transformer 用同一条「管线」干两件事: 一是预测下一个字 (哪个 token 该出现), 二是把当前状态「暂存」起来给后面的字做参考。本文问: 如果用两条独立的计算管线分开干这两件事, 模型会不会变得更好? 实验发现: 会的 — 分离之后, 训练过程更稳 (loss 衰减更平滑), 困惑度 (跟语言建模质量挂钩的指标) 也更低。

📖 专业版问题讲解 (展开)
State-Prediction Separation Hypothesis 由 Cornell University + Harvard University 联合提出, 提出 disentangle Transformer 内 next-token prediction 跟 state-storage 两个 role 的架构视角。论文的 state-prediction separation hypothesis 主张: 把 prediction-only path 跟 state-bearing path 解耦, 用 two-stream Transformer variant 分别承担, 能同时稳定预训练动力学 (loss decay 平滑) 和提升语言建模 (lower perplexity)。实验通过 controlled pretraining runs 验证 hypothesis, 显示预测流和状态流的分离是「LM 设计的 free lunch」而不是性能 trade-off。
⚙️ 方法：Two-stream Transformer variant: (1) prediction-only stream 专做 next-token 预测; (2) state-bearing stream 专做 past context 状态暂存; 两条 stream 在 forward 计算里解耦, 通过 controlled pretraining runs 验证 hypothesis; 实验比较同参数预算下两种架构 (standard single-stream vs separated two-stream) 的 loss curve 跟 perplexity
⚖️ 取舍：优势: 第一个提出 explicit disentangle prediction / state role 的 Transformer 架构 hypothesis; 训练稳定性 + 语言建模质量双赢; 限制: 仍是 hypothesis 性质工作, 大规模 (e.g. 70B+) 训练成本限制下未验证; 两 stream 之间的信息传递机制是 ad-hoc 的, 缺统一理论框架; 局限在 language modeling, 是否能推广到 multimodal / reasoning 任务待验证
📊 效果：Two-stream variant 在 controlled pretraining runs 上: loss decay curve 比 single-stream 更平滑 (训练稳定性); 同样计算预算下 lower perplexity (语言建模质量更好); 验证 state-prediction separation 是 free lunch, 不需要在别的能力上让位
🏢 团队：Monea, Giovanni, Godey, Nathan, Brantley, Kianté, Artzi, Yoav → Cornell University (康奈尔大学) + Harvard University (哈佛大学)

现在企业级 agent 都把 SOP (标准操作流程) 存在 skills 库里, 但今天一个 skill 怎么用、对不对、跟隔壁 skill 怎么搭配, 全凭 LLM 自由发挥, 错了都不知道错哪。SkillSpec 给 skills 加了一个声明式 schema — 每个 skill 写「输入是什么, 输出是什么, 包含哪几个步骤, 错怎么办」, 然后用 Rust 实现可执行 runtime, 让 agent 像跑函数一样跑 skill。

mindmuxai/brain.md

想象你今天用 Cursor / Claude Code / Aider 写一个项目, 关掉 IDE 明天再开, agent 已经完全忘了昨天跟你聊过什么 — 上下文每次都从零开始重建。brain.md 是给 coding agent 加的一层「项目级长期记忆」, agent 每次回到项目, 自动读 brain.md 文件, 把之前的决策、踩坑、约定重新加载进上下文, 不再重复让你解释。
