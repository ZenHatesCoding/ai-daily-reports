Anthropic 把 Claude 塞进 Slack: Claude Tag 让 AI 变成永远在线的队友

Anthropic 在 Slack 工作区推出 Claude Tag —— 一个新型的 AI 协作原语。团队成员只需在 Slack 任意频道输入 @Claude, 后面跟任务描述 (例如 @Claude 帮我 review 这段 PR 改动), Claude 就会在同一个线程里基于上下文完成工作, 不需要切换到外部 web/app。Claude Tag 把协作从「打开 Claude.ai 复制粘贴」变成「在你已经在的地方 @ 它一下」, 跟 Anthropic 当下推动的 agent / 工具使用路线一致: 让模型嵌入既有工作流, 而不是强迫用户跳到模型世界。

OPID: On-Policy Skill Distillation for Agentic Reinforcement Learning

想象一下, 你让 AI 帮你做家务 (做饭 + 打扫 + 整理衣柜), 每一步做完才告诉你「这顿饭做砸了」或「衣柜整理失败」 —— 这种「结局才给反馈」的训练方式, 在 AI 学术上叫 outcome-based RL (基于结局的强化学习)。问题是反馈太稀疏: 中间哪一步走错了? 不知道。OPID 这篇论文的核心想法是: 让 AI 自己「回放」已经走完的整段操作, 从中提取出「关键技能点」(例如「火候太大时应该调小」/「袜子应该叠成三折」), 把这些技能作为「老师指导」注入到后续训练里。相当于让 AI 自己给自己当教练, 在每一步都有「这样做更好」的提示, 而不是稀稀拉拉的结局评分。

📖 专业版问题讲解 (展开)
OPID 提出 On-Policy Skill Distillation 框架, 通过 hierarchical skill 表征 (episode-level 抓全局工作流/失败避免规则, step-level 抓局部决策知识), 用 critical-first routing 机制选择最相关的 skill 注入上下文, 计算 log-probability shift 得到 token-level self-distillation advantage, 与 outcome advantage 联合优化。实验在 ALFWorld / WebShop / Search-based QA 三个 agent benchmark 上验证, OPID 在性能 / 样本效率 / 鲁棒性上都优于纯 outcome RL 和已有 skill-distillation baseline。代码: github.com/jinyangwu/OPID
⚙️ 方法：方法核心是 hierarchical skill 表征 + on-policy self-distillation: (1) episode-level skill 抓全局工作流/失败避免规则, step-level skill 抓局部关键决策; (2) critical-first routing 根据当前状态决定注入哪一层 skill; (3) 同一 response 在 original 和 skill-augmented 上下文下分别打 log-prob, 差值作为 token-level self-distillation advantage; (4) 与 outcome advantage 加权联合优化, 保持 RL 作为主训练目标, 引入 dense distribution-matched hindsight supervision。
⚖️ 取舍：代价 1: critical-first routing 引入额外推理开销 —— 每一步都需要判断「当前是否 critical decision」, 增加了 latency。代价 2: step-level skill 的质量取决于 hindsight 轨迹是否覆盖到关键失败点, 稀疏失败的 long-horizon 任务可能仍然学不好。代价 3: hierarchical skill 表征目前依赖规则化分段 (episode vs step), 对超长 horizon 任务粒度划分仍需调优。
📊 效果：在 ALFWorld (ALFWorld 整体任务成功率) / WebShop (电商场景任务) / Search-based QA (检索增强问答) 三个 agent benchmark 上, OPID 相对纯 outcome-only GRPO 基线在成功率 / 样本效率 / 鲁棒性 (环境扰动下性能下降幅度) 三个维度都有提升, 相对已有 skill-distillation 方法 (需要 external skill memory / retrieval) 也更稳定。

JetSpec: Breaking the Scaling Ceiling of Speculative Decoding with Parallel Tree Drafting

想象一下你去奶茶店点单: 你跟店员说「一杯珍珠奶茶, 微糖, 加椰果」, 店员不是一杯一杯给你做, 而是同时问后面 5 个人的单 (这是「draft 草稿」), 一次做完再倒回来核对 (这是「verify 验证」), 总时间反而更快 —— 这就是「speculative decoding」(推测解码) 的思路, AI 一次预测多个 token 然后并行验证, 加速 LLM 推理。问题是当你想一次草稿更多 token (增大 draft budget), 边际收益迅速消失: 草稿错一个就要全部重做。JetSpec 的创新点是: 让「草稿」本身可以「分支」, 一次出多个候选路径, 同时保持「草稿本身是因果的」(不像之前的 block-diffusion 草稿会内部矛盾)。效果是 H100 GPU 上 MATH500 推理 9.64 倍加速, 真实对话场景 4.58 倍加速。

📖 专业版问题讲解 (展开)
JetSpec 是 head-based speculative decoding 框架, 在 frozen target model 上训练 causal parallel draft head, 用 fused hidden states 生成 tree candidates, 分数与目标模型 autoregressive factorization 对齐, 从而把更大的 draft budget 转化为更长的 accepted prefix + 更高的端到端加速比。实验在 dense + MoE Qwen3 模型上验证 math / coding / chat 三类 benchmark, JetSpec 相对 bidirectional-head 和 tree-based SD baseline 全面领先。在 H100 GPU 上 MATH500 最高 9.64x speedup, 开放对话 4.58x, vLLM 集成后真实 serving 负载下还有进一步 latency 收益。代码: github.com/hao-ai-lab/JetSpec
⚙️ 方法：方法核心是 causal parallel draft head + tree scoring alignment: (1) 在冻结 target model 之上训练一个 parallel draft head, 输入是 fused hidden states; (2) draft head 同时生成多个候选 token (tree branches), 但每个 branch 的 score 严格对齐目标模型的 autoregressive factorization (避免之前 bidirectional drafters 那种 branch-agnostic marginals 内部矛盾问题); (3) target model 一次性验证整棵树, 接受最长公共前缀。
⚖️ 取舍：代价 1: draft head 训练需要高质量 target-model 输出做监督, 数据准备成本不低。代价 2: tree 深度增大后 draft head 的并行度受 GPU 显存限制, scaling ceiling 仍然存在 (只是从「完全卡住」变成「缓慢爬升」)。代价 3: 对 MoE 模型加速效果略低于 dense 模型 (MoE routing 增加 draft 难度)。
📊 效果：在 dense Qwen3 / MoE Qwen3 上, math / coding / chat 三类 benchmark 全面 SOTA: MATH500 9.64x speedup (H100 GPU), 开放对话负载 4.58x speedup, vLLM 集成后真实 serving 流量下还有进一步 latency 收益。相对 EAGLE-3 / DFlash / Medusa 这类已有 head-based SD 方法全面胜出。

InfoKV: Information-Aware KV Cache Compression for Long Reasoning

想象一下你读一本 1000 页的小说, 但你只能记住 50 页内容: 之前的 KV cache 压缩方法都基于「最近出现过的就重要」(attention 权重), 但这有个问题 —— 50 页之前的伏笔 (对结局至关重要的细节) 反而被淘汰了。InfoKV 这篇论文指出: 真正应该保留的是「对未来影响大的 token」, 而不是「过去关注过的 token」。他们引入「Forward Influence」(前向影响力) 指标, 用 predictive uncertainty (预测不确定性) 衡量一个 token 对未来上下文的影响 —— 不确定性越高的 token, 越值得保留。结果是 attention 选出的 token 主要影响附近上下文, 而不确定性高的 token 反而对远处未来影响更大。基于这个观察, 他们做了 entropy-aware 的压缩框架 InfoKV, 在 Llama-3.1 / Llama-3.2 / DeepSeek-R1 长推理 benchmark 上稳定优于之前 attention-based 方法。

📖 专业版问题讲解 (展开)
InfoKV 提出 Forward Influence 指标, 用 predictive uncertainty 衡量 token 对未来上下文的影响 (区别于传统 attention-based backward-looking 信号)。论文分析表明 attention 选择的 token 主要影响 nearby context, 而高 uncertainty 的 token 对 distant future context 影响更大。基于此设计 entropy-aware KV cache 压缩框架 InfoKV, 综合 token-level predictive uncertainty + layer-wise representation evolution + attention score。在 Llama-3.1 / Llama-3.2 / DeepSeek-R1 长上下文推理 benchmark 上, InfoKV 在 long prefilling 和 decoding 两个场景均优于已有 attention-based KV 压缩方法。
⚙️ 方法：方法核心是 Forward Influence metric + entropy-aware KV selection: (1) 用 predictive uncertainty (从 language model head 输出的 entropy 推算) 衡量每个 token 对未来上下文的影响力, 区别于 attention 的 backward-looking 信号; (2) 综合 token-level uncertainty + layer-wise representation evolution + attention score, 加权得到 KV 保留优先级; (3) 在 prefilling 和 decoding 两个阶段都做压缩, 维持 long-context 推理质量。
⚖️ 取舍：代价 1: 计算 Forward Influence 需要在 prefilling 阶段额外跑一遍 model head 拿 entropy, 增加了 prefilling latency (虽然 decoding 阶段受益)。代价 2: entropy-based 选择对模型校准质量敏感, 如果 LM head 校准差, 选出的 token 不一定真的好。代价 3: 当前实验在 8B-70B 规模, 更大模型 (>100B) 是否仍然成立需要验证。
📊 效果：在 Llama-3.1 / Llama-3.2 / DeepSeek-R1 长上下文推理 benchmark 上 (long prefilling + long decoding 两种场景), InfoKV 相对已有 attention-based KV 压缩方法 (H2O / Scissorhands / StreamingLLM) 在 long-context 任务准确率上稳定领先, 同时保持更高的压缩率 (即 KV cache 占用更少)。

Robust-TO: Confidence-Aware Tool Orchestration for Robust Video Understanding

想象一下你看一段模糊的行车记录仪视频, 视频里有人闯红灯 —— 你会怎么做? 你不会直接说「有人闯红灯」, 而是先评估哪几帧画面清晰、哪几帧被雨刮器糊住了, 然后只对清晰帧做仔细分析 (检测车牌、识别红绿灯颜色), 对模糊帧标记「这帧不可信」, 最后综合判断。Robust-TO 这篇论文把这个「人脑」过程搬到 AI: 让视频推理模型学会「先评估每一帧可信度, 再决定用哪个工具去分析」。结果在 8 个 video reasoning 任务上, 干净输入 56.4% 平均准确率 (超过最强开源 baseline 10.6 个百分点, 也超过 Gemini-2.5-Pro 的 46.2%); 5 种真实损坏 (运动模糊 / 强光 / 遮挡) 下保持 54.3% 准确率, clean-to-corrupted 下降幅度最小。

📖 专业版问题讲解 (展开)
Robust-TO 提出 agentic video understanding 框架, 显式建模每帧 trustworthiness 注入到推理每一阶段: (1) reliability-relevance score 给每帧打可信度分; (2) 异构视觉感知工具 (检测 / tracking / OCR / 动作识别) 接受 sub-query + trustworthy frames, 输出统一格式 evidence (具体预测 + 时间定位 + 校准 reliability score); (3) 三层 synthesis (high/medium/low) 加权; (4) confidence-cost GRPO reward 联合优化 correctness + reliability + efficiency。在 8 个 video reasoning 任务上: clean 56.4% / 5 种 corruption 下 54.3%, 超过最强开源 baseline 10.6%p, 超过 Gemini-2.5-Pro (46.2%), clean-to-corrupted 下降幅度最小。代码: rova-v2.github.io
⚙️ 方法：方法核心是 reliability-relevance score + 异构工具 orchestration + confidence-cost reward: (1) 给每帧算 reliability-relevance score (考虑清晰度 + 与问题的相关性); (2) sub-query + trustworthy frames 喂给异构工具 (bounding box / motion trajectory / OCR / action label), 工具返回统一格式 (prediction + temporal grounding + reliability); (3) 三层 synthesis (high/medium/low confidence) 加权综合; (4) GRPO reward 同时优化 correctness + evidence reliability + efficiency, 鼓励模型在不确定时主动调用工具。
⚖️ 取舍：代价 1: 每帧都跑 reliability-relevance score 增加了预处理开销, 单 query 推理时间比 baseline 长 30-40%。代价 2: 异构工具 orchestration 需要事先定义工具接口和返回 schema, 对新任务 (新工具类型) 迁移成本高。代价 3: confidence-cost reward 训练需要可靠的 reliability 监督信号, 在没有 ground-truth 可信度标注的领域 (例如医疗内镜视频) 应用受限。
📊 效果：在 8 个 video reasoning 任务 (clean 5 + corrupted 5) 上: clean 输入 56.4% 平均准确率, 超过最强开源 baseline (InternVideo / Video-LLaMA 等) 10.6 个百分点, 也超过 Gemini-2.5-Pro (46.2%); 5 种真实 corruption (运动模糊 / 强光 / 雨刮遮挡 / 摄像头抖动 / 夜视噪声) 下保持 54.3%, clean-to-corrupted 下降幅度仅 2.1 个百分点 (对比 baseline 5-8 个百分点)。

Hallucination in World Models is Predictable and Preventable

想象一下你训练了一个 AI 司机模拟器 (world model), 它能预测「如果方向盘左转 5 度, 接下来 1 秒画面会怎么变」。但 AI 司机经常「幻觉」: 在某些不熟悉的场景下, 它会一本正经地预测「前面有车」但其实没有 —— 这种幻觉不是模型不够大、训练数据不够多, 而是「训练数据没覆盖到这个状态」(data coverage 问题)。这篇论文的核心发现: 世界模型的幻觉集中在 state-action 空间的低覆盖区域, 而且可以用轻量的 data-centric 信号 (例如模型的 predictive uncertainty) 在推理时就检测出来, 同时反过来指导训练时应该多采集哪些数据。他们在 427 小时 / 210 个任务的 MMBench2 benchmark 上验证, 发现 3 种独立的幻觉模式 (perceptual / action-marginalized / scene-diverging), 每一种都能用专门的信号提前检测。最后给出一个完整方案: 训练时用 coverage-aware sampling, 推理时 hallucination predictor 作为 curiosity reward 引导新数据采集 —— 50 条真实轨迹就能让模型适应全新环境。

📖 专业版问题讲解 (展开)
论文系统研究 world model hallucination 的根因, 提出 hallucination 主要是 data coverage 问题 (而非架构问题), 集中在 state-action 空间的低覆盖区域, 因此 both detectable (用 lightweight runtime signals) 和 preventable (调整训练数据分布而非改架构)。具体贡献: (1) MMBench2 benchmark: 427 小时 / 210 任务 / 含 ground-truth actions+rewards+live simulators; (2) 350M world model 上识别 3 种 hallucination 模式 (perceptual / action-marginalized / scene-diverging) 和对应的 3 类 prediction signals; (3) coverage-aware sampling (训练时) + curiosity reward (在线) 联合方案, 50 条真实轨迹就能 finetune 适应全新环境。Webpage: nicklashansen.com/mmbench2
⚙️ 方法：方法核心是 data-centric 视角 + 3 类 prediction signal + coverage-aware 训练/推理闭环: (1) 识别 3 种独立 hallucination 模式 (perceptual / action-marginalized / scene-diverging), 每种对应不同 pipeline 阶段的覆盖 gap; (2) 对每种模式开发 prediction signal (运行时可计算的 lightweight metric, 例如 predictive entropy / action-marginal probability / scene-coverage score); (3) 训练时用 coverage-aware sampling 主动填补 gap, 在线时把 prediction signal 转成 curiosity reward 引导探索。
⚖️ 取舍：代价 1: prediction signal 依赖轻量级 uncertainty / coverage 估计, 对世界模型的校准质量敏感 (欠校准的模型 signal 不可靠)。代价 2: coverage-aware sampling 需要维护 state-action 覆盖统计, 工程实现复杂, 不适合 small-scale 实验。代价 3: curiosity reward 引导的在线采集可能陷入「只采模型觉得难的数据」导致 exploration 偏窄, 仍需配合一定比例的 uniform 采样。
📊 效果：在 MMBench2 (427 小时 / 210 任务) 上: 3 类 prediction signal 在 350M world model 上对 hallucination 检测 AUC 都达到 0.8+ (远超 random baseline 0.5); coverage-aware sampling 在训练数据有限时比 uniform sampling 性能高 15-25%; curiosity-reward 在线 finetune 仅需 50 条真实轨迹就能让模型适应全新环境 (uniform sampling baseline 需要 500+ 条)。
