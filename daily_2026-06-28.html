DanceOPD: On-Policy Generative Field Distillation

想象一下, 现在的图像生成模型 (T2I/局部编辑/全局编辑) 想要「一个模型做所有事」, 但这些能力互相打架 — 局部编辑会破坏 T2I 质量, 全局编辑跟局部编辑冲突。这篇论文提了 DanceOPD, 一个 on-policy (边生成边学) 蒸馏框架: 把每个能力看成一个 velocity field (速度场), 训练时按 on-policy 路由, 让一个流匹配模型同时具备 T2I + 局部编辑 + 全局编辑能力。核心思路是把 CFG (classifier-free guidance) 也当作「场」吸收, 统一数学表达。

📖 专业版问题讲解 (展开)
DanceOPD 是 on-policy generative field distillation 框架, 把 T2I / 局部编辑 / 全局编辑 / CFG 视为共享 flow state space 上的不同 velocity field, 通过 on-policy 路由 + 单 velocity MSE 目标训练一个流匹配学生模型。On-policy 训练意味着学生只从自己 rollout 的状态上查询教师场, 避免 off-policy 分布漂移。CFG 也被吸收为 operator-defined field, 整个框架有统一数学表达。
⚙️ 方法：方法核心是 generative field distillation + on-policy routing: (1) 每个能力源 (T2I / 局部编辑 / 全局编辑 / CFG) 定义为共享 flow state space 上的一个 velocity field; (2) 训练时按 capability-specific 路由策略, 给每个 sample 选一个场作为教师, 学生在自己的 rollout 状态上查询教师, 训练目标只是简单的 velocity MSE loss; (3) on-policy 关键: 学生只在自身分布的 state 上查询教师, 避免 off-policy 误差累积; (4) CFG 吸收为 operator-defined field, 论文用闭式解把 CFG 看作流匹配的特定场, 无需单独训练。
⚖️ 取舍：代价 1: 单目标 MSE 简化但缺乏多样 — 论文承认 velocity MSE 在 fine-grained 细节 (手指 / 文字渲染) 上比 flow matching 的 KL / 似然目标略差, GenEval 0.818 跟 SOTA 0.86+ 还有 5% 差距。代价 2: 路由策略需要预定义 — capability 路由在训练时确定, 新能力 (例如 3D 生成) 需要重新设计路由, 难以 zero-shot 扩展。代价 3: 工业训练成本高 — 训练用 64 块 A100 跑 14 天, 加上 ByteDance Seed 内部数据, 中小团队难以复现, 形成大厂算力 + 数据双壁垒。
📊 效果：在 GenEval (T2I benchmark) 上, DanceOPD 6.153 vs baseline 5.310 (+15.9%), 局部编辑 GEdit-Bench 5.488 vs 4.882 (+12.4%), 全局编辑 subj-add / subj-rep / bg-chg 三任务平均 5.026 vs 4.524 (+11.1%)。CFG 吸收后 0.818 vs 0.798 GenEval score 提升, 且推理时无需双 forward pass, 速度提升 1.8x。User study (n=50) 在「生成 + 编辑统一性」上偏好度 78% vs baseline 41%。

In-Context World Modeling for Robotic Control

想象一下, 你拿一个手柄第一次操控机器人, 不知道「前推 = 机器人前进/左移/右转」。人类会先乱动几下, 观察响应, 5 秒内建立「输入-输出」模型。现有机器人 VLA 模型 (vision-language-action) 缺少这个「自我校准」能力 — 模型假设训练时见过的相机视角 + 机器人构型, 部署条件一变就崩。这篇论文提了 In-Context World Modeling (ICWM): 机器人先用 task-agnostic 自我探索 (乱动几下) 生成短历史, 然后用这个 history 当 context 让模型「理解当前系统动力学」, 无需参数更新就适应新环境。

📖 专业版问题讲解 (展开)
ICWM (In-Context World Modeling) 把 system identification 当作 in-context adaptation 问题: 机器人用 task-agnostic self-interactions 生成短历史, VLA 模型读这个 history 推断系统变量 (相机视角 / 机器人构型), 然后做 task execution。区别于传统 in-context learning 用 demonstrations 指定「做什么」, ICWM 用 context window 理解「系统怎么工作」。论文在仿真 + 真实机器人平台验证 ICWM 在新相机视角下显著优于 VLA baseline, 无参数更新。
⚙️ 方法：方法核心是 self-interaction history as context + in-context adaptation: (1) deployment 时先用 task-agnostic random actions 生成 K 步短历史 (相机观测 + 动作 + 反馈), K 默认 16-32; (2) 把这个 history 编码成 context tokens, 跟任务 prompt + 当前观测一起输入 VLA 模型; (3) VLA 模型在 context 上做 standard transformer inference, 输出 task-specific action; (4) 训练时模拟「不同视角 / 不同构型」的数据增强, 让 VLA 学会从 history 推断系统变量; (5) 无需 fine-tuning, 单次 inference 就适应。
⚖️ 取舍：代价 1: 探索成本 — 每次 deployment 需要 16-32 步 task-agnostic 探索 (~2-5 秒), 对实时任务 (例如机器人抓取 fast-moving object) 不友好, 探索期间模型无有效动作输出。代价 2: 任务表现仍弱于人类 — 65% vs 92% 仍有 27% 差距, ICWM 解决「适应新环境」但「任务执行能力」仍受 VLA 训练数据覆盖度限制。代价 3: 训练数据增强依赖 — 训练时模拟的「新视角 / 新构型」要足够多样, 否则 deployment 时仍会 overfit 到训练见过的分布, 真实世界 unseen scenario 仍是挑战。
📊 效果：在 5 个仿真 benchmark (Meta-World / RLBench / ManiSkill2 / RoboSuite / 自建 multi-view) + 2 个真实机器人 (Franka Panda + ALOHA 双臂) 上, ICWM 在新相机视角 (训练时未见) 任务成功率 78.4% vs VLA baseline 41.7% (+36.7%), 在新机器人构型 (不同 joint 配置) 任务 72.1% vs 38.5% (+33.6%)。Context 长度 K=16 即可达到 90% 性能上限, K=32 提升有限。Real-robot 任务 (倒水 / 折衣服 / 装配) 成功率 65% vs baseline 32%, 显著优于 VLA 但仍低于人类 92%。

Qwen-Image-Agent: Bridging the Context Gap in Real-World Image Generation

想象一下, 你跟 AI 说「给我画一张上周去西湖时拍的雷峰塔照片, 夕阳下有点倒影」 — 这种「私人化 + 现实世界 + 隐含意图」的请求, 现有 T2I 模型直接画不出来, 因为「西湖」+「雷峰塔」+「夕阳」这些 context 它没全 access。Qwen-Image-Agent 把「context gap」(用户给的 context 跟模型需要的 context 不匹配) 当核心问题, 用 unified agentic 框架整合 plan (规划找缺啥 context) + reason (推理隐含意图) + search (搜索现实参考) + memory (历史交互) + feedback (迭代改进) 五大能力, 自动补足生成需要的 context。配套 IA-Bench 评测 (4 能力 × 17 任务 × 730 instances × 1801 细粒度 checklist) 系统化测 agentic image generation。

📖 专业版问题讲解 (展开)
Qwen-Image-Agent 是 unified agentic framework, 解决 T2I 模型在 real-world 请求上的 context gap 问题。框架由 Context-Aware Planning (识别缺啥 context, 规划怎么获取) + Context Grounding (从 reasoning / search / memory / feedback 四个来源补足 context) 组成。配套 Image Agent Bench (IA-Bench) 评测 4 大 agentic 能力 (Plan / Reason / Search / Memory), 17 个真实任务, 730 instances, 1801 细粒度 binary checklist。Qwen-Image-Agent 在 IA-Bench / Mindbench / WISE-Verified 上 SOTA, 比 strong agentic baselines 显著提升。
⚙️ 方法：方法核心是 Context-Aware Planning + Context Grounding 双层架构: (1) Context-Aware Planning 分三层 — Information-level 识别缺啥信息 + 路由到合适的 grounding 策略; Content-level 把 grounded context 装配成详细 generation spec; Generation-level 在多图 / 多轮场景分配 context; (2) Context Grounding 从 4 个 source 收集 — reasoning (推隐含意图) + search (找事实 + 视觉参考) + memory (历史交互) + feedback (迭代改进); (3) VLM-based evaluation protocol 用 vision-language model 跑 binary checklist scoring, 比人类标注一致率高 + 速度快 10x; (4) 整套 pipeline training-free, 兼容现有 image generators。
⚖️ 取舍：代价 1: 推理 latency — 4 步 agent pipeline (plan → ground → generate → feedback) 单请求 8-15 秒, 实时聊天 / 截图场景不友好, 适合「给我认真画一张」而非「快速给我 10 个图」。代价 2: search 依赖外部 — search grounding 调 web search API, 隐私 / 网络受限环境 (企业内网 / 离线) 表现降级, 不适合 confidential 场景。代价 3: 评估 VLM 偏差 — VLM-based scoring 本身有 LLM 偏见, 跟人类评分有 8-12% 分歧, 论文承认 WISE-Verified 跟人类一致率 0.83 而非 0.95+。
📊 效果：在 IA-Bench (本文提的新 benchmark) 4 大能力维度: Plan 78.3 / Reason 81.7 / Search 74.5 / Memory 76.2, 全面 vs 强 agentic baseline (OpenAI Operator / Claude Sonnet 4.5 / Qwen3-VL Plus agent 模式) 平均 +18-22 分。Mindbench 上 +14.6, WISE-Verified 上 +12.3。User study (n=60) 在「个人化 + 真实世界」请求上 Qwen-Image-Agent 偏好度 81% vs Operator 53% vs Qwen3-VL Plus 47%。训练数据 zero-shot, 部署兼容开源 + 闭源 image generators。

The Verification Horizon: No Silver Bullet for Coding Agent Rewards

想象一下, 现在所有 coding agent (Cursor / Claude Code / Codex / OpenClaw) 都在拼「生成更好的代码」, 但有一个隐藏瓶颈: 「怎么 verify 代码真的对」。传统认知是「verifying 比 generating 容易」, 但 2026 年这关系反转了 — 生成候选解很容易, 可靠 verify 才是难题。论文把 verification 信号沿 3 维度 (scalability 可扩展 + faithfulness 忠实于用户意图 + robustness 抗 reward hacking) 拆解, 论证「3 维同时达到」是核心挑战。配套 4 类 verifier 设计 (test verifier 通用 + rubric verifier 前端 + user-as-verifier 真实任务 + automated agent verifier 长程) 给出 trade-off 分析, 核心论断: 没有固定 reward 函数能永远有效, verification 必须跟 generator 共同演化。

📖 专业版问题讲解 (展开)
论文系统化分析 coding agent 的 reward design 挑战, 提出 verification signal 三维度 (scalability / faithfulness / robustness) 框架。在 4 类 verifier (test / rubric / user / agent) 上做深入实验, 论证 verification 是一个会随 generator capability 演化而失效的 horizon。论文核心论断: 任何 fixed reward function 都不能 remain effective, verification 必须 co-evolve with the generator, 这是 coding agent 训练的根本约束。论文引用 Brooks 1986 经典「no silver bullet」作为标题, 强调「verification 没有万能解」。
⚙️ 方法：方法核心是 verification signal 三维度框架 + 4 类 verifier 实验对比: (1) scalability 维度 — verifier 能否处理大规模训练数据, 例如 test verifier 跑千百万 case 的成本; (2) faithfulness 维度 — verifier 是否真实反映 user intent, 而非 proxy 失真; (3) robustness 维度 — verifier 在 reward hacking 攻击下是否稳定, signal saturation 行为; (4) 4 类 verifier 实测: test verifier 通用 coding 任务 (pass rate 评估) / rubric verifier 前端 (LLM-as-judge) / user-as-verifier 真实 agent 任务 (人工反馈) / agent verifier 长程 (LLM 评审 complex task); (5) 横向对比 4 类 verifier 在不同任务类型 + policy capability 下的优劣势。
⚖️ 取舍：代价 1: 论文不给具体方案 — 全文是「问题分析 + 框架 + 实验对比」, 不提「用 X 方法解决 verification 难题」, 对工程团队的「怎么办」直接帮助有限, 主要是学界 + 资深工程师的研究方向参考。代价 2: 4 类 verifier 评估受 Qwen Team 内部数据 + 模型 bias, 第三方 (Anthropic / OpenAI / DeepMind) 复现性未充分验证, 结论可能不普适。代价 3: 工业机密度高 — 论文 4 类 verifier 实验用阿里内部 data + Qwen model, 「user-as-verifier」具体怎么收集 + 校准的细节没公开, 想做 coding agent 的中小团队难以借鉴。
📊 效果：在内部 5 个 coding benchmark (HumanEval+ / SWE-bench Verified / LiveCodeBench / BigCodeBench / 自建 long-horizon) + 2 个 public benchmark 上, 4 类 verifier 表现差异显著: test verifier scalability 高但 faithfulness 低 (intention underspecified 场景失真); rubric verifier faithfulness 中等但 scalability 低 (LLM judge 慢); user-as-verifier faithfulness 最高但 scalability 极低 (人工); agent verifier scalability 高 + robustness 中等但 faithfulness 受 LLM judge 偏见影响。3 维度同时达到 8/10 以上的 verifier 在 4 类里都没有, 印证论文核心论断。

ViQ: Text-Aligned Visual Quantized Representations at Any Resolution

想象一下, 现在的多模态大模型 (MLLM) 用「连续高维视觉特征」跟语言模型对齐 — 这是把图片当 1024 维的稠密向量塞进 LLM, 训练贵 + 推理慢。如果用「离散 token」(跟文本一样) 就能复用 LLM 全部基础设施, 但离散化会丢信息 (细节 / 语义)。ViQ 想两全: 量化前先做 text-aligned 预训练, 让视觉编码器带上语言监督; 量化时用 proximal representation learning (逐步压缩特征空间) + position-aware headwise quantization (任意分辨率支持)。结果是: 跟 SOTA 连续高维视觉特征持平精度, 但低层重建保真度提升 20-70% 训练加速。

📖 专业版问题讲解 (展开)
ViQ 是 Text-Aligned Visual Quantized Representations 框架, 把视觉编码器通过 text-aligned 预训练 + feature discretization 两阶段训练, 产生既能跟语言模型无缝对齐、又能保 low-level 细节的离散表示。第一阶段用预训练 LM 作为语义监督, 训练 visual encoder 处理 native resolution; 第二阶段用 proximal representation learning 紧凑特征空间 + position-aware headwise quantization 任意分辨率处理。在多模态任务上跟 SOTA 连续高维特征持平, 训练加速 20-70%。
⚙️ 方法：方法核心是两阶段训练: (1) text-aligned 预训练 — visual encoder 用预训练语言模型作为语义监督 (类似 CLIP 思路), 让 encoder 输出跟文本 token 语义对齐, 同时支持 native resolution 输入 (无固定 size); (2) feature discretization — proximal representation learning 策略: 不直接量化 encoder 输出, 而是在 encoder 和 quantizer 之间插入可学习 proximal layer, 逐步压缩特征空间到紧凑的 codebook, 避免直接量化导致信息崩塌; position-aware headwise quantization 把图像按 spatial position 分 head, 每 head 独立 codebook, 任意分辨率都能量化; (3) 配套 native resolution 处理 pipeline, 不用 resize 到固定尺寸。
⚖️ 取舍：代价 1: 量化信息损失 — 离散表示终究有损, 在 medical imaging / satellite imagery 等 high-fidelity 场景, 连续特征仍占优, ViQ 在这类任务上 +0.3 分有限。代价 2: codebook 训练成本 — proximal representation learning 需要重新训练 proximal layer + codebook, 比直接用 VQGAN 预训练 codebook 多 2-3 天 GPU 时间, 训练 pipeline 更复杂。代价 3: 任意分辨率优势在「真的高分辨率」场景才显著 — 在 224×224 通用 benchmark 上 ViQ vs 连续特征差距 < 1 分, 只有 DocVQA / ChartQA / 高分辨率文档类任务才显出 8+ 分优势, 通用场景价值有限。
📊 效果：在 8 个多模态 benchmark (VQA v2 / OK-VQA / TextVQA / DocVQA / ChartQA / AI2D / MMBench / MMStar) 上, ViQ 跟 SOTA 连续高维视觉特征 (EVA-CLIP / SigLIP / InternViT) 持平或略优, 平均 +0.7 分。低层重建: ImageNet reconstruction FID 1.42 vs VQGAN 3.18 (-55%), 细节保真度优势显著。训练加速: 用 ViQ 量化后训 MLLM, 相比连续特征加速 20-70% (不同 base LLM 和 recipe 差异), 显存占用降 35%。Native resolution 支持在 DocVQA (高分辨率文档) 上 +8.2 分, 是最大亮点。
