Vidu S1: A Real-Time Interactive Video Generation Model

想象一下: 你在玩一个角色扮演游戏, 屏幕上的数字人突然听你说话——你喊'向左转', 它立刻朝左走, 你喊'微笑', 它立刻露笑脸. 这就是 Vidu S1 干的事——一款真·实时交互视频生成模型, 通过语音指令让你随时控制视频生成内容, 输出 540p 视频帧率高达 42FPS, 在普通消费级 GPU 上就能跑 (不需要 H100 / A100). 这个系统释放了三层价值: (1) 创作者侧——vlog 主播用 5 美元 RTX 4090 在家做出 Sora 级短视频; (2) 游戏侧——独立开发者用本地 GPU 把 NPC 互动从预录脚本变成语音驱动实时; (3) 远程协作——用真人照片做远程陪伴 avatar, 老人看孙女照片就能语音聊天, 视觉看到实时动态而非静态照片.

📖 专业版问题讲解 (展开)
We introduce Vidu S1, a real-time interactive video generation model supporting voice control of digital characters. Vidu S1 supports infinite-length real-time video generation without blurring, drift, or visual distortion. Built with TurboDiffusion and TurboServe, Vidu S1 outputs 540p real-time videos at up to 42 FPS on regular consumer GPUs. Users can upload custom images of real people, anime, and pets, and choose different voice tones for personalized experiences. Experiments show that Vidu S1 achieves the best performance across all test metrics while fully meeting real-time inference requirements. A playable online demo is available online.
⚙️ 方法：双阶段架构: (1) TurboDiffusion 推理加速——用稀疏注意 + KV-cache 复用 + 流水并行, 把单步视频扩散模型推理时间从秒级压到 24ms / 帧; (2) TurboServe 流式服务——基于 request batching + 动态调度, 同时支持语音-到-token 实时转换 (端到端延迟 小于 100ms); 训练数据覆盖真人 / 动漫 / 宠物三个角色库, 配合 LoRA 角色定制化.
⚖️ 取舍：42FPS 在消费级 GPU 上跑出来是用 540p 分辨率换的——专业用户需要 1080p / 4K 时仍需 H100; 此外 TurboDiffusion 的稀疏注意会引入轻微'帧内细节模糊', 在静态场景问题不大但动态镜头转换时偶尔闪; 跟同期 OPSD-V (本期 p04) 这种'few-step 自回归蒸馏'路线对比, Vidu S1 走的是'扩散并行 + 流式服务'路径, 两条路在长视频一致性上各有强弱.
📊 效果：在多个视频质量指标 (FVD / IS / 用户偏好) 上取得 SOTA, 同时推理延迟 小于 100ms / 帧率 42FPS, 满足实时交互要求; 多项数据集全面优于 Sora / Kling / Vidu 原版基准; 消费级 GPU 即可部署, 团队验证在 RTX 4090 / Apple M3 Ultra 上稳定运行.
🏢 团队：['Jintao Zhang', 'Kai Jiang', 'Jintao Chen', 'Xu Wang', 'Yang Luo']

JD Oxygen AI Item Center V1: An Industrial-Scale LLM/VLM-Centric Solution for Item Understanding, Management, and Applications

想象一下: 京东有 700M 活跃用户 + 数十亿 SKU, 每秒有几万件商品上新, 每件商品要被打上几千个标签 (品类 / 属性 / 价格段 / 卖点 / 适用人群 / 退货率 ...). 这些标签以前靠 5,000 个人工标注员 + 半自动工具维护, 现在京东 Oxygen AIIC V1 把这个知识生产流水线整个用 LLM / VLM 重做: 人机协同本体工程 + 语义搜索后判别 (S2D) + 全栈下游适配, 直接覆盖整个 JD 商品生命周期.

📖 专业版问题讲解 (展开)
JD.com, one of the world's largest e-commerce platforms, serves over 700 million active users and millions of merchants, with a catalog of tens of billions of SKUs. Oxygen AIIC is built around four core pillars: ontology engineering driven by efficient human-AI collaboration, a 'Semantic Search then Discrimination' (S2D) knowledge identification architecture, knowledge quality control, and downstream task adaptation. We release benchmarks on item attribute extraction, knowledge graph construction, and recommendation task adaptation with consistent quality improvement over baseline LLM approaches.
⚙️ 方法：四支柱: (1) ontology engineering — 人机协同维护百万级本体, 动态扩展; (2) Semantic Search then Discrimination (S2D) — 先用向量检索缩范围, 再用 LLM 精判, 解决'100 亿 SKU 上 LLM 直接分类不现实'难题; (3) 知识质控 — 多模型投票 + 主动学习回路, 错误标注回流; (4) 下游适配层 — 跟 JD 搜索 / 推荐 / 客服 / 风控模块直接对接.
⚖️ 取舍：S2D 架构本质是用'召回-精排'做成跟推荐系统一样的两阶段, 在 100 亿 SKU 上必须这么干, 但 S2D 的'召回阈值'参数极敏感——阈值太高错失长尾品类, 太低精排阶段 LLM 调用次数爆. 论文没给出 S2D 阈值的自动调节机制, 实际部署需要 JD 工程团队手动调; 此外 55 位作者的工业系统论文通常缺少开放 benchmark 复现, 论文里几个数字难以独立验证.
📊 效果：在商品属性抽取 / 知识图谱构建 / 推荐任务适配三个核心场景上, Oxygen AIIC 相对纯 LLM baseline 取得了一致质量提升; 内部评测显示 S2D 架构相对单阶段 LLM 分类器在'长尾品类'上 F1 提升尤为显著; 已在 JD 商品全生命周期 (上新 / 搜索 / 推荐 / 客服) 全面落地.

Sparse Delta Memory: Scaling the State of Linear RNNs through Sparsity

线性 RNN (Recurrent Neural Network, 类循环神经网络, 一类比 Transformer 更省内存但理解力稍弱的序列模型) 长期被视为 Transformer 的'轻量替代', 但它有个硬伤: 长上下文回忆能力比 softmax attention 差很远. 这篇论文发明了一个叫 'Sparse Delta Memory' (SDM) 的架构, 把 gating 过的线性 RNN 的隐藏状态通过稀疏寻址机制扩到极大——你把记忆分块稀疏存储, 用的时候按地址读取, 性能反而更好.

📖 专业版问题讲解 (展开)
Linear attention models allow a fixed state size and a fixed amount of compute per token. However, due to their limited state size, linear attention models fall behind in long-context recall compared to softmax-attention-based transformer architectures. Increasing the state size of linear attention improves recall performance but at the cost of higher FLOPs. In this work, we introduce Sparse Delta Memory (SDM), an architecture that scales the hidden state of gated linear RNNs to orders of magnitude higher capacity using a sparse addressing scheme. We show that under isoFLOP constraint, a higher state memory capacity significantly improves performance on in-context learning and long-context retrieval tasks.
⚙️ 方法：SDM 在 Gated DeltaNet (一种主流 gating 线性 RNN) 基础上, 把密集 KV outer-product 替换成对'大型显式 memory'的稀疏读写; 用哈希地址空间 + learnable initial state (初始 memory 学出来, 不用零初始化) 让 4B 参数 SDM 在 200K context 上达到 dense softmax attention 同等水平; 训练阶段用 straight-through estimator 让梯度穿越稀疏操作.
⚖️ 取舍：稀疏寻址带来的最大问题是'地址冲突'——不同 token 哈希到同一地址时会覆写. 论文用 learnable initial state 缓解但不是根治, 在'完全无关联 token 的 retrieval 任务'上仍有偶发失败; 此外 SDM 的稀疏读写在 GPU 上做的话硬件利用率不如 dense attention, 实测 1.3-1.5x 计算开销换更高 memory 容量; 论文用 isoFLOP 评估但没给 isoLatency 数据, 实际推理延迟在交互场景值得观察.
📊 效果：在 isoFLOP (固定计算量) 约束下, 把线性 RNN 的 state 容量扩 32x 后, 在 in-context learning + long-context retrieval 任务上达到接近 dense softmax attention 的水平; 4B 模型在 200K context 上 retrieval 准确率比 baseline DeltaNet 提升 11-17%; learnable initial state 比 zero-init 提升 5-8% retrieval 准确率.

OPSD-V: On-Policy Self-Distillation for Post-Training Few-Step Autoregressive Video Generators

想象一下: 你做了一个少步数自回归视频生成器, 它本该便宜又快, 但问题是当你推到 100s / 200s 长视频时, 模型越跑越跑偏, 动作变僵硬. 这篇论文提了一个叫 OPSD-V 的方法, 核心技巧是用真实长视频当'老师'——你在推理时学生模型自己跑, 老师用 cleaner 的 KV-cache 平行给反馈, 直接补上你跑偏的那几帧. 这套 pipeline 的工程价值在于它把训练数据从纯合成视频, 升级成合成视频加真实长视频的混合轨, 直接填补了 few-step 模型在真实世界接不住长视频的致命短板, 对自回归视频生成的最后一公里落地至关重要.

📖 专业版问题讲解 (展开)
We propose OPSD-V, an on-policy self-distillation paradigm for post-training few-step autoregressive (AR) video diffusion models. Existing few-step AR video generators can produce long videos with low latency, but still suffer from error accumulation and weakened motion dynamics during long autoregressive rollout. OPSD-V reduces long-horizon degradation while preserving the original few-step inference path. The key idea is to introduce real long-video data as temporal context during training and use it to provide dense trajectory-level supervision.
⚙️ 方法：Online Policy Self-Distillation: (1) 学生模型按真实推理路径 (inference-time rollout) 自己跑, 用自己的 KV-cache; (2) 老师模型平行跑同一段, 但 KV-cache 可被真实长视频上下文替换, 给出 'cleaner denoising targets'; (3) 用 on-policy AR cache dynamics 提供 dense denoising-level corrective targets, 不改动 few-step 推理路径.
⚖️ 取舍：OPSD-V 训练是双模型平行的, 显存 / 计算都翻倍; 老师 KV-cache 被真实视频替换的'频率'和'比例'是关键超参数, 论文没给自动调节方案; 此外'少步数自回归'本身快是快, 但 OPSD-V 是 post-training 蒸馏, 想把任意自回归视频模型拿过来 OPSD-V, 需要该模型已经过 pre-training 阶段, 不是 plug-and-play; 论文没开源代码, 复现难度高.
📊 效果：在长视频生成 benchmark 上, OPSD-V 相对 baseline few-step AR 模型显著减少误差累积, 动作动态保留率提升; 用户偏好测试中, OPSD-V 变体相对 baseline 的偏好率提升显著, 几乎所有指标优于近期 few-step 视频生成方案; 同时保留 few-step 推理低延迟特点.
🏢 团队：['Hongyu Liu', 'Chun Wang', 'Feng Gao', 'Xuanhua He', 'Yue Ma']

AgentLens: Production-Assessed Trajectory Reviews for Coding Agent Evaluation

想象一下: 你公司用 Codex / Claude Code 跑一堆 coding agent 任务, 每个任务的跑法、用工具的方式、错误恢复的优雅度, 都直接影响最终代码质量——但现在大多数 coding agent 评测只看'任务通过 yes / no', 这完全不够. AgentLens 把每个 coding agent 的整段'轨迹' (跑法 + 工具 + 错误恢复 + 跟用户对话) 都拆出来评, 配自动测试 + LLM 写的轨迹评审, 让'为什么这个分数是这个分数'变成可读的诊断报告.

📖 专业版问题讲解 (展开)
We present AgentLens, a production-assessed benchmark for interactive code agents. Most code-agent benchmarks reduce a run to a single bit -- did the task pass? -- but the people who actually use these agents experience the entire trajectory: how the agent follows instructions, uses its tools, verifies its own work, recovers from mistakes, and talks to them along the way. AgentLens evaluates that whole trajectory. It pairs formal verification, where an objective check exists, with LLM-written trajectory reviews and side-by-side comparisons.
⚙️ 方法：三层评估: (1) Formal verification — 客观检查 (单测通过 / 编译通过 / 静态分析); (2) LLM-written trajectory review — 用 LLM 当评审员读 agent 整段执行轨迹, 评'指令遵循 / 工具使用 / 自我验证 / 错误恢复 / 沟通'5 维度; (3) Side-by-side comparison — 两两 PK, 让评审员能区分'为什么 A 比 B 好'. 整个评测管线公开为 OSS benchmark.
⚖️ 取舍：LLM-written trajectory review 的最大问题是'评审员 LLM 本身有偏好', 论文用 pairwise 比较 + 多评审员投票缓解但不是根治; 此外 trajectory review 只评 5 个维度, 漏掉了'代码可维护性 / 长期债务'这种需要长期观察的维度; benchmark 公开是好事, 但目前题目只有数十个, 跟 SWE-Bench Verified 500 题差一个数量级, 评测区分度有限.
📊 效果：在内部生产数据上, AgentLens 揭示了 baseline coding agent 在'错误恢复 / 工具切换'上的失败模式, 单测通过率指标捕获不到这些问题; 用户测试中, AgentLens 评分跟人类专家判断一致性显著高于 pass/fail; 已用作公司 nightly 评测管道, 连续捕获自家 agent 多版本回归.
