OpenAI 与 Broadcom 联合发布自研推理芯片 Jalapeño: 单卡性能超 H200 50%

OpenAI 与 Broadcom 联合推出首款面向 LLM 推理优化的自研 ASIC 芯片 Jalapeño。该芯片专为 transformer decode 阶段设计, 在 FP8 精度下实现 4 PFLOPS 算力 + 288GB HBM3e 显存 + 8 TB/s 显存带宽, 单卡推理性能相比 NVIDIA H200 提升 50%, 推理能耗比提升 2.3 倍。Jalapeño 采用 Broadcom 3nm 工艺, 首批 5 万片将于 2026 Q4 量产, 部署在 OpenAI 自有算力集群与 Microsoft Azure OpenAI 服务中。这是 OpenAI 继 5 月与 NVIDIA 续签 500 亿美元算力承诺、6 月初与 AMD 敲定 MI400 部署后, 第三个 GPU 替代方案的明确信号。OpenAI 强调 Jalapeño 不替代 GPU, 而是为推理这种特定负载提供更优的能耗成本曲线, 训练仍以 NVIDIA 为主。

💡 OpenAI 三条腿走路 (NVIDIA 训练 / AMD MI400 推理 / Broadcom Jalapeño 推理) 的算力布局终于在 6/24 全部落地, 标志着头部 AI 公司开始从'买卡'走向'定制卡'的拐点。Broadcom 选择 OpenAI 而不是 Anthropic / Google 这种大客户, 反映了 OpenAI 在 inference workload 上的体量优势 — 据 The Information 估算 OpenAI 日推理 token 量已经是 Anthropic 的 4 倍以上, 足以撑起 ASIC 量产。能耗比 2.3 倍这个数字对 AI 公司 CFO 是核弹级的 — 推理成本占 OpenAI 总成本约 60%, 单卡能耗降低一半意味着同等算力下年度 capex 可降低 30%, 直接推动 OpenAI 加速降价和扩张 API 客户群。短期看这是 Broadcom 估值利好 (ASIC 业务 Q4 营收贡献预期 +5%), 中期看是 NVIDIA 在推理市场份额的首次实质侵蚀。

Qwen-AgentWorld: 语言世界模型让 agent 在 7 个领域做长链路环境仿真

想象一下, 普通 AI agent 走一步看一步, 经常走着走着就迷路。Qwen-AgentWorld 想做的事是给 agent 一个「内心沙盘」— 让语言模型自己充当环境模拟器, 在脑子里推演未来 50-100 步会怎样。论文发布两个模型: 35B-A3B 轻量版 + 397B-A17B 旗舰版, 都用 1000 万条真实环境交互轨迹训练。训练分三段: 先学通用世界建模能力 (CPT), 再激活「预测下一步」推理 (SFT), 最后用强化学习把仿真逼真度刷上去。配套发布 AgentWorldBench 评测基准, 覆盖 7 个 agent 领域 (代码 / 终端 / 操作系统 / 浏览器 / GUI / 工具调用 / 游戏)。

📖 专业版问题讲解 (展开)
Qwen-AgentWorld 探索的是「语言世界模型 (Language World Model)」这条新路径 — 不是用 diffusion 生成像素, 而是用 LLM 直接推理状态转移。模型分 35B-A3B (MoE 激活 3B) 和 397B-A17B (MoE 激活 17B), CPT+SFT+RL 三阶段训练, 1000 万条轨迹来自真实环境 (TerminalBench / OSWorld / Tool Decathlon)。AgentWorldBench 包含 9 个 benchmark, 用 ground-truth rubric judging 评估仿真保真度。实验表明语言世界模型在工具调用 / 终端操作场景下, 能把下游 agent 任务的成功率提升 12-18 个百分点。
⚙️ 方法：CPT (Continued Pre-Training) + SFT (Supervised Fine-Tuning) + RL (Reinforcement Learning) 三阶段训练管线。RL 阶段设计 hybrid rubric-and-rule reward — 对可验证的任务 (代码 / 终端命令) 用 rule-based reward, 对开放式任务 (GUI 操作 / 浏览器导航) 用 rubric-based reward。模型架构是 MoE, 35B 参数激活 3B / 397B 参数激活 17B, 在推理时只激活 9-12% 的参数以节省算力。
⚖️ 取舍：世界模型把下游 agent 任务成功率拉高 12-18 个百分点的代价是, 推理 token 消耗显著增加 — 模型需要先在内心沙盘里推演未来 50 步, 再选择最优动作。Hybrid rubric-and-rule reward 的局限是, 开放式任务的 rubric 本身需要 LLM 评判, 这就形成「模型自己生成仿真、自己评判仿真」的循环依赖, 在长链路仿真 (100+ 步) 时误差会累积放大。三阶段训练管线需要 1000 万条真实轨迹做 SFT, 数据采集成本极高, 复现门槛对中小团队不友好。
📊 效果：在 AgentWorldBench 上, Qwen-AgentWorld-397B-A17B 把 Tool Decathlon / Terminal-Bench 1.0 / OSWorld-Verified 等 9 个 benchmark 的下游 agent 成功率平均提升 12-18 个百分点, 超过 Qwen3-235B 基线 +GPT-4o agent 框架。在仿真保真度维度 (AgentWorldBench 自有指标), 397B-A17B 的 next-state prediction accuracy 达到 71.3%, 比 GPT-4o 的 58.9% 高 12 个百分点。35B-A3B 轻量版在 7 个 agent 领域平均仿真保真度 62.8%, 接近 397B 旗舰版的 88%。

FLAT: 从视频扩散潜空间直接解码三角面片, 3D 场景生成首次跑出可仿真表面

想象一下, 你拿一张照片给 AI, 它能不能给你生成一个能走进去的 3D 场景? 现在主流方法用 3D 高斯泼溅 (3DGS) 做这件事, 但 3DGS 是「雾团」, 没有真正的表面 — 不能丢进游戏引擎、物理仿真器、3D 打印这些需要明确几何的场景。FLAT 提出一个巧妙思路: 跳过 3DGS, 直接从视频扩散模型的潜空间解码出三角面片 (triangle splats)。但三角面片对朝向极敏感, 训练时梯度流很差。FLAT 用两个关键 trick 解决: (1) ray-centered rotation 参数化 — 让三角面片绕光线方向旋转, 而不是绕世界坐标轴; (2) product window function — 控制每个三角面片的影响范围, 改善梯度流动。结果是首个能从单张图直接生成可仿真 3D 场景的 feedforward 模型。

📖 专业版问题讲解 (展开)
FLAT 把视频扩散模型的潜空间直接解码到 surface-aligned 三角面片, 跳过 3DGS 中间表示。两个核心创新: ray-centered rotation parameterization (绕光线而非世界轴旋转三角面片) 和 product window function (缓解梯度流问题)。实验表明 FLAT 在 ScanNet / Replica 室内场景重建上, surface alignment error 比 3DGS baseline 降低 42%, 同时保持可比的几何精度。模型在 1024×1024 输入下端到端推理 1.2 秒, 适合交互式应用。
⚙️ 方法：架构上 FLAT 是 video diffusion VAE decoder 的扩展, 把原来的 RGB 像素解码替换为 triangle splat decoding。Ray-centered rotation 让三角面片的法线方向始终指向观察方向, 等价于把 6 自由度旋转问题降维到 3 自由度。Product window function 借鉴 splatting 的高斯衰减思想, 给每个三角面片一个衰减区域, 防止训练时三角面片位置剧烈抖动。整个模型是 feedforward 一次性推理, 不用多步优化 (跟 NeRF / Gaussian Splatting 那种需要 per-scene 优化的方法不同)。
⚖️ 取舍：三角面片相比 3D 高斯泼溅的最大优势是 surface-aligned (有明确表面), 但代价是几何表达力下降 — 3DGS 能表示半透明、烟雾、流体这种无明确表面的物理现象, 三角面片表示不了。FLAT 当前只在 1024×1024 输入下做了实验, 对超高分辨率 (4K+) 图像的泛化性未验证。Ray-centered rotation 假设输入是单视图, 扩展到多视图输入需要重新设计冲突解决机制。三角面片数 (mesh complexity) 是硬编码的, 对不同复杂度场景 (空旷室内 vs 拥挤街道) 没法自适应。
📊 效果：在 ScanNet 室内场景重建基准上, FLAT 的 surface alignment error 降低 42% (相比 3DGS baseline), Chamfer Distance 降低 18%。在 Replica 基准上, FLAT 的 surface F-score 达到 0.83 (3DGS 是 0.71)。单图推理时间 1.2 秒 (A100 GPU), 比 3DGS + 多步优化快 25 倍。在用户偏好评测中, FLAT 生成的 3D 场景在「表面平滑度」「光照一致性」两个维度比 3DGS 高 31% 和 27% 偏好率。
🏢 团队：Orest Kupyn, Goutam Bhat, Philipp Henzler, Fabian Manhardt, Christian Rupprecht, Federico Tombari → Google Research + University of Oxford Visual Geometry Group + TU Munich

DiffusionBench: 把 DiT 评测从 ImageNet 单维扩展到 ImageNet + 文本生成双维

扩散 Transformer (DiT) 的研究有个怪现象: 所有人都在 ImageNet 上跑 FID 跑分, 但 FID 高真的意味着生成模型好吗? 这篇论文直接把怀疑做了实验: 团队训练了 21 个不同配置的 DiT 模型, 在 ImageNet 和文本生成 (T2I) 两个维度同时评测, 发现方法排名「几乎不相关」— Pearson 相关系数在 -0.38 到 -0.58 之间, 负相关! 意思是 ImageNet 上 FID 改进的方法, 在 T2I 上可能反而变差。配套发布 NanoGen 训练框架, 12 行配置就能切换 ImageNet 和 T2I 两种训练模式, 让 T2I 训练成本降到跟 ImageNet 相当。

📖 专业版问题讲解 (展开)
DiffusionBench 配套发布 NanoGen 统一训练框架, 支持 RAE / VAE / pixel-space / MeanFlow 四种扩散方法, 在 ImageNet 和 T2I 两种设置下训练。21 个模型的横向对比揭示 ImageNet FID 与 T2I benchmark 排名之间的 Pearson 相关性只有 -0.377 到 -0.580, 说明 ImageNet 上的方法排名对 T2I 几乎没有预测力。论文提议把 T2I benchmark 作为 DiT 研究的标配评测, 并开源 NanoGen 降低 T2I 训练门槛。
⚙️ 方法：NanoGen 框架的核心是配置驱动的统一数据管线: 12 行 YAML 配置切换 latent space (RAE/VAE/pixel) + 训练目标 (diffusion/MeanFlow) + 数据集 (ImageNet/T2I)。论文训练 21 个模型覆盖 4 种 latent space × 2 种数据集的组合, 控制变量。每个模型训练 200K 步, ImageNet 256×256 + T2I 256×256 在同一硬件上跑通, 让横向对比有意义。评测侧 ImageNet 用 FID + IS + Precision/Recall, T2I 用 GenEval + T2I-CompBench + DPGBench。
⚖️ 取舍：NanoGen 框架把 T2I 训练门槛降低到「ImageNet 同等算力」, 但代价是必须接受 NanoGen 默认的 12 行配置选项 — 任何超出 12 行的自定义 (例如多模态控制 / LoRA 微调) 都得自己改框架。ImageNet vs T2I 排名负相关的发现虽然震撼, 但 21 个模型是来自同一团队同一框架, 缺少跨实验室验证 — 其他团队复现时可能得出不同的相关性。论文没有解释为什么相关性是负的, 只指出这是经验观察, 没有理论分析。
📊 效果：21 个 DiT 模型在 ImageNet FID 上排名前 5 的方法, 在 T2I GenEval 上排名平均下降 3.2 位 (最好的从 #1 掉到 #6, 最差的从 #4 掉到 #11)。Pearson 相关性在 FID-vs-GenEval 是 -0.580, FID-vs-T2I-CompBench 是 -0.377, FID-vs-DPGBench 是 -0.512, 全部是显著负相关。NanoGen 训练一个 T2I 模型用 256 A100 hours, 比此前 SOTA T2I 训练成本降低 35%。

ChartWalker: 跨图表 RAG 任务的层次化知识图谱基准

想象一下, 你老板给你 50 张图表 (折线图 / 柱状图 / 饼图 / 散点图混在一起), 让你写一份季度分析报告 — 你会怎么干? 人类会先建一个「心智地图」, 把图表之间的关联串起来 (这家公司的收入图表跟那家公司的成本图表指向同一季度, 这个饼图的份额跟那个柱状图的比例一致)。现在的 RAG 系统做不到这点 — 它们要么只处理单图表, 要么把图表当成纯文本检索, 完全丢了图表之间的逻辑关系。ChartWalker 提出一个生成这种「跨图表难题」的方法: 先建层次化知识图谱 (每个图表是节点, 跨图表关联是边), 再用结构感知采样算法生成多跳推理问题。配套 ChartWalker-Bench 评测基准 + ChartWalker-Agent 基线模型。

📖 专业版问题讲解 (展开)
ChartWalker 提出跨图表 (cross-chart) RAG 任务的统一框架, 解决现有 benchmark 的两个核心缺陷: 只关注 well-structured table, 或者只生成简单 key-point 抽取型查询。核心贡献是层次化知识图谱构建 + 结构感知采样算法。评测覆盖 8 个主流 RAG 范式, 发现现有方法在跨图表推理任务上的性能显著低于单图表任务。
⚙️ 方法：层次化知识图谱 (Hierarchical Knowledge Graph) 构建分三层: (1) chart-level 节点 — 每个图表是一个节点, 包含图表元数据 + 主数据点; (2) entity-level 边 — 跨图表共享的实体 (公司 / 季度 / 指标) 连边; (3) relation-level 超边 — 多图表共同表达的关系 (如时间序列趋势 / 比例分配)。结构感知采样算法基于 BFS/DFS 在图谱上生成多跳推理路径, 显式控制查询难度和粒度。评测涵盖 8 个 RAG 范式 (dense retrieval / sparse retrieval / hybrid / GraphRAG / ReAct / multi-agent / 等等)。
⚖️ 取舍：跨图表 RAG 任务对人类分析师是基础能力, 但对现有 AI 系统是「未被攻克的难题」— 因为这需要 (1) 多模态理解 (图表解析) + (2) 跨文档推理 (知识图谱) + (3) 复杂问题分解三件事同时做。ChartWalker 的局限性是当前 benchmark 用合成图表, 真实业务图表 (不规则布局 / 缺失图例 / OCR 错误) 的泛化性未验证。8 个 RAG 范式评测覆盖广但缺少 LLM-as-Agent 范式 (例如 GPT-4o Codex / Claude Computer Use) 的横向对比。
📊 效果：在 ChartWalker-Bench 上, 现有 RAG 范式的 F1 平均 28.4, 远低于单图表 RAG 任务的 65.7。GraphRAG (知识图谱检索增强) 表现最好达到 F1 41.2, 表明知识图谱对跨图表推理是真有效。最佳 LLM (GPT-4o) 直接答的 F1 只有 23.1, 说明即使强模型也解决不了跨图表难题。图表数量从 5 张增加到 50 张时, 准确率从 38.7 降到 19.2, 表明长上下文下推理能力断崖式下降。

FlowR2A: 用 flow-matching 解开自动驾驶规划中奖励与动作的对立

想象一下, 自动驾驶汽车要决定下一步怎么开 (加速 / 转向 / 刹车)。现在的规划方法有两种思路, 但都有问题: (1) 「打分派」 — 预定义一组动作 (比如 100 个候选轨迹), 给每个打分, 选分最高的。问题: 动作空间是固定的, 没法生成新动作; (2) 「生成派」 — 直接生成一条轨迹, 用真实驾驶数据训练。问题: 只有一条「正确答案」做监督, 训练信号太稀疏。FlowR2A 想了个巧妙办法: 把奖励信号 (来自仿真器) 当成「条件」, 而不是「监督目标」, 用 flow-matching decoder 学习「给定奖励, 应该输出什么动作」的分布。这样模型既能享受稠密奖励监督, 又能生成新动作。

📖 专业版问题讲解 (展开)
FlowR2A 把自动驾驶规划问题重新定义为 reward-conditioned action distribution learning, 用 flow-matching decoder 同时获得 dense reward supervision 和 dynamic proposal generation 两个优势。配合 per-timestep reward conditioning + reward noise augmentation, 模型在 nuScenes / Waymo Open Dataset 上的规划指标超过 UniAD / VAD 等 SOTA 7-12 个百分点。可控采样 (reward guidance / anchored sampling) 让模型能在「安全 vs 进度」之间动态权衡。
⚙️ 方法：FlowR2A 的核心是 flow-matching decoder, 输入是当前环境状态 + per-timestep reward, 输出是未来 N 个时间步的动作分布 (轨迹)。训练时用仿真器 (CARLA + nuPlan) 生成 (轨迹, 奖励) pair 做监督。Reward noise augmentation 在训练时随机扰动奖励信号, 提升模型对奖励噪声的鲁棒性。推理时通过调节 reward guidance strength 动态平衡安全 / 进度 / 舒适度 / 合规四个维度, 也可以用 anchored sampling 把生成轨迹约束在 anchor (历史轨迹的延伸) 附近。
⚖️ 取舍：Flow-matching decoder 相比 diffusion / VAE 的优势是推理时只需 5-10 步 (diffusion 通常 50 步), 适合自动驾驶这种实时性要求极高的场景。Per-timestep reward conditioning 的代价是奖励设计本身成为「隐藏的人力成本」 — 仿真器奖励设计需要资深自动驾驶工程师, 不是所有团队都能复现。Reward noise augmentation 虽然提升鲁棒性, 但在极端噪声下 (例如传感器故障), 模型可能生成保守但不安全的轨迹 (宁愿停车不挪动)。FlowR2A 当前依赖 nuScenes / Waymo Open Dataset, 在中国复杂城市道路 (外卖车 / 电动车 / 行人混行) 的泛化性未验证。
📊 效果：在 nuScenes planning benchmark 上, FlowR2A 把 L2 规划误差降低到 0.42m (UniAD 是 0.51m, VAD 是 0.48m), 碰撞率从 UniAD 的 0.18% 降到 0.09%。在 Waymo Open Dataset 上, FlowR2A 的 planning score 达到 0.84, 比 UniAD 的 0.78 高 6 个百分点。推理时间在 A100 GPU 上每帧 18ms, 满足实时规划要求 (60 FPS 需要 16ms)。Reward guidance 实验表明, 调高 safety reward 让碰撞率再降 60%, 但路径效率下降 12%。
